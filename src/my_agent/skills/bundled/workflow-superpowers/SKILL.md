# Superpowers 分步开发 / Incremental development

本应用适配版，来源和差异见 `SOURCE.md`。当前任务阶段关联的方法已随请求提供；沿当前阶段工作，不每轮重新讨论已经明确的目标。没有自动安装上游 Hooks、原生子 Agent 运行时或 Git worktree 管理器。

## 讨论到交付

需求不明确时，用已有代码和具体使用场景识别真正缺失的信息；比较少量可行方案，记录用户确认的取舍。目标已清楚的小改动直接推进，不强制额外设计审批。

计划围绕可体验结果拆分，说明改动位置、依赖与如何确认。优先项目既有计划和进度位置，只维护一份实施清单。步骤不按固定分钟数拆分，不要求每步 commit 或启动 reviewer。

实施按计划逐项完成，遇到实际偏差更新受影响的部分。工作范围独立且并行有收益时，可按现有协作角色或已开启的子 Agent 能力分工；普通单会话同样可完成这套流程。不自动创建正式会话或工作副本。

## 调试与测试选择

先观察症状、缩小触发条件并定位原因，再修复；验证应能区分修复前后行为。当前任务仅要求诊断时返回分析，不自行修改。

本适配版默认按改动做最小必要验证。用户明确选择严格 TDD 时执行 RED → GREEN → REFACTOR：先观察针对缺陷的失败，再最小实现、复查并按需要重构。保持他人和已有工作的内容，不为补齐顺序删掉已写代码。正常测试执行但断言不通过时如实报告，修复取决于本次请求是否包含修复。

## 审查与接续

审查基于实际 diff 和需求，区分必须解决的缺陷、建议及未验证项。独立 Review 由用户启动或已有明确安排承接；适配模板不自动授权反复修复、全量回归或新会话。

交付记录实际结果、验证和下一步；任务状态与 Goal 分开，局部 Goal 完成不代表任务自动结束。普通请求完成后返回，已启动 Goal 按其目标接续。用户已有 Git 授权时按其范围操作，无远端也可以完成本地交付。
