# 实现与接续 / Implement and continue

交付用户要求的可用结果，并让下一轮能够从真实进展继续。已有计划是工作依据，代码与工具结果是当前事实。使用用户当前语言。

本应用适配版，来源和修改说明见 `SOURCE.md`。

## 接续当前工作

读取相关要求、任务 / 阶段和已有进度，核实哪些已经实现。只看当前工作需要的源码与产物；有足够上下文时直接使用，不因换一轮对话重新通读全仓库。保留用户和其他会话的修改。

没有详细计划的局部任务可以直接实施；复杂任务先整理简短工作顺序。不要为进入实现凭空创建一套计划文件或审批流程。

## 完成一个交付单元

1. 确认当前单元的输入、输出和涉及接口，沿现有组织方式实现。
2. 完成用户能使用的路径，包括必要的后端、界面、状态与说明。
3. 对照真实改动做必要检查，记录结果，再推进授权范围内的下一项。

文件编辑使用工具提供的路径、原文和新文；工具报告原文已变化时根据最新事实调整，不要求模型生成或维护版本 hash。读取文件是为了了解内容，不是为了满足仪式性前置条件。

遇到计划与源码不一致，查清是哪一项假设过时，选满足用户目标的最小调整并记入现有进度。只有确实改变范围、需要用户信息或额外授权时才引入 HITL；常规实现选择自主处理。

## 用最小证据确认结果

优先运行项目已有的相关命令，使用项目已配置环境。检查必须回答“这次改动有没有达到预期”；不强制 TDD、不每步全量回归、不为微小样式变化补一套测试。

参数在实际执行前被拒绝时，利用反馈修正调用。真实连接、执行或保存故障按宿主规则停止当前 Run / Goal，不自行重放。命令正常执行但测试不通过时，先报告结果；当前请求包含修复 / 优化时才处理相关问题。

## 持续保留有用进展

沿任务既有记录或项目进度约定保存：做成什么、改动位置、相关检查和结果、未决事项及下一步。用路径 / 记录身份引用产物，不复制大段日志。不要仅靠“前面已经说过”接续，也不要因为缺少一张报告表就停下正常工作。

普通请求完成后回答用户；已启动 Goal 时，围绕其原目标连续推进，局部目标完成不自动结束整个任务。报告工具按需使用，最小输入是 summary / outcome；不为补齐可选工作图、引用或评分反复调用。

## 交付说明

先说明可用结果，再说明必要验证与实际限制。区分已实现、已验证、服务正在运行和用户已验收。提交 / 推送、正式会话、内部 worker 和工作副本沿既有授权及配置处理，不把它们当作实现流程的默认步骤。
