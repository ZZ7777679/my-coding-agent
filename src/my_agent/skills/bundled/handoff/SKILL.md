# 工作交接 / Handoff

让接手者快速恢复“为什么做、做到了哪里、下一步做什么”，避免重做和误解授权。交接是接续信息，不是复制整段对话或代替任务目标。使用用户当前语言。

本应用适配版，来源和修改说明见 `SOURCE.md`。

## 确认交接对象与范围

若用户已指出下一会话的用途，按该用途组织简报。查看当前任务、阶段、角色、分工与最新工作状态；不要把已经结束或取消的 Goal 当作仍应继续的指令。

现有计划、规格、进度、差异或提交已有内容时给出路径 / 身份引用，不重新复制全文。不为交接临时创建另一套事实来源。

## 按需要保留以下信息

- **目标与范围**：用户要的结果，当前会话负责部分。
- **已确认选择**：用户决定、关键约束及其原因；建议与假设单独说明。
- **当前事实**：已保存改动、可读取产物、必要运行状态；标明未提交或未验证。
- **证据**：相关检查及真实结果、失败原因和记录位置。没有运行过的检查不写通过。
- **未决事项**：实际阻塞、开放问题、不要重复尝试的已知失败。
- **下一步**：可以直接执行的具体行动、所需输入，以及适合继续使用的已存在 Skill 身份。

这是可裁剪的内容提示，不是逐栏填满的门槛。短任务几句话即可；长任务先给接续要点，再引用细节。

## 保存或发送

已有项目进度约定时更新对应文档；否则按用户指定目的地或现有任务工作记录保存，不强制写操作系统临时目录。只有用户要求额外交接文件时才另存一份。

已有协作关系可通过当前提供的状态 / 协作工具读取或投递简报，目标必须是已安排的会话角色；交接文字不创建正式会话或扩大访问范围。普通回答直接给简报即可，不为发送一份报告强制调用工具。

避免包含密钥、凭据或无关私密材料；引用必要产物而不是拷贝整份原始日志。

## 接手时

先读引用的进度和产物，再核对当前文件 / 运行状态。简报记录的是交接时事实，服务可能已经停止，其他会话可能已有新修改。不要机械重放旧命令或覆盖并发成果。核实后从下一项具体工作继续；只有实际信息缺失才询问用户。
