# 上下文压缩第二版：工具减量、切点摘要与绝对 token 预算

> **后续定稿：** 本文描述已实现基线。三 Agent 讨论后的新增改进已按 [上下文系统最终方案](context-system-final-design.md) 实施：来源、命中片段、调用关联与无收益请求去重；新会话自动起点改为 800K，其余主流程保持。

> 定稿 / 实施：2026-09-21。**第二版已接入 dev 工作区；验证与限制见 [M3 进度](../progress/m3.md)。**
>
> 依据：[近期保留对照](../research/14-compaction-retention-comparison.md)、[原压缩专题](../research/12-context-compaction.md)。本文替代第一版及第二版草案中的策略；历史讨论与验证保留在进度文档。真实验收及用户授权补测采用隔离样本，累计 25 次请求，不涉及个人会话。

## 1. 最终选择

采用组合：**按需缩短可回读工具结果 → 按完整交互切点选区 → 同模型生成接续摘要并替换旧区间**。用绝对 token 预算决定何时处理和保留多少近期材料。自动与手动共用一个实现，只在选区策略上不同。

三者不是互斥算法：工具减量处理大量低密度正文，摘要处理对话语义，绝对预算控制工作区。原始事件、完整结果和读取来源保留在本地，不建立第二份权威聊天记录。

删除草案中的 B/R/S 多重比例、固定“旧历史必须小于 8K”、严格 4K 截断、按释放比例分级和默认二次摘要收紧。一次有效替换是正常路径，不增加评分模型、强制章节校验或业务审批。

## 2. 各方法在 Coding Agent 中的优缺点

| 方法 | 适合解决的问题与优点 | 代价 / 局限 | 本项目采用方式 |
| --- | --- | --- | --- |
| 确定性工具结果缩短 | 命令日志、搜索命中、文件全文常占大量输入；无需模型请求，快且便宜 | 机械截取可能丢掉错误中段或精确代码；回读增加工具调用；不能总结需求变化 | 只在整理时处理较长、已消费且有来源的结果；保留事实字段、头尾片段和回读位置 |
| 按切点做模型摘要 | 保留目标演变、纠正、决定和进度；能处理长单轮已完成步骤 | 有生成成本和语义损失；切点太靠前会丢精确工作材料，太靠后减量不足 | 作为主要压缩手段，替换旧前缀，保留协议完整的尾部 |
| 绝对 token 配置 | 15K 不随 1M 容量膨胀成 150K；阈值、保留和生成额度含义可解释 | 估算有误差；不同任务需调整；不是语义重要性判断 | 控制自动触发、近期区和摘要正文期望，允许覆盖，不当严格切割器 |
| 按容量百分比保留 | 能随小 / 大模型自动缩放 | 大窗口可能留下过多材料；容量不等于当前任务所需工作记忆 | 不作为近期区策略；模型真实容量仍影响是否接近输入上限 |
| 只留摘要、不留近期材料 | 手动交接时减量大 | 刚得到的报错、精确标识、代码原文可能必须重新获取 | 不作为自动默认；手动只留必要尾部，而非承诺完全无原文 |
| 全历史语义挑选 / 图检索 | 可能发现较早但相关的信息 | 新的模型 / 检索成本、选择不稳定和实现复杂度 | 不加入压缩核心；按需回读沿已有工具实现 |

上游依据：
- [DSH 固定版本](https://github.com/deepseek-ai/deepseek-harness/blob/0d1f50007f9bca3f52b06e1c3074fa14d5fb0720/packages/compaction/compaction-basic/README.md) 将工具减量与摘要分开，原文有配对切点；其手动选区更积极，详见 [compactNow](https://github.com/deepseek-ai/deepseek-harness/blob/0d1f50007f9bca3f52b06e1c3074fa14d5fb0720/packages/compaction/compaction-basic/src/index.ts#L332-L372)。
- [Pi 固定版本](https://github.com/earendil-works/pi/blob/71dca871bc80b6bc97be37f0ca3189399d651fff/packages/coding-agent/docs/compaction.md) 使用绝对近期预算和合法切点，并处理超长回合前缀。
- [OpenCode V2](https://opencode.ai/v2/docs/compaction) 使用近期序列化材料，其 15K 默认与工具正文缩短为本方案提供起始参考。本文不照搬其摘要格式校验或网络重试。
- 这些是机制依据，不是本项目质量实测。原生商业压缩协议不能直接用于当前 Go Chat Completions 路线，不为压缩新增 provider。

## 3. 配置与计量：各参数只负责一件事

以下为首次实施的明确起始配置，集中保存、可按会话覆盖；真实验收允许据结果调整，不再把未验证值宣称为最佳实践。K 统一为 1000 token。

| 配置 | 起始值 | 作用 / 理由 |
| --- | --- | --- |
| automatic | true | 是否自动维护；关闭后仍可手动整理 |
| auto_trigger_tokens | 800000 | 当前两个 1M 模型的新会话可调起点；已保存会话策略保持；不是模型能力上限，也不是上游统一默认 |
| keep_recent_tokens | 15000 | 自动模式的近期区目标，采用 OpenCode 起始参考；约为 1M 的 1.5%，不是历史的 15% |
| tool_result_preview_tokens | 1000 | 整理时每份可缩短工具结果的预览目标；本项目初值，不等于 OpenCode 的 2000 字符 |
| summary_target_tokens | 2000 | 摘要正文的期望长度，不是精确硬上限或最小填充量 |
| summary_output_tokens | 留空继承既有运行额度 | API 生成上限，可能包含思考，不能直接设成正文目标导致截断 |

不新增“手动保留 token 数”：手动使用末尾必要单元策略。用户可以先在会话中说明新的工作重点，最新要求会原文保留一次；本轮不另增 focus 控制字段或来源填表。

自动实际触发点取用户配置的起点和模型可用输入容量中较小者；当前目录使用 context window 减有效输出预留，没有凭空设置独立 input limit。模型容量未知时沿显式整理起点工作，不为计量联网或拒绝正常对话。800K 可以调整，不是不可覆盖的输入门槛。

计量规则：
1. 保持相同有效前缀时，以最近主请求服务 input usage 为基准，加上随后模型输出、工具参数 / 结果及新输入的估计；cache token 不重复加到已包含它们的 input。
2. 系统、工具定义、任务、记忆和协作都算入整体输入。前缀改变、模型切换或 checkpoint 替换后，重新估计，等下一次真实 usage 校准。
3. 切点和预览使用同一个本地估算器。没有精确 tokenizer 时明确是估计，覆盖中文、代码和必要原生字段，不声称统一四字符一 token 是精确值；不额外调用模型计数。
4. UI 分别展示“上次实际输入”和“下次预计输入”。压缩后不能继续用旧 usage 冒充新窗口。
5. 字节预算只留作真实传输 / 存储边界。实施时解除 max_context_bytes 对普通上下文的独立旧策略门槛，核对实际请求、JSONL 和内存边界后迁移，不能只改显示标签或放任摘要请求撞同一旧上限。

## 4. 工具结果缩短：处理正文，不破坏工具协议

### 4.1 日常读取与整理分开

工具首次执行继续沿用已有分页、输出限制和大结果归档。新返回且主模型尚未消费的结果，不被后台整理立即截短。正常低压力对话不因为用户又发一句话就重新裁剪历史；取消现有每轮旧结果统一前 512 字符的规则。

达到自动整理起点、用户手动整理或模型主动调用 compact_context 时，才构建确定性的精简投影。原始事件和成果数据不变。

### 4.2 哪些内容可以缩短

候选是已被后续助手步骤消费、具有可回读来源的长工具结果。最新用户要求、助手工具调用参数、尚未配齐的交互、最新一组继续执行所需结果不在此步骤截断。最近已完成单元中的大输出在模型已经消费后可处理；保留尾部不等于所有结果正文永久免缩短。

工具结果保留调用身份和真实状态；按工具已有结果结构提供路径 / 命令 / 退出码等事实字段，不能根据零退出码推断测试通过。正文留头尾片段、原长度和明确的不完整标记；预算包括引用开销，缩短后反而更长则保留原结果。没有结构可利用时使用通用头尾预览，不增加基于关键词猜“重要段落”的系统。

不能截断 tool_calls 的 JSON 参数或破坏 tool_call_id 配对。长参数问题由其所属完整交互进入摘要解决。工具正文若是结构化 JSON，返回合法的预览包装或文本片段，不能制造半个 JSON 冒充完整结果。

只有宿主确实保留的原文才标注可全文回读；上游或首次执行已经截断的内容继续标为不完整。历史 / 文件读取沿现有接口，不重复执行旧命令。

### 4.3 缩短后的生命周期

一旦该精简投影被正式采用，后续请求沿用，不能下一次重组时又恢复成全文。只在现有 context 状态内保存来源 seq 与采用的精简策略 / 范围，不存第二份正文或通用缓存库；窗口投影按原事件恢复。checkpoint 覆盖该区间后，相关投影元数据可归并。

模型回读得到的是新的工具结果，当前步骤可用完整内容，之后仍可进入下一次整理。回查副本搜索过滤与工作索引分页保留。

## 5. 切点：自动保留工作区，手动尽量释放旧历史

### 自动

精简后仍达到触发点时，从尾部倒序累计约 keep_recent_tokens，选择附近协议允许的完整交互边界。近期区是目标，不是精确硬上限；配对调整可以让实际保留稍大或稍小，不增加“超出 15K 就不许工作”的错误。

选中的旧前缀与已有摘要生成一份新摘要。近期区中的原文 / 已精简结果按原顺序保留，切点以前的旧摘要和旧消息被整体替换。

### 手动 / Agent 主动请求

界面“压缩上下文”和 compact_context 默认采用积极策略：保留最新用户原文一次，以及最后一个可继续接续的完整交互单元；其余已经完成的历史尽量进入摘要。已结束助手回答可作为末尾单元，最后是工具结果时回溯至它的工具调用，包含同批配对结果。

这借鉴 DSH 的手动选区语义，不机械复制 retainTokens=0 的代码。工具配对、最新明确指令与双模型续接要求必须成立；它并不承诺零原文。若只有当前输入或一个不可拆分单元，没有旧前缀可替换，直接说明无需整理，不调用模型。

### 长单回合及大单元

正常用户回合内部的已完成工具步骤可以选为切点，不必等下一次提问。摘要说明当前用户目标及步骤进展，最新原文若跨越摘要边界则单独保留一次，避免重复注入。

若最后单元很大，先看是否为可缩短的已消费结果。若是工具参数、最新未消费结果或超长用户输入，不能为凑预算撕开协议或悄悄丢掉原文。显示此部分实际占用，旧前缀仍可压缩；必要输入真的超出服务容量时报告具体来源。保留上限不是对不可分单元的强制裁断。

保留区的原生 reasoning / 续接字段由已有适配器按协议处理；总结区整体替换，不通过删除仍活跃的原生字段制造体积下降。GLM 与 DeepSeek 长回合切点兼容性必须在实施中验证。

## 6. 摘要：通常一次，替换而不追加

摘要输入为有效旧摘要加其后本次选区内的消息；采用已缩短的历史投影，不能忽然从原日志恢复全部巨大输出抵消减量。宿主提供来源区间，不要求模型精确填控制字段。系统 / 当前任务与记忆快照不反复全文总结，必要任务定位可作为简短参考。

提示要求输出工作接续简报：目标、关键纠正、已完成与未完成事项、决定及原因、必要路径 / 标识、下一步；省略执行流水、已失效方案和可回读的正文。不强制 JSON、固定章节或逐项验收声明。

summary_target_tokens 是通常的正文目标。源材料本身短于该目标时，明确要求比源更短，使用简短段落，不按模板填满 2K；必要且不容易回读的细节可以让摘要略长，不能为精确卡数机械截掉末尾。生成额度另外允许思考消耗，流不完整不当成功。

复用当前 GLM / DeepSeek、Go 客户端和请求头。总结过程不执行模型返回的工具，不引入新的 provider、审阅模型或语义打分。

正常只发一次摘要请求；只有选定材料真实超出摘要请求可容纳范围时，才做有界分批滚动更新同一摘要，并计入现有预算。不拼接多个长摘要，不默认再发一次“总结摘要”，也不自动重试失败请求。

采用时新摘要替换选定前缀，尾部保持。后台快照之后的新消息另行追加；新消息增长不让已完成摘要作废，也不能据新尾部增长判断当初摘要没减量。

## 7. 完整运行流程与无效压缩处理

自动：
```text
估计当前输入 → 未达起点：直接工作
              达到起点：缩短可处理工具结果
                       → 已降到起点以下：采用减量投影，不调用摘要模型
                       → 仍然达到起点：按近期预算选切点 → 摘要 → 采用
```

手动：
```text
到下一完整步骤边界 → 缩短可处理结果 → 选末尾必要单元
                                     → 无旧区间：说明原因，不调用摘要模型
                                     → 有旧区间：摘要替换，不受自动 15K 区限制
```

只在采用处比较一次：同一快照、同一估算器下的候选替换区（含摘要包装）必须比被替换区小。系统、记忆、新追加内容不混进压缩收益计算。返回实际减少量，不增加“必须省一半”或“总窗口必须小于 8K”的采用门槛。

若模型正常完成但没有产生更小的替换，保留之前窗口和已采用的有效工具减量，显示“摘要未缩短，未采用”，不能写成成功。相同选区与配置在没有新材料时不自动反复发请求；显式再次操作可以重试。该结果不自动停止仍可正常发送的 Run / Goal，也不在内部循环直到达标。真实模型 / 保存故障沿既有失败停止规则。

这项兜底与 DSH 类似，但不是正常验收目标。减少无效调用依靠：手动不保留整块 15K、正确的完整切点、缩短输出后重新计量、不反复携带旧摘要全文与被覆盖历史、短材料不用长模板。不承诺生成模型绝不返回劣质摘要；真实验收必须证明正常案例有效，而非仅证明失败能被处理。

若摘要确实变小但固定系统 / 工具或必要尾部仍导致超出实际输入容量，应显示主因，不能不断总结相同摘要解决非历史占用。预算到达或用户停止时不偷偷追加请求。

## 8. 接口、持久化与迁移

复用 ContextService、ContextStore、已有 checkpoint / 历史查询、作业和模型适配，不新建压缩框架。背景事实、记忆、协作仍归原服务，摘要不自动转为长期记忆。

- 公开入口继续为 context 面板 / get_context_status / compact_context。compact_context 无需先调用状态检查；默认积极策略，来源范围与事实由宿主给出。
- 面板常显自动开关、手动入口和实际 / 预计计量；可调整的触发、近期保留、工具预览、摘要目标 / 生成额度统一放在可折叠参数区，保持紧凑。手动按钮旁说明“保留最新要求和末尾必要交互”。
- 结果区区分“工具减量”“摘要压缩”“无可替换历史”“未采用 / 失败”；给出同快照前后估计、保留区实际量、摘要请求数和用量。来源详情可折叠，原文可按需读。
- 保留上次实际 input usage；新窗口用估计展示，下一次请求后更新。摘要成本与后续输入减少分开，不声称维护请求本身免费或整次交互立即省钱。
- 正式采用的减量投影与 checkpoint 可重启恢复。只有保存完成再通知 UI；取消不恢复已执行工具，也不在重启后补发模型请求。
- 旧 checkpoint 与原始事件兼容，不重写私人历史。迁移时 recent_ratio / prepare_ratio / target_ratio 不机械乘字节换成 token；旧自动开关及用户明确配置的生成额度保留，新 token 参数采用集中默认并在面板说明，可直接修改，无确认弹窗。
- 废止旧按用户回合自动 512 字符策略；已有消息、成果及原日志不删除。过往请求清单仍描述当时实际发送内容，不能随新策略改写。

## 9. 开发落点和验收

| 切片 | 最小实现 | 直接必要证据 |
| --- | --- | --- |
| 计量 / 配置 | 共用 token 估算，usage 基准失效条件，生成 DTO / TS，解除旧字节策略混用 | 中文 / 代码估计标识、缓存不双计、模型切换与压缩后不套旧 usage |
| 工具减量 | 来源引用、合法预览包装、采用范围持久化 | 新结果首次消费不被提前裁掉、错误尾部可见、原文可读、下一请求不恢复全文 |
| 切点 / 摘要 | 自动 15K 近似区与手动末尾单元，长回合选区，替换 checkpoint | 工具配对、最新纠正保留、摘要覆盖区不重复发送、手动短历史不会因 15K 保留而全留 |
