## 1. 阶段目标与技术选择

让当前 Harness 从“具备编码和协作能力”发展为“能够复用个人工作方式、连接外部工具，并清楚展示执行过程”。

本阶段交付四个模块，均包含桌面入口：

| 模块 | 技术选择 | 调研启发与本项目取舍 |
| --- | --- | --- |
| 项目规范与 Skill | Markdown、标准 SKILL.md、Python 资源目录服务 | 借鉴 Pi、DSH 的短目录与按需加载，区分规则、方法和记忆 |
| 任务工作流 | 扩展现有 Task、WorkItem、Goal、协作服务；JSON 模板 | 借鉴产物驱动流程和完整 Agent 工作单元，支持依赖、反馈与交接 |
| MCP 与浏览器 | 官方 Python MCP SDK；微软 Playwright MCP | MCP 统一连接和工具调用；浏览器作为首个实际服务 |
| Trace 与对话精简 | 现有事件日志的展示投影；React 侧面板 | 借鉴 DSH 的过程折叠、调用关联与最终回答保留 |

继续使用 Python 3.13、Electron、React、现有 JSON-RPC/Pydantic 协议和 OpenCode Go 双模型。新增依赖限定为官方 MCP SDK、YAML 解析器和 Playwright MCP 所需运行包，采用正式版本并写入锁文件；开发启动不运行 `@latest`。

规划时核对的官方 MCP Python SDK 当前稳定线为 v2，支持现有 Python 基线及 stdio、Streamable HTTP；本阶段采用这两种传输。实际锁定补丁版本和兼容验证结果在进度中记录，不能把官网说明当成本项目安装验收。[官方 SDK](https://github.com/modelcontextprotocol/python-sdk)

实施锁定 MCP Python 2.2.0、PyYAML 6.0.3 和正式发布的 Playwright MCP 0.0.82。后者官方包明确依赖 `playwright` / `playwright-core` 的 `1.64.0-alpha-1789764292000`，本项目保留上游配套版本并实际验证页面操作、隔离与清理；不强制覆盖成其他 Playwright 版本，不将传递依赖描述成全部稳定版。浏览器由同一 MCP 包的安装器安装。见 [官方包清单](https://github.com/microsoft/playwright-mcp/blob/v0.0.82/package.json)。

不引入 LangGraph、通用插件框架、向量数据库或图形工作流画布。已有压缩、记忆与协作继续复用，不另建同类系统。

## 2. 四个模块的具体设计

### A. 项目规范与 Skill

#### 资源组织

- 项目规范以项目根 `AGENTS.md` 为入口，进入模型请求时加载；子目录规范按路径展示，并让 Agent 在处理相应目录前按需读取。
- Skill 支持三类来源：应用内置、数据根下的用户目录、项目内 `.agents/skills/`。
- 同名默认采用项目 → 用户 → 内置顺序，界面显示实际来源和被覆盖项；所有资源有稳定身份，避免仅靠名称关联。
- 不向项目自动写文件。用户明确选择创建或导出项目 Skill 时才写入项目目录。

#### 格式与加载

采用标准 `SKILL.md`：YAML 元信息描述名称与用途，Markdown 正文描述方法；允许携带 `references/`、`scripts/`、`assets/`。这一格式具备短目录、正文、附属资源的渐进加载结构。[Agent Skills 规范](https://agentskills.io/specification)

- 每次请求提供启用 Skill 的短目录，模型通过 `load_skill` 读取正文；用户也可在左侧资源管理页为已有会话主动选择。
- 加载结果明确资源基目录，附属文件通过既有读取和执行工具使用。
- 已加载 Skill 在会话中保留引用，同一版本不反复追加正文；修改后下一次请求采用新版本，历史记录保留当时实际材料。
- 压缩后保留当前工作仍需使用的 Skill 引用并重新组装正文，不依赖摘要记住整份操作方法。
- 初版不执行 Skill 中的 Hooks、内联 shell 展开或自动模型切换；额外元信息可以保留，界面明确哪些能力受支持。

#### 桌面体验

2026-09-22 按用户调整：左侧栏提供独立 Skill 管理入口，集中提供目录、导入、查看、编辑、启停和刷新，并可将用户 / 内置资源显式导入选定项目。会话输入框上方不放资源管理面板；需要时在管理页为已有会话选择资源。内置 Skill 通过“复制为用户版本”修改。现有六种内置方法迁入同一资源体系，旧工作记录仍能识别原方法。

Trace 显示“加载了哪个 Skill、为何加载、来自哪里”；上下文面板显示实际带入的内容。

2026-09-22 预装内容增量见 [精选方案](bundled-skills-curation.md)：六项方法基于 Superpowers / Matt Pocock 适配，另附三项 Anthropic / Vercel 原版专业资源。固定源码、许可证与附属文件随应用发布，保持旧方法身份与按需加载。

### B. 默认工作流与可编辑模板

#### 模板与实例分开

- 模板描述阶段名称、目标说明、关联 Skill、可选产物说明、依赖、反馈目标及建议角色。
- 桌面用列表表单编辑，支持复制、增删阶段、调整依赖和 JSON 导入导出。
- 创建任务时复制模板快照；之后修改模板只影响新任务。用户可以单独修改当前任务流程。
- 默认模板包含讨论、规划、实现、验证、审查、交接与收尾；允许直接开始实现、跳过、返回或重复阶段。

#### 执行规则

- 阶段表达任务的长期工作位置，Plan、Goal、常规模式继续表达当前会话怎样工作。
- 普通请求完成后返回用户；只有已启动的 Goal 才自动连续推进其授权范围内的工作。
- 工作节点由完整会话或内部 worker 承担；复用已有角色、分工、协作消息和结果等待。
- 并行节点使用已有协作会话，或在子 Agent 开关开启后按需要委派。系统不自动创建正式会话。
- 反馈关系表达“发现问题后可以回到哪里”，不因 Review 或测试发现问题就自行取得修复授权。
- 实际调用失败继续停止受影响 Run/Goal；测试正常执行但未通过按原规则报告。
- 阶段产物、工作图、报告属于接续信息，不设文件存在、评分、逐项填表等执行门槛。

#### 数据与界面

复用任务修订和 WorkItem，增加模板来源、阶段身份及会话关联。流程配置与运行报告分别更新，模型报告不覆盖用户维护的目标和模板内容。

任务页显示阶段列表、当前成员、最近结果与未决事项；可进入已有会话或手动切换阶段。任务完成仍按用户要求记录，不随某个局部 Goal 完成而自动结束。

### C. MCP 接入与临时浏览器

#### MCP 管理

2026-09-22 常用服务增量见 [MCP 首批方案](mcp-service-presets.md)：Context7 / GitHub 可编辑预设、表单认证、Windows 加密保存与连接失败分类。原有通用服务、工具发现和项目范围继续复用；随后授权的 [OAuth 增量](mcp-oauth.md) 接入登录 / 刷新，插件运行时仍后置。

- Python 后端持有连接，左侧栏的 MCP 管理页集中管理本地 stdio 服务及 Streamable HTTP 服务，选择在哪些项目启用；服务配置与凭据引用保存在应用数据根，不自动写入项目。
- 支持登记、启停、连接测试、刷新工具目录、查看错误和项目启用范围。
- 服务列表使用中文连接状态和传输类型；工具以名称、用途和搜索入口呈现。参数类型 / 必填项可展开，原始 JSON 留在高级详情，展示操作不触发工具调用或增加上下文注入。
- 工具使用服务器身份和原始工具名关联，统一进入现有工具执行、预算、取消、结果归档和 Trace。
- 模型先获得服务摘要，通过工具发现接口选择能力；选中的工具 schema 在下一次请求加载，避免默认塞入全部服务器定义。
- 工具、资源列表及资源读取纳入首版；远程 OAuth、MCP prompts、sampling 和插件市场后置。需要凭据的服务支持明确的环境变量引用。
- 缺失或断开的可选服务不阻断普通聊天；调用中的真实故障按现有规则报告，不自动重放可能产生副作用的调用。

借鉴 DSH 的统一工具身份与连接生命周期，保留现有核心执行接口，不复制其插件宿主。

#### 浏览器选择

采用 Playwright MCP，通过 stdio 启动，默认可见窗口和 `--isolated` 临时上下文。官方实现支持隔离模式及结构化页面快照，适合本地网页交互。[Playwright MCP](https://github.com/microsoft/playwright-mcp)

- 每个正式会话独立持有浏览器实例，同会话多轮复用；内部 worker 使用自己的实例，避免互相操作标签。
- 首次需要时启动；切换会话、普通回复结束或停止 Goal 时保留。
- 用户关闭或退出应用时清理；重启不恢复登录、Cookie、站点存储或自动打开页面。
- 页面快照用于模型理解与交互；截图作为可查看的产物，不把截图保存成功称为模型已完成视觉检查。
- 支持导航、页面读取、点击、输入、截图，以及读取浏览器提供的控制台和网络信息。
- 浏览器运行依赖由 MCP 管理页明确安装或指定，采用锁定版本；未安装只影响浏览器能力。运行数据和产物进入应用数据根，测试使用隔离目录。
- 临时浏览器仅表示不保存站点状态，不将其描述为项目执行沙箱。

### D. Trace 与对话界面精简

#### 主对话

保留用户消息、回答、默认展开且可折叠的思考，以及简短工具动作。调用和结果合并为一项，例如：

> 修改 `src/main.py` · 已保存　查看过程

一轮完成后允许折成过程摘要；错误摘要、HITL 问题和必要程序控制保持直接可见。完整参数、结果 JSON 和详细日志移入 Trace。

#### Trace 面板

- 采用可关闭的右侧面板；窄窗口使用覆盖式面板，关闭后恢复完整对话空间。
- 按 Run → 模型请求 → 工具调用组织，Goal 关联多个 Run；独立压缩和记忆作业保留自己的归属。
- 点击对话中的动作定位对应记录；支持按工具、失败状态筛选及复制参数、结果。
- 展示真实状态、耗时、用量、参数、结果、差异、来源、归档输出，以及关联 Skill、阶段和协作记录。
- 实时更新不重置展开状态或阅读位置，长内容按需加载。
- 复用现有事件和产物，不再保存另一份完整 Trace 日志。旧记录缺少的字段显示未知，不推测补齐。
- Trace 中隐藏或折叠内容不改变模型上下文。请求详情复用实际材料清单，不将有限预览称为完整原始请求。

这一设计承接已有 [界面与 Trace 方案](main-interface-and-trace.md)，保留 DSH 的过程组织思路，同时适配本项目现有 Run 和事件结构。

## 3. 接口、存储与兼容

新增四组服务接口：资源目录与 Skill 管理、工作流模板与任务流程、MCP 连接与工具发现、Trace 分页与详情。

- Python 为唯一业务写入者，renderer 通过 RPC 使用能力；DTO、schema、生成 TypeScript 同步更新，协议升级为 v5。
- 应用数据根保存用户 Skill、工作流模板、MCP 设置和浏览器产物；项目资源使用项目相对路径，机器专属命令路径不写入可分享模板。
- Trace 关联现有 `session_id`、`run_id`、请求身份和 `tool_call_id`。
- 旧任务没有流程模板时继续按原方式使用；用户可以显式套用模板，不批量改写历史任务。
- 旧六种方法身份提供兼容映射；旧会话、记忆与压缩设置保持可读。
- 当前任务的 Skill 内容、流程阶段和实际工具目录进入统一请求组装与材料清单，避免出现第二套上下文注入路径。

上述接口只承担各自职责，不新增统一插件 DSL 或独立工作流运行时。

## 4. 实施路线与交付顺序

| 批次 | 交付内容 | 可直接体验的结果 |

| A | Trace 投影、工具摘要、侧面板 | 现有对话不再铺工具 JSON，能够查看实际执行细节 |

| D | 默认工作流、模板编辑与任务关联 | 新建任务套用个人流程，跨阶段和协作会话推进 |

各批包含后端和桌面体验，不积累成最后才接前端的大批实现。阶段进度按交付结果推进，不设固定工期。

## 5. 验收与范围边界

采用一个空白项目中的**单页计数器**作为联合场景：

1. 使用项目规范和一个自定义 Skill，创建采用默认模板的任务。
2. 讨论后直接实现页面并启动服务。
3. Agent 通过临时浏览器点击按钮，确认数字变化并保存截图。
4. 用户启动已有角色的独立 Review 会话，结果返回后按明确授权修改一处问题。
5. 在 Trace 中查看 Skill 加载、文件修改、命令和浏览器操作；主对话保持简洁。
6. 重启后恢复任务、模板和 Trace，临时浏览器登录与站点状态不恢复。

最小定向验证覆盖：Skill 来源与刷新、旧任务兼容、Goal 与阶段切换、MCP 发现和取消、浏览器会话隔离与清理、Trace 分页关联和迟到事件。测试集中在现有 `tests/`，产物归 `.artifacts/tests/`；通过后不无理由扩大回归。

真实模型验收使用隔离样本，GLM、DeepSeek 各完成一次简短闭环，总计最多 12 次请求、15 分钟；该预算仅用于本次验收，不写入产品限制。未使用完的请求不为凑数执行，模拟结果与真实结果分别记录。

本阶段不包含安装包、自动更新、任意图形编排、日常浏览器接管、远程执行沙箱、默认工具并行或记忆算法重做。正常项目操作沿用已有授权与失败语义，不增加信任开关、强制报告、hash 门槛或逐工具审批。
