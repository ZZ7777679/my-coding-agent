# 主界面、模型切换与运行轨迹

> 2026-09-18。根据用户实际桌面截图与后续修正整理。布局、模型切换、思考流及程序调用卡片已实施；第 5 节的整轮 trace 仍是后续方案。验证与剩余限制记录在 [M2 进度](../progress/m2.md)。

## 1. 会话主体优先

左侧保留项目 → 任务 → 会话的可折叠树，显示各会话的运行、停止、失败和完成状态。主对话区域直接开始显示消息，不重复放会话入口、活动会话横幅、模型标题或大块归属说明。

底部集中输入与当前控制：

```text
┌ 左侧项目 / 任务 / 会话 ┐ ┌────────────────────────────┐
│ 会话名称与当前状态     │ │ 消息、思考、工具过程、回答 │
│ 点击进入对应会话       │ │                            │
│                       │ │ 主体独立滚动               │
│                       │ ├────────────────────────────┤
│                       │ │ ▸ Goal 状态 · 目标摘要     │
│                       │ │ 当前动作 · 耗时       详情 │
│                       │ │ ┌ 输入内容 ──────────────┐ │
│                       │ │ │ 模型⌄ 模式⌄ ···  发送 │ │
└───────────────────────┘ └─┴────────────────────────┴─┘
```

Goal 不存在或已完成 / 取消时，输入区不占位。程序每次调用直接出现在对应对话位置，默认折叠，不在会话末尾另放集中列表。归属、协作和修改成果通过输入框内的“···”按需展开。运行详情默认收起，错误仍直接显示，不能为了紧凑藏掉需要处理的问题。停止当前运行的按钮位于输入框内；查看或停止其他会话先使用左侧树进入对应会话。

布局依靠 flex 分配剩余高度，避免把多个固定高度面板逐个叠在对话上方。展开 Goal / 详情时允许占用一定高度，内容过长在各自区域滚动；正常收起状态把更多高度留给消息。主区域不再套一层整页滚动。

## 2. 同会话切换模型

模型选择在输入框内，当前允许 GLM 5.3 Flash 和 DeepSeek V4.1 Flash。保存选择不调用模型，不创建会话，不清空历史，也不要求停止当前工作。

- 已经接纳的模型请求保持其实际模型，包括正在接收的思考、正文和工具参数。
- 下一个模型请求读取最新已保存选择，适用于后续提问、同一 Run 的工具续答和 Goal 续跑。正在执行的工具照常完成。
- 每次请求及其完成消息记录实际模型，不能用当前下拉框的值反向重标历史回答。旧消息没有模型事实时不补造。
- 选择作为会话事件保存，重启恢复；设置页的默认模型只决定新会话的初始选择。两个会话可以独立选择。

实现沿用现有会话存储和 Go 适配器：`sessions.select_model` 写入 `session.model_changed`，运行循环在请求接纳时读取选择，`RequestStarted` / `AssistantCommitted` 保留实际模型。历史中的 provider 续接数据继续留在 Python。当前已用模型替身验证运行中切换及下一请求路由，本轮未增加真实 GLM ↔ DeepSeek 上下文互换的联网测试。

## 3. 思考流与正文

2026-09-22 布局补充：应用外壳使用窗口可用高度，不让侧栏导航、项目树或会话内容撑高整页。侧栏项目树、管理页、对话历史和 Trace 各自在自己的区域滚动；对话输入区贴合底部。展开的辅助内容限定在可滚动区域内，较小窗口仍能直接操作输入和发送。

展示模型服务实际返回的 `reasoning_content`，默认展开，并以独立“思考”区与正文区分。用户折叠后继续接收内容，流结束不重置该次折叠选择；刷新 / 重启后使用默认展开。用户向上滚动思考时，不强行把阅读位置拉回末尾。

适配器提取明确的字符串字段进入 `ModelTurn.reasoning`，通过 `reasoning.delta` 与正文增量共用消息归属和顺序索引；快照提供当前思考与正文，完成消息保存思考展示字段。仍不将整个原生续接对象序列化给 UI。流片段不逐 token 同步落盘，也不影响已有回答正文首字的计时口径。

没有思考字段的响应不显示空思考框，不据耗时猜测内部内容。旧记录没有展示字段时保持原样，不把 native 对象临时拆到前端。已完成的新记录重启可读；被取消或退出打断的未完成预览沿用现有流保存语义，不承诺恢复全部未提交片段。

## 4. Goal 与运行控制

尚未结束的 Goal 放在输入区上方，默认只显示一行状态与目标。展开后保留完成条件、累计使用量、最近报告、暂停、接续、取消及预算设置。新的 HITL 问题自动展开以便答复，用户仍可折叠。失败、暂停、等待、预算耗尽和中断仍可明确接续，因此保留控制入口。

完成 / 取消后，输入区卡片消失；对话内在结束事件处保留只读折叠卡片，可看结果、完成条件和使用量，不自动恢复目标。历史代码、工具结果和对话继续保留。上下文组装将终态 Goal 的定义与旧工作请求明确标为历史，普通后续请求保持原文；只有当前 Goal 绑定的运行才会注入当前 Goal 指令。历史仍可能影响模型理解，这不等于旧目标还在自动执行，也不宣称将它从上下文彻底删除。本次不是上下文压缩或记忆功能。

常规 / Plan / Goal 模式和模型并列放在输入框内；Goal 的创建条件与预算默认折叠，Plan 的可选文档路径只在对应模式出现。现有 Goal 插话与失败停止规则不因布局调整而改变。

### 4.1 程序调用卡片

`run_command`、`start_service`、`read_program`、`stop_program` 每次调用各占一个可折叠卡片，按 `run_id` 与 `tool_call_id` 合并对应调用和结果。摘要显示工具名、命令与当前程序状态 / 退出码；展开查看环境、目录、输出并停止程序或打开预览。结果位于历史分页边缘时，仍能从结果恢复对应调用，不依赖相邻位置或“最近运行的程序”推断。

执行中的调用通过既有程序记录关联；活动状态在卡片收起时也会刷新，展开按需读输出。旧记录无法转换为程序视图时显示原始工具结果，不影响执行。项目工作台保留项目级服务入口，便于查看跨会话保留的服务；切换会话、折叠卡片或取消 Goal 不因此停止已经交付的服务，退出应用仍按既定规则清理，重启不重放。

## 5. 后续 trace：主对话保留摘要，过程可以展开

### 2026-09-21 讨论补充：工具详情迁入 Trace

用户希望参考 DSH，将当前对话内的工具调用参数和结果 JSON 放进 Trace。本轮复核已有固定提交的 ui-chat README：可借鉴按轮折叠过程、保留最终回答与错误，以及展示投影不修改模型请求的分层；独立 Trace 面板的具体布局是本项目建议，不称为已核实的 DSH 同款界面。

- 主对话保留用户消息、回答、默认展开且可折叠的思考，以及简短工具动作。工具调用与结果合并为一项，例如“修改 src/main.py · 已保存”；点击进入 Trace 对应调用。运行中显示真实当前动作，结束后可折成整轮过程入口。
- Trace 建议使用可关闭的侧面板，按 Run → 模型请求 → 工具调用组织，展示参数、结果 JSON、输出、耗时、失败信息，以及既有文件差异 / 来源链接。独立压缩或记忆作业保留自己的归属，不强塞进无关请求。列表实时更新，用户展开和阅读位置不因新事件重置；长内容按需加载。
- 程序调用仍保留对话位置的简短可折叠卡片，以及停止 / 打开预览等常用操作；详细输出和原始 JSON 进入 Trace。错误摘要与 HITL 问题仍直接可见。工具摘要由真实参数 / 结果产生，不额外调用模型。
- Trace 是现有执行事实的另一种展示，关闭面板不停止任务；移出对话界面不等于从模型上下文删除工具结果，也不改变压缩和历史保存规则。不建立第二套日志或增加运行检查。
- 本轮仅调整设计，未实施。下一阶段建议把 Trace 与对话减负合成一个独立交付项，具体布局和筛选范围随阶段计划确定。

### 5.2 建议的信息结构

以用户发起的一次 Run 为主要过程分组，Goal 关联它连续推进的 Run，不把整个任务合成一条无边界时间线。已有 `session_id`、`run_id`、请求消息 ID、`tool_call_id`、事件序号用于定位：

| 层级 | 主界面摘要 | 展开后的事实 |
| --- | --- | --- |
| 一次 Run | 当前动作，结束后的工具 / 请求次数与耗时 | 按顺序排列的请求、思考、工具和结果 |
| 模型请求 | 模型、连接 / 等待 / 接收阶段 | 已有首字、收包、用量和实际失败原因 |
| 读取 / 搜索 | `read_file · src/main.py` 或查询摘要 | 范围、结果、截断与来源 |
| 文件修改 | `edit_file · src/main.py · 已保存` | 对应修改记录、原文 / 新文差异和写入结果 |
| 代码执行 | 命令摘要、当前状态与退出结果 | 环境、cwd、输出及程序控制入口 |
| 联网 | 搜索词或目标页面 | 实际使用的搜索模型、来源及引用 |

调用与结果在 UI 通过调用 ID 合为一项；数据层继续保存各自事实，不能只按相邻位置拼接。工具摘要从实际参数和结果提取，不额外调用模型编造“做了什么”。参数仍在流入时只展示接收状态，不能提前宣称已执行或已修改。

进行中的过程保持可观察；完成后可以折为简短过程摘要，最终回答独立保留。错误、待答复问题和未确认结果不被自动藏起。详细日志 / diff 按需展开或在成果面板查看，不在对话里铺完整 JSON；思考是否收起尊重用户选择。
