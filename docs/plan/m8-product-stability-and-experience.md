## 1. 阶段目标与边界

阶段目标：连续处理真实项目时，应用响应流畅、运行事实清楚、异常可以定位和接续，常用操作容易找到，界面有一致的视觉与交互品质。

本阶段的交付单位是完整使用流程，包括正常、等待、失败、取消和恢复状态。保持 Python 3.13、Electron、React、现有 Go 双模型、JSON-RPC 与本地数据根；不借此切换技术栈或大范围重写运行时。

| 主线 | 要交付的变化 | 对应实际问题 |
| --- | --- | --- |
| 异常与恢复 | 原因链、影响范围、结果确定性、实际可用的恢复入口 | HTTP 400 细节丢失、历史失败误停新运行、断连后不知道是否完成 |
| 预算与协作 | 默认不限建议落到完整链路、父子用量可见、部分成果保留、真实进度 | 25 请求／60 工具／600 秒共享额度过早耗尽，取消结果为空 |
| 性能与持续使用 | 长历史按需读取、流式更新效率、后台读取合并、资源清理与重启恢复 | 旧会话读取慢、后台 RPC 积压、多面板与长日志拖慢交互 |
| 视觉与信息组织 | 统一主题和组件、导航／输入区整理、独立详情空间、文字对齐 | 大量同级卡片、层层折叠、侧栏挤压项目树、长材料难读 |
| Agent 工作质量 | 能力说明一致、上下文材料可解释、记忆纠错顺手、改进结果可追踪 | 已有工具被误判缺失、历史结论过时、采用与实际改善混淆 |

用户日常开发仍优先。不增加逐工具审批、信任开关、预测成本准入、强制复盘、证据评分门槛或新的 hash 校验。

## 2. 异常信息统一

### 2.1 复用现有错误和诊断链路

从 `AgentError`、Run／工具事件、诊断记录和 Trace 扩展，边界适配器只转换一次底层异常；不另建一套通用异常框架或重复保存全部 Trace。模型、CLI、桌面使用同一份业务事实，呈现详略可以不同。

| 信息 | 要求 |
| --- | --- |
| 类别与错误码 | 区分可修正输入、预算停止、用户取消、连接／执行／保存故障，不全部归为失败 |
| 发生环节 | 连接、服务响应、流式接收、工具准备、执行、保存、RPC、后台维护等；未知则标未知 |
| 原因链 | 保留服务状态码、有效错误说明、底层原因与必要参数位置；上层引用原错误，不覆盖成空泛文案 |
| 归属与影响 | 关联项目、会话、Run、请求、工具、worker、维护作业；只包含实际存在的身份 |
| 结果确定性 | 未执行、已执行并保存、部分完成、结果未确认；按记录事实判断，不由错误码猜测副作用 |
| 已保留内容 | 部分回答、已完成工具、代码变更、产物、最近确认位置及可读取来源 |
| 恢复过程 | 已尝试什么、尝试结果、当前是否重连／等待、下一步可执行动作 |
| 诊断材料 | 可展开、复制或导出相关脱敏详情；保留原始原因与时间顺序，不暴露密钥，不把有限摘要称为完整原始请求 |

主界面提供短摘要和就地操作；详情进入可扩展的诊断／Trace 空间。HTTP 服务说明有长度或展示分页时，应明确截断及详情入口；未知原因不得补造。“完整有效”指已取得且与排障相关的信息不在层间丢失，不要求把任意响应、全量环境和所有用户材料都塞进错误正文。

### 2.2 统一展示和模型反馈

- 一个根因在父子运行间传递时保留关联，父卡片说明受哪个子任务影响；避免连续显示数个内容相同的报错横幅。
- 模型读取历史失败是成功查询；预算耗尽和取消不冒充模型服务错误。测试正常执行但未通过仍按既定规则报告。
- 诊断保存失败独立标为诊断降级，不覆盖原业务错误；缺少旧字段保持可读。
- 字段与恢复动作从现有 DTO／schema 同源生成。对当前请求没有适用意义的动作不显示，不用固定“请重试”覆盖所有异常。

## 3. 重连、重试、接续和回退

### 3.1 四种不同动作

| 动作 | 恢复对象 | 关键行为 |
| --- | --- | --- |
| 重连 | IPC／RPC 通道、事件订阅、MCP 连接 | 恢复连接后同步真实快照和事件，不重新派发原业务操作 |
| 重试 | 指定失败的请求／调用 | 新尝试有独立身份并关联原尝试，真实请求计入用量；不覆盖原失败 |
| 接续 | 已停止的 Run／Goal／子任务 | 保留原目标、已完成成果和停止位置，在既有入口继续，不从头重复工作 |
| 回退 | 已有代码检查点、会话重新提问分支 | 显示影响，恢复选定代码或从消息重新开始；保留旧记录，不把外部副作用描述成已撤销 |

代码回退继续复用 M6 的 Git／非 Git 检查点服务，既有冲突处理在对应写入边界执行，不新增全项目扫描和证明表。回退接口未确认时先查询实际状态，不因前端未收到响应而重复回退。

### 3.2 建议恢复策略

| 场景 | 默认方案 |
| --- | --- |
| 界面断连、订阅中断、只读刷新失败 | 自动恢复连接或读取，合并重复刷新，采用退避；显示真实恢复状态，用户可停止 |
| Python 后端退出 | 确认原进程退出后恢复后端读取服务，加载已有记录；不抢锁、不重放在途模型请求／项目命令，不反复拉起持续崩溃的后端 |
| MCP 连接断开 | 可以恢复连接与目录，真实工具调用另按结果状态处理；重连成功不表示先前调用成功 |
| 模型暂时性连接／服务故障 | 提供显式重试入口与可选自动重试策略；建议保持当前默认关闭自动模型重试，启用后按配置执行退避与次数限制，尝试清楚可见 |
| 认证、余额、请求格式问题 | 返回具体处理入口；未纠正原因时不循环请求、不静默更换模型或 provider |
| 流式输出中断 | 保留已接收的可展示内容，标明未完整结束；未完整接收的工具参数不执行，重试产生的新回答与旧片段分开 |
| 写入／命令／Git 操作确认丢失 | 先读取已保存事实与对应操作状态；仅当能确认未执行，或原接口已支持去重时重派。未知则显示未确认成果与可操作接续入口 |

自动重连恢复通信；自动模型重试会改变当前失败即停的规则，两者不混用。自动重试由用户保存的策略控制，SDK 隐式重试仍关闭；启用后的故障在策略耗尽或不可重试时停止受影响 Run／Goal。实施这部分时同步 AGENTS.md 对应条款，不凭本计划默默放宽现有规则。

停止信号要覆盖重连等待、重试退避、工具等待和后台队列；用户停止后不能被迟到回调重新启动。用户明确接续前不恢复中断的 Goal 自动推进。状态以运行身份关联，旧失败不能影响后来无关的任务。

## 4. 预算与子 Agent 体验

### 4.1 默认不限与用量分项

承接用户要求记录的预算建议：普通 Run 的请求次数、工具次数和累计活跃时间默认不限，用 null 表达；保留用户主动设置具体上限的能力。Goal、worker、辅助请求、配置保存、CLI／RPC／桌面、历史读取共同处理，不仅改 defaults.json。

- 父子仍统计真实总消耗，界面与模型可查看父任务、各子任务和总计；有限额时返回限额与剩余量，不限时明确表示不限。
- `spawn_worker`、`read_worker` 及合适的状态入口提供预算事实；不要求模型另猜总额度，不增加预测未来调用数量的启动预检。
- 区分实际经过时间与累计 Agent 活跃时间，多个 Agent 并行时后者累加，界面不再把它笼统标成用户等待的总时长。
- 单请求网络超时、模型单次输出、文件／工具展示分页与并发数量独立管理；取消三项累计上限不等于删除全部技术容量配置。
- 旧记录继续按接纳时的预算解释；已有用户配置原样读取，提供明确的“改用不限默认”保存入口，不静默覆盖用户曾设置的值。
- 经验与改进继续保留自己的项目级预算，不因普通运行改为不限而被同步改写。

### 4.2 停止与部分成果

取消、预算停止、应用退出及真实故障均整理已保存的部分回答、最近工具、已完成成果、停止原因和历史入口；没有完整总结时不调用额外模型伪造总结。未完整保存的内容如实标记，工具输出通过原归档回读。

预算耗尽使用预算停止语义；关联取消指出原始来源。用户设置的团队总额度约束整个安排，不能让兄弟任务无限越过该上限。若后续明确需要子任务独立额度，耗尽只影响对应子任务；本阶段先做好共享总账、可选总上限与状态说明，不额外强制用户分配每个 worker 的额度。

新执行故障沿用既有原安排停止规则，不借界面调整偷偷改为忽略子任务故障。已完成子任务保持完成，未完成的保留部分成果和后续接续入口。

## 5. 布局与独立详情空间

### 5.1 应用骨架

- 左侧项目 → 任务 → 会话树保持核心地位，可调宽／收缩并记住状态。全局功能导航更紧凑，Skill、MCP、工作流和经验与改进仍从左侧集中进入。
- 主区用于当前对话、代码或任务工作空间，切换保持项目与来源会话，不重复建立会话入口或大模型标题。项目首页突出继续工作和最近任务，收缩低信息量介绍卡片。
- 输入框保留模型、模式、发送／停止与附件；Goal 仍在附近可折叠，已结束 Goal 不长期占位。思考继续流式展示、默认展开且能收起。
- 工具和程序动作仍在发生的对话位置以简短可折叠项展示；完整参数、输出和日志按需进入详情。
- 可见主区独立滚动，输入框保持可达。避免整页滚动叠加多层小滚动框；长详情有明确的主阅读区域。

### 5.2 子 Agent、Trace、记忆的分工

用户反馈现有小折叠框看不清内容，本阶段必须交付适合长内容的阅读空间；不能只换颜色或扩大少量高度。

| 模块 | 当前工作位置的入口 | 完整阅读布局 |
| --- | --- | --- |
| 子 Agent | 输入区附近简短显示运行数、最近动作，点击查看 | 应用内独立详情页：左侧子任务列表，右侧任务目标／状态／进展／部分或最终输出／错误／关联 Trace；可切换子任务、停止或按原入口接续 |
| Trace | 对话工具项和状态区直接定位记录 | 时间线列表＋详情，按 Run／请求／工具组织；参数、结果、诊断、材料、差异用明确分区，支持展开到主工作区 |
| 记忆 | 会话处显示上次实际使用和快捷查看，项目处进入管理 | 搜索／范围／状态过滤＋记忆列表＋正文与来源编辑区；区分库内条目和本次实际使用，方便纠错、失效与恢复 |
| 上下文 | 输入区短摘要 | 上次实际材料、下次组装规则、压缩状态分开呈现；大材料可扩展阅读，避免同层堆叠所有 JSON |
| 异常与证据 | 原问题或发现旁边的查看入口 | 在当前视野打开相应详情；保留与原任务、错误或候选的关联，支持返回原位置 |

子 Agent 的完整页不是新的正式会话，不改变子任务身份或自动创建会话。可以查看已保存的工具活动和公开输出，不宣称把未知进展总结成已完成工作。

采用统一的“就地摘要 → 侧面详情 → 展开到工作区”交互。子 Agent 默认进入应用内独立详情空间；Trace、记忆可先侧面查看，长内容一键展开。首次实现不强制新增操作系统窗口；已有应用窗口内即可完整阅读，未来需要独立原生窗口再复用同一详情内容。

打开、关闭、切换和返回保留输入草稿、滚动位置、列表筛选、展开状态与焦点；实时事件不把阅读位置拉回顶部。宽窗口并排，窄窗口使用完整页或覆盖面板，不压成不可读的窄列。面板关闭不改变模型上下文或运行状态。

## 6. 视觉体系与可调配色

### 6.1 设计方向

整体简洁、美观、适合长时间读代码和中文。用清楚的排版、留白、对齐与状态层次建立品质；减少重复大卡片、大段装饰文字和同时争抢注意力的强调色。信息密度可调，默认兼顾阅读与空间利用。

主题使用语义颜色变量：应用背景、面板、浮层、主／次文字、边框、选中、焦点、主操作，以及成功／警告／错误。自定义主色主要影响主操作、选中和焦点；状态仍有文字／图标，不能只靠红绿区分。

### 6.2 五组经典风格预设

以下为本项目拟定的初始色板，表达经典配色方向，不宣称完整复刻第三方主题。实际组件、图表与代码颜色在视觉稿中联合校准。

| 预设 | 应用背景 | 面板 | 正文 | 主色 | 风格 |
| --- | --- | --- | --- | --- | --- |
| 石墨蓝（建议默认） | `#14161B` | `#1D212A` | `#E8ECF2` | `#7AA2F7` | 中性深灰配蓝，层次清楚 |
| 经典浅色 | `#F8FAFC` | `#FFFFFF` | `#0F172A` | `#2563EB` | 黑白灰配蓝，明亮简洁 |
| 北欧灰蓝 | `#2E3440` | `#3B4252` | `#ECEFF4` | `#88C0D0` | 低饱和灰蓝，整体柔和 |
| 暖纸米色 | `#F7F3EB` | `#FFFCF5` | `#40372F` | `#8A5A36` | 暖白与棕色，适合文档阅读 |
| 深灰薄荷 | `#141817` | `#202824` | `#E5ECE8` | `#7BC7A8` | 保留当前绿色识别感，降低大面积绿底 |

设置中提供预设、主色选择器／HEX 输入、即时预览、保存和恢复预设。文字与按钮前景随背景保持可读；自定义颜色对比不足时提示并提供推荐组合，不增加阻止正常工作的审批或强制门槛。图标、图节点、连线、终端和编辑器同步适配浅深底色，保留必要的代码语义色。

外观为应用级偏好，保存在选定数据根，通过受信设置入口读写，renderer 不直接访问文件。默认主题定义集中维护；首次绘制尽量采用已保存主题，避免启动闪白，修改不重启后端或中断任务。

### 6.3 关键组件文字对齐

- 表单在同组内统一标签列与输入起点，宽窗口对齐，窄窗口自然改为上下布局；不靠空格或固定字符数排版。
- 标题、描述、内容正文和操作区使用一致的边距与排版层级，长标题换行后不能挤乱按钮。
- 图标放统一尺寸容器，与单行文字垂直居中；多行说明从正文起点对齐，不缩进到图标下方。
- 同类按钮、下拉框、输入框与状态标签统一高度和内边距，文字垂直居中；同级操作排列有稳定间距。
- 列表正文左对齐，数字列右对齐并使用等宽数字；状态和操作列保持对齐，空值有一致表示。
- 错误卡片按“原因 → 影响／已保留成果 → 操作 → 技术详情”纵向组织，不能把几段说明放成拥挤的横排。
- 合作图节点的标题、角色、动作、计数和入口采用统一布局；连线标签与节点内容不互相遮挡。
- 代码、日志、路径和 ID 保留合适的等宽字体及复制能力；长文本按语义换行或局部展开，不能为了对齐截掉唯一排障信息。

使用少量共享组件与 CSS 变量集中落实，不为每页写另一套控件，也不为换视觉引入完整的新 UI 框架。覆盖键盘焦点、悬停、禁用、加载、空状态和错误状态；支持 Windows 常见缩放下的可读性。

## 7. 性能与持续使用

先在当前代表性样本上记录启动、冷／热打开旧会话、切换会话、首个反馈、打开详情与后台空闲表现，再按瓶颈优化，不凭感觉给所有接口加缓存。

- 复用已有日志缓存与在途读取合并；请求按身份关联，过期回包不能覆盖新选择。避免单条流式片段触发整页历史／记忆重新读取。
- 长对话、Trace、记忆和成果采用分页／按需详情；仅在实际渲染测量显示必要时使用虚拟列表，保留搜索、复制、定位与阅读位置。
- 区分本地排队、请求准备、连接、首个服务数据、思考首字、正文首字和完整完成时间。服务响应慢与前端卡顿分开定位，不把模型耗时承诺成客户端优化收益。
- 页面隐藏或面板关闭时停止无必要刷新；已运行任务仍保留正确事件接收。空闲不持续高频 RPC／磁盘访问。
- 检查取消和退出时的请求、事件订阅、MCP、终端／程序及句柄清理；重启恢复业务记录，不自动重跑服务或在途副作用。
- 性能结果记录相同样本与环境的前后对比，响应阈值作为体验目标，不写成运行时拒绝条件。

## 8. 高频流程与 Agent 工作质量

### 8.1 任务、协作和恢复入口

打开项目 → 继续／创建任务 → 对话执行 → 按需协作 → 查看改动／程序 → 接续或结束，应能在当前工作位置找到下一步。现有角色、任务绑定、工作图和 handoff 继续复用；缺少可选配置时给相关入口，不使普通编码需要先填写团队表单。

合作图同时做好节点编辑、当前工作、返回会话、查看成果与 Trace；用户能看懂谁在做什么，生成配置、保存配置、实际开始运行三种状态清楚区分。

### 8.2 能力与材料一致

- 能力目录、模型实际加载定义、可调用工具与界面说明从真实注册／启用状态派生，区分已发现、已加载、可用和已调用，不依赖历史模型自述。
- 核对按需发现是否能让模型找到 worker、搜索、Git 等已有能力；不通过恢复全量 schema／Skill 正文解决所有发现问题。
- 上下文材料和用量保持 M3／M6 的真实边界，减少重复附带目录和重复工具结果；必要历史可回读，不做未经验证的固定比例删减。
- 不自动增加模型或切换 provider，不新增图数据库、向量数据库、插件宿主或工作流运行时。

### 8.3 记忆与经验改进

优先改善现有能力的使用质量：本次用了什么、来源在哪里、是否过时、怎样纠正。提供无关／错误／过时等快捷反馈，复用现有修改、替代和失效服务；反馈不自动变成全局事实或采用代码的授权。

经验与改进保留选择性调查，显示实际证据和相关记忆；候选、采用与后续观察继续关联具体版本，不能把采用当作收益。明确的问题可从 Trace 就地带入复盘，日常执行不强制复盘。若有真实误召回样本，再定向调整排序和去重，不在本阶段默认重做记忆算法。

## 9. 实施顺序与交付

| 批次 | 范围 | 可体验结果 |
| --- | --- | --- |
| A | 异常与恢复契约、预算与部分成果；保留近期未提交修复 | 失败有原因和接续入口，父子用量可见，默认限额不再阻断普通协作 |
| B | 主题／对齐基础与关键页面视觉稿，再实现应用骨架 | 配色可选可调，主对话与导航统一，阅读空间足够 |
| C | 子 Agent 独立详情、Trace、记忆与上下文阅读空间 | 小折叠入口可进入完整页面，能读长结果，切换返回不丢位置 |
| D | 任务／合作图、经验改进与能力发现接线；针对测量优化性能 | 常见任务流完整顺畅，已有能力与模型说明一致 |
| E | 代表性持续使用、恢复场景、主题与缩放检查，指南更新 | 正常与异常流程均有实际证据，已知限制明确 |

每批包含后端事实、模型接口和桌面体验，不把 UI 接线全部留到最后。关键视觉稿覆盖主对话、子 Agent／Trace 详情、任务合作空间和记忆／改进页，可先用同一示例比选色板；不用先做完所有页面再判断风格。

不设固定工期。不通过批量新增审批、严格默认限额或过度校验达成表面稳定。性能、工具与记忆工作以真实问题和有限代表性场景为依据，避免顺带重构全仓。

## 10. 定向验收与证据边界

测试统一放在现有 `tests/`，临时产物放 `.artifacts/tests/`。只覆盖实际改动、相关失败和核心接续，不无理由扩大回归，不把检查设施变成产品启动要求。

| 场景 | 要观察的结果 |
| --- | --- |
| 普通任务和四个只读 worker | 默认不限真实贯通；父子分项准确，工具进度可见，停止后已有成果可读 |
| 显式设置有限预算 | 准确显示预算停止、消耗和影响；历史接纳快照不被新默认改写 |
| 连接失败、HTTP 拒绝、流中断 | 原因链可读，不错误归为思考；若开启重试，次数与每次结果可见，停止能中断退避 |
| 操作已完成但响应丢失 | 重新连接／查询不重复文件修改、命令启动或 Git 操作，未知结果如实显示 |
| 子任务失败／取消／应用退出 | 原安排与后续读取分离，部分成果／中断点可回读，重启不自动重跑 |
| 两种既有回退入口 | 代码恢复和从消息重开符合预览；失败不伪装完成，旧记录保留 |
| 长会话与快速切换 | 输入、选择、折叠、滚动和详情定位稳定，无重复读取积压或迟到回包覆盖 |
| 子 Agent／Trace／记忆完整页 | 长内容可读、返回来源位置、筛选与草稿保留，图和表单不因窄窗口错位 |
| 五种主题、自定义主色、重启与缩放 | 主题持久，主色可恢复，文字／数字／图标对齐，编辑器／终端／图状态可辨认 |
| 记忆纠错与改进关联 | 更正沿原服务生效，来源和版本可核对，采用不被描述为已证明改善 |

故障用隔离传输、进程和数据样本复现，不修改用户 VPN／防火墙或破坏个人项目。真实模型验证采用小型只读协作及简单代码任务，区分服务自身失败与本地机制问题；不自动重发用户历史。是否实际访问模型、用了多少请求、哪些是替身，都在阶段进度中记录。

形成方案时仅核对代码、既有截图和历史验证；后续已完成的性能测量、实际桌面、隔离故障及真实模型证据见 [M8 进度](../progress/m8.md)。历史 800K 长输入、完整 Conda、个人 MCP OAuth、偶发程序终态保存等限制仍保留；新证据明确覆盖后才更新。

## 11. 本阶段后置范围与文档同步

安装包、自动更新、跨平台、新沙箱后端、自动故障转移 provider、原生多窗口系统、记忆算法整体替换与更复杂的自主进化，均不自动并入本阶段。启动与重启体验仍会改进，不能据此声称已经完成安装交付。

实施后同步 DTO／schema／TypeScript、设置说明、README 和对应用户指南；必要时根据实际协议兼容性决定版本升级，不在规划阶段提前改版本。主题与 UI 修改不更换业务身份，不批量迁移旧会话，保存失败保留原配置。
