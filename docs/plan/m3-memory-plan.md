# M3 模块计划二：短期工作记忆与长期记忆

## 2026-09-21 实际使用修正

本轮按用户确认先修记忆提取、纠错、召回及相关接口误导，暂不调整上下文压缩策略。没有新增审核模型、人工逐条审批或代码任务执行门槛。

- **提取依据**：维护模型区分用户决定、助手陈述、工具调用与实际结果；助手自述能力、短暂工具可用性、token 用量和单次网络失败不应作为项目长期事实。这是提取指引，不声称能够确定性保证生成内容正确。程序工具的历史回读优先保留实际结果，不能被卡片携带的调用参数覆盖。
- **纠错候选**：按本批新材料词法检索已有项目条目，包括停用 / 过期条目，沿用现有候选数量与容量；不再从整个库按 ID 取前几条。优先修改已知 ID；模型省略 ID 时，仅对候选中唯一精确同名项复用身份，不做模糊强制合并。明确失效的条目可更新为停用，已停用条目不能仅凭旧内容重新启用。
- **纠错路径**：主会话已有明确证据或用户纠正且允许贡献时，指引模型直接使用现有 `save_memory` 更新 / 停用，无需重复询问确认。读取记忆或上下文状态所得的新工作也能进入既有空闲维护。用户编辑和固定条目不由后台覆盖；当前批次显示保存 / 更新与保留条数。没有自动回扫、清理既有个人记忆。
- **召回与搜索分开**：手动搜索按关键词匹配，固定项不再冒充命中；自动召回优先固定项，仍受既有容量限制。失效或尚未生效的替代条目不能隐藏当前有效知识。保留词法 / 结构检索，尚未实现向量语义检索，不另加 provider。
- **双方接口**：`read_memory` 返回启用 / 失效、作用域、来源处理边界与更新时间；UI 明示后台提取是可纠正参考，边界序号不是逐条事实证明。`get_context_status` 不再返回展示专用的 `preview_complete`，实际采用形式只看 `form=full/summary/fragment`，并提供释义；桌面预览字段保留，不改变实际模型输入。

验证边界及当前进度见 [M3 进度](../progress/m3.md)。模型是否在真实复杂对话中正确提取仍需实际观察；模拟场景验证取材、持久修订与下一请求召回，不冒充生成质量验收。

## 1. 先区分三种“记住”

| 类型 | 例子 | 应放在哪里 |
| --- | --- | --- |
| 当前会话上下文 | 刚读过哪个函数，接下来改哪一行 | 近期窗口、checkpoint 和历史回读 |
| 任务工作记忆 | 页面已完成，说明待写；用户刚决定不使用 CDN | 任务当前字段、各会话进展、决定、产物与 handoff |
| 长期记忆 | 这个项目通常离线使用；运行入口是什么；某种已验证的排错办法 | 项目或用户范围的可维护条目 |

短期记忆不是再复制一份完整聊天；长期记忆也不是把所有摘要永久保存。应用重启、换会话、换任务是三种不同接续需求。

M3 完成后，新会话先理解当前任务；新任务再按需使用长期知识。用户当下的明确要求始终可以纠正旧记忆，记忆不自动成为 AGENTS.md 或新的执行门槛。

## 2. 短期：任务工作记忆

### 2.1 复用现有状态

直接使用现有任务目标、约束、决定、未决项、产物、`TaskWork`、`WorkReport` 和协作简报。用户维护的任务字段保持权威，模型报告不能覆盖它们。

新增一个按需生成的任务工作概览，包括：

- 当前目标与用户确认约束。
- 各会话的角色、范围、最近一次进展、下一步和更新时间。
- 等待中的协作、已返回结果和 handoff。
- 当前有用的文件 / 修改 / 程序 / 历史入口。
- 明确未完成、失败或待用户答复的事项。

目前 `TaskWork.last_report` 表达最新报告。M3 增加按会话保留最新报告的投影，保留原报告历史；某个会话提交新进展不能把其他成员的工作从概览中抹掉。

### 2.2 没有报告也能继续

模型报告的最小输入继续是 summary / outcome。没有报告时仍可从已完成工具、最新回答和运行状态显示有限进展，并明确这些是自动提取的观察，不伪造“任务已完成”。

不要求每轮填写图节点、证据清单或完成度；不另发模型请求来给每条工具记录补总结。信息太长时保留最近进展和来源，详情通过已有接口读取。

新会话读取任务概览，当前会话在下一模型请求刷新。概览无需等其他成员全部结束或全部上报才能使用。

## 3. 长期：作用域和内容

| 作用域 | 适合保存 | 默认来源 |
| --- | --- | --- |
| 项目 | 稳定结构、运行方式、项目偏好、关键决定、可复用排错经验 | 用户明确记住；当前项目的新工作中自动提取 |
| 用户 | 跨项目的表达偏好、工作习惯、用户明确的常用方式 | 用户明确表达为长期通用偏好，或在管理页保存 |
| 任务 | 尚未完成的工作、局部决定、临时约束 | 留在任务工作记忆，不默认晋升为长期条目 |
| 会话 | 临时推理、工具中间输出、具体尝试过程 | 留在会话历史 / checkpoint |

可使用偏好、项目事实、决定、经验等轻量标签方便检索；不引入必须选择的复杂知识本体，也不把每条笔记限制成固定类别。

经验可以是程序性记忆：描述在什么场景用什么步骤、有什么例外和实际依据。按相关任务召回后影响工作方式，仍是可纠正的参考知识；不自动修改 AGENTS.md 或正式 skill 文件。

例如“这个任务先不写测试”不能自动变成“用户永远不需要测试”；“某次运行端口为 8123”不能自动变成项目固定端口；模型的一次猜测不能记成已经验证的工程事实。

## 4. 条目和存储

### 4.1 最小条目

宿主记录 `memory_id`、作用域及项目身份、正文、简短标题、来源类型、可用来源引用、创建 / 更新时间、启用状态。标签、替代关系、使用记录按实际需要补充。

本次技术修订明确支持可选的主体 / 路径、事实适用时间、`supersedes`、`related_ids` 和条目修订信息。记录时间由宿主生成，适用时间需有来源依据；缺失保持未知。模型不用为普通一句话凑齐所有字段，关联也不要求达到固定分数。

用户 / 模型的写入接口以内容为主；宿主补齐身份和时间。来源引用有则保存，引用缺项不成为保存有用知识的硬门槛。条目可以是简短 Markdown，不要求模型填写可信度评分、有效期和全部证据。

区分 user、agent、maintenance 三类来源，显示它是用户保存、Agent 提取还是后台整理。条目是可纠正的知识，不使用一个分数宣称它绝对正确。

### 4.2 物理组织

首版实际使用以下结构，以条目的 `scope / project_id` 区分作用域：

```text
<data-root>/memory/
  entries/<memory-id>.json
  forgotten/<memory-id>
<data-root>/sessions/<session-id>/
  memory.json
  memory-usage/<job-id>.json
```

JSON 负责元数据，正文保持可读 Markdown 字符串；管理页可直接编辑。不同时维护一份必须逐字同步的 Markdown 主本和 JSON 主本。索引能重建，正文和用户编辑不能靠重跑模型恢复。

记忆归应用数据根，项目移动后沿项目登记身份恢复，不靠绝对仓库路径当唯一身份。不默认在项目创建 `MEMORY.md`、初始化 Git 或添加提交；用户需要可移植文档时再提供明确导出。

沿用单写者和原子保存；不用 Git worktree 合并本机几条笔记，不建分布式锁或独立常驻 memory 服务。

知识页也使用独立条目，类别为 `knowledge_page`，`source_ids` 指向来源；不在用户项目落 agent 数据。来源改变后标记 stale 并停止自动注入，可手动从来源重新整理，或在后续增量维护中更新。经验手册是 `procedure` 类别条目的筛选视图，不另维护必须同步的巨型主本。

## 5. 写入方式

### 5.1 用户明确要求记住

会话里的“记住这个项目……”可调用记忆工具保存；默认作用域为当前项目。用户明确要求通用于其他项目时使用用户范围。模型已能从语义判断时不追加确认；只有确实存在互斥含义才询问。

保存成功后用简短卡片说明记了什么、在哪个范围，可直接修改或撤销。不会仅回答“我记住了”却没有持久化。

### 5.2 工作中的自动记录

当既有任务中出现稳定且可复用的知识，Agent 可以记录项目记忆。工具使用简洁的保存 / 更新操作，不要求切换特殊模式或先进入单独审批页。

用户维护或固定的条目不由后台模型覆盖。相近内容可以更新现有条目；出现不同解释而无法确定时保留为可见的不同记录或暂不合并，不阻断当前代码工作。

### 5.3 空闲整理

以已结束的工作区间为输入，批量提取新增知识，优先复用现有报告和关键事件。只处理尚未处理的区间；不在每条消息之后串行生成一份总结，也不反复扫整库。

默认在没有前台待发请求时接纳整理。新前台到来时暂停接纳新维护请求；已在途的请求可完成保存或被用户取消，不强制等待维护完成才能发送前台问题。

整理是独立维护作业，使用触发会话当前选定的现有 Go 模型、该会话请求头与连接池，记录 `purpose=memory`。合并多个来源时保存来源列表，不能假装是某一条用户消息直接授权的规则变更。

模型输出简短的候选新增 / 更新，宿主填元数据。格式无效只结束该维护作业并给出可见结果，不加隐式纠错循环、审核模型或全应用停止。没有值得记忆的内容是正常空结果。

保存并发采用条目级处理：若用户刚编辑了同一条，保留用户版本，跳过该候选或把它作为建议显示；不使整次原任务失败，也不要求整个记忆库版本完全不变。

### 5.4 独立记忆单元与增量合成

提取时把含糊的代词、对象、项目和相对时间补成离开原聊天仍可理解的内容；无法确定时不补造事实。已有明确内容直接保存，整理不是用户显式记住的额外模型前置请求。

同一批次处理新增、重复、修订、替代。相同经验合并增量而非反复新增；旧事实适用于过去时保留历史状态，当前召回使用新的有效条目。只靠“写入时间最新”不能解决所有冲突。

借鉴 SimpleMem 的表示和合成思想，时序仍采用本项目的空闲 / 工作边界整理。原始事件先保存，提取结果后保存；不照搬在线模型写入到每次前台消息，也不声称无向量检索已经完整复现 SimpleMem。

### 5.5 增量经验手册

参考 ACE，以稳定条目增量维护经验，保留适用条件、操作要点、例外和反馈。需要修改哪条就修改哪条，避免让模型反复“重写整份更简洁的手册”丢失细节。

程序性条目共用保存 / 检索 / 遗忘流程，不增加三个常驻反思 agent。显式用户纠正与可解释的实际结果可用于修订；条目被加载、任务总体成功都不自动等于它有帮助。反馈用于管理与排序，不设置经验评分阻止工具执行。

### 5.6 可选关联与知识页

**关联记忆实验**在会话输入区的记忆选项中默认关闭。开启后，现有整理批次从有限候选中提出 `related_ids`；不比较全库所有条目对，不为每一条边单独调用模型。连接表示相关，不默认为因果；未知引用只跳过该连接，普通记忆仍可保存。

**知识页**是面向一个主题的派生概览，用户可手动创建；自动维护实验默认关闭。它组合来源条目、工作报告或产物，保留来源引用、生成时间和更新状态。新事件只让相关页面待刷新，不触发全库重写；刷新按已有维护调度进行，前台可直接回读来源。

两个实验都在 M3 C 批提供实际可用的界面和行为。关闭关联实验不删除条目和明确替代关系；关闭自动知识页维护不删除已保存页面，也不强制前台等候。手动编辑的正文保持用户所有权。

## 6. 使用和检索

### 6.1 默认路径

1. 请求组装先确定当前项目、任务和最新用户目标。
2. 加入必要的任务工作概览。
3. 从启用的项目 / 用户记忆中按词法、结构条件与已启用关系合并候选；按 ID 去重。
4. 在可用上下文预算内采用短索引、主题概览或具体正文，并记录本请求实际使用的 ID 与层级。
5. 需要更多细节时，模型使用记忆搜索 / 读取工具；没有命中就正常工作。

固定的少数用户条目可以优先提供；固定不等于永久强制执行。长正文按需读取，不因为一条笔记很大就把最近用户输入挤走。

### 6.2 第一版多路检索

修订后不止做关键词查找，但继续使用本地索引：

| 路径 | 处理的遗漏 |
| --- | --- |
| 词法 | 中文片段、英文标识符、路径和稀有名称的直接命中 |
| 结构 | 项目、主体、路径、已知时间和当前 / 历史状态条件 |
| 关系 | 明确替代链；开启关联实验后的相关条目补查 |

宿主合并、按 ID 去重，在剩余预算内选择相关材料。当前问题问“现在怎样做”时不把已失效条目当默认；问“之前为什么这样”时允许查历史及替代过程。查询条件不足不会拒绝检索，默认从当前项目与当前状态开始。

复杂问题可由主 Agent 在既有循环中分解查询，或者在允许子 agent 时委派检索角色；普通问题没有额外模型规划请求。关联展开量集中可调，不复制论文固定 top-k 或门控阈值。词法 + 结构 + 关系并不具备完整 embedding 语义召回，本轮不增加 embedding 调用、额外 key 或搜索服务。

索引故障时可从有限范围条目直接检索，并提示索引待重建；不能把可选索引缺失变成模型不可用。索引只提高查找效率，不负责判断用户任务是否“允许执行”。

检索数量与上下文长度受可调预算控制；相关性评分只做排序，不要求超过固定分数才准许运行工具。概览和经验的原始依据可继续展开；推断关联错误或同义表达未命中都应允许用户纠正，不转成运行故障。

### 6.3 记忆可能过时

记忆说“使用 npm”而当前项目已使用 pnpm 时，实际文件和用户最新要求优先；更新笔记即可。涉及具体命令 / 文件时按当前任务需要读取现状，而不是对整个记忆库做 hash 或引用校验。

用户明确的当前纠正优先于自动推断。项目规则继续由项目规范负责，记忆只是辅助材料；历史记忆中的命令文字不会自行触发执行。

## 7. 纠正、停用、遗忘与整理

| 操作 | 下一请求的行为 | 原始历史 |
| --- | --- | --- |
| 编辑 | 使用新正文，显示更新来源 | 保留曾发生的工作 |
| 停用 | 不参与自动注入 / 检索默认结果，可恢复 | 保留 |
| 替代 / 合并 | 只把有效新条目纳入检索，保留必要变更来源 | 保留 |
| 忘记 | 删除记忆正文和索引内容；保留最小 ID / 来源处理标记，避免重扫旧来源再生成 | 不等于删除聊天，可另行管理历史 |

遗忘必须影响当前组装缓存，不能只删除文件却继续发送缓存里的原笔记。已经发出的请求无法撤回其输入；更新从下一请求生效，需要立即中断时使用已有停止入口。

自动整理不读取已处理的旧区间重新提取同一知识，也不从 checkpoint 或模型自动注入的记忆再次学习。遗忘的来源位置保留最小处理标记，不保存被忘记条目的正文副本来做所谓审计。

遗忘同步移除指向该条目的派生关联，并让依赖它的自动知识页立即停止注入旧正文，再从剩余来源按需重建。普通记忆与会话不等待刷新；用户自己编写的页面不能作为“清理缓存”被擅自整页删除。查询历史时同样不能从失效索引恢复已删除的记忆正文。

按独立审查 R6，checkpoint 的输入不含自动注入的记忆；请求边界重新读取当前条目。遗忘不要求摘要重建，也不追加模型调用或代码工具语义检查。原聊天中直接说过的内容仍属于历史，最新明确纠正优先。

“忘记记忆”不保证从旧聊天中抹掉同一事实，也不能保证模型凭当前代码无法再次推断它。管理页应说明删除范围，不声称实现模型反学习。用户明确重新要求记住时，可以从新要求创建新条目。

## 8. 默认行为与成本

建议提供少量直接有用的设置：

- 使用记忆：默认开启，可在当前会话关闭。
- 贡献项目记忆：默认开启，可在当前会话关闭；不影响读取已有条目。
- 用户范围：不从普通项目工作自动推广通用偏好，明确要求记住时保存。
- 自动整理：可关闭、取消，维护额度可调整；显示实际模型、请求、token 与最近结果。
- 实验：关联记忆、知识页自动维护分别默认关闭；开启后仍受当前会话“贡献 / 使用”设置与共同维护额度约束。

开启贡献不意味着每次聊天额外请求一次模型。可直接由正在执行的 Agent 记录少量知识；后台仅对有新增材料的批次工作，无增量不请求。

新增事实、经验修订和可选关联尽量在同一整理请求中输出；知识页只在选择的主题确需刷新时生成，记录独立目的和来源。关闭贡献不继续自动更新条目 / 关系 / 页面；用户主动保存或手动整理属于明确单次操作。

维护消耗单独持久保存，当前桌面展示本会话维护累计请求与已报告 token，未知用量单列，不暗算到已结束 Run。应用级综合费用面板尚未提供；保留每个 job 的计量可供后续汇总。维护不能继续耗尽预算的 Goal。活动任务中的记忆工具仍按该 Run 计数。

不使用固定“三小时、十条消息、三十天失效”等条件决定功能能否工作。闲置合并间隔与单批大小属于集中调度参数，用户手动保存 / 整理无需满足这些自动调度条件。

## 9. 失败与恢复

读取某条记忆失败时说明并跳过该条；普通会话仍可使用其他材料。用户主动保存失败必须明确失败，不说“已记住”；若发生在活动 Run 的实际保存步骤，沿既有故障规则停止该运行。独立空闲维护失败仅影响本作业。

崩溃后从已保存条目和最后处理区间恢复；未完成提取标为中断，不自动重新调用模型。重建索引不重新生成条目，也不丢弃用户编辑。

应用内记忆不包含模型凭据、完整环境变量或 provider 私有续接状态。使用已有凭据边界即可，不新增一个给所有知识打“安全评分”的常驻审查模型。

## 10. 桌面入口

任务详情显示“当前工作概览”，按成员展开最近进展与来源。输入区只显示紧凑的“本次使用若干记忆”入口；展开可看标题、来源和正文，不挤占会话正文。

输入区“上下文 / 记忆”折叠面板提供搜索、作用域保存、编辑、固定召回、停用、忘记和维护状态，不另建重复设置页。自动新增 / 合并显示在同一面板，不要求用户逐条批准后其他工作才能继续。

详情可展开时间 / 替代链、关联来源、经验适用条件和知识页来源；初版用列表，不强制复杂图画布。提供“整理为知识页”和两个实验开关，让用户能看见本次用了什么、改变了什么、付出了多少调用。

会话工具卡中展示实际保存的简短内容与作用域。模型声称记住但没有成功工具结果时，UI 不显示保存成功。

## 11. 实施与最小验收

| 步骤 | 交付 | 直接检查 |
| --- | --- | --- |
| A 中的任务投影 | 按成员保留报告，概览与历史入口 | 新报告不覆盖其他成员；任务目标不被自动报告改写 |
| C1 可维护条目 | 独立记忆单元、时间 / 替代关系、显式工具与管理页 | 重启存在；作用域准确；指代不被错误泛化；保存失败不假成功 |
| C2 请求检索 | 词法 / 结构 / 关系合并、分层读取、使用清单 | 当前与历史问题选对状态；按 ID 去重，不整库灌入 |
| C3 自动整理与实验 | 增量经验、空闲调度、可选关联和知识页 | 无增量不请求；用户编辑优先；实验可关闭，费用可见 |
| C4 遗忘闭环 | 条目、索引、关联、派生页与组装缓存更新 | 下一请求不再注入旧材料；不从同一旧来源重新生成 |

使用简单计数器项目验证“任务进度接续”和“项目偏好跨任务使用”；纠正或遗忘后再检查实际发送窗口。只检查输出回答不够，因为偶然没提到旧偏好不能证明没有发送。

验证集中复用 `tests/`；不建立记忆排行榜，不用大量重复模型调用证明一个开关。摘要质量、中文召回和条目增长带来的实际问题记录在 [M3 进度](../progress/m3.md)，再决定是否需要更复杂检索。

关联与知识页的效果对照按 [技术吸收说明](m3-technology-adoption.md) 使用少量已有材料，记录命中和额外成本。没有效果也保留结论；不能用“采用了新算法”替代真实接续质量。
