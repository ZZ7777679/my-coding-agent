# 协作空间可落地性修复

2026-10-19。用户已授权依次修复 [审查报告](../research/reports/collaboration-usability-audit-2026-10-19.md) 和 DS 评价中的有效问题。复用既有 Task、Run / Goal、协作投递、文件成果和工作图，不新增运行时或审批体系。

1. 接纳前协作错误交回模型；真实执行故障仍停止。统一 discuss / plan / review 的只读接续能力。
2. 工作图定义采用后成为当前节点集合，历史不复活删除节点；支持拖动位置、连线、删除、负责人随草稿一起保存，就近属性编辑。生成草稿明确进入编辑态。
3. 内部提示与用户输入分开预算，接纳前校验，避免启动失败先改阶段；群聊增长历史采用分项记录并分页，兼容原文件，不以整体 4 MiB 限制任务寿命。
4. 同任务候选成员、安排状态、worker 开关和下一步统一可见；不自动创建正式会话或代用户绑定任务。等待支持可选时长，精确取消自己发起的请求，返回进度 / outcome / 结果来源，复用已有摘要。
5. 按任务 / 文件聚合已有修改来源，显示其他会话最近修改；未知外部 / shell 写入不猜来源。不加入长期文件独占、反馈无环或固定委派深度。
6. 同步桌面状态、等待 / 结果 / 来源入口和旧测试定位，定向验证已有用例与审查复现；保留依赖缺失、反馈环、报告可选和故障停止语义。

新增公开字段与 RPC 保持 schema / 生成 TypeScript 同步；必要时升级协议。测试集中现有 tests，产物仅写 .artifacts/tests。真实模型验收不作为本批离线修复前置条件；没有本轮额外授权不调用真实模型、不提交 / 推送。

## 使用入口与本次取舍

- 在任务合作空间切换「团队视角 / 工作视角」，点击节点打开旁边的属性区。工作图可从流程补充骨架或自己添加，拖动节点保存位置；选择连线类型后连接起点 / 终点，选中关系后 Delete 或点击删除按钮。删除保留执行历史，负责人和正文同一次保存。团队生成结果采用后进入编辑区，已有成员改配置后保存即可；新增成员再显式组建或绑定。
- 在会话「协作」中选择同任务候选，先安排角色再投递；模型 `list_collaborators` 同时返回任务归属、可用约定、候选、worker 状态和接入说明。没有 task 或约定时明确原因，模型不能自行创建正式会话。已有 `spawn_worker` 继续由用户开关控制。
- 普通协作只执行一次；协调成员可使用 Goal 持续推进，其他成员承接有限请求。已有 Goal 的暂停、失败和继续由用户操作，普通消息不等于新工作。等待可选时长，到时保留请求并返回 pending；用户或发起会话可精确取消，不取消无关 Run / Goal。
- 结果沿用已保存 Run 的 outcome、下一步、来源与回答；没有报告就显示实际回答，outcome 未知，不强制结构化证明。运行中已经提交的回答可作为进展读取，非完整结果。`read_session(summary_only=true)` 读取实际摘要 / 最近报告，不调用另一个模型生成第二份摘要。
- 「修改成果」选择同任务与相对文件路径，查看其他会话的时间和差异；模型使用 `list_changes(scope="task", path="...")` 和 `read_change(scope="task", session_id=..., change_id=...)`。共享的是本任务文件成果，不因此开放其他任务历史。shell / 外部写入未被记录时来源未知，当前磁盘内容仍由文件读取确认。
- 累积群聊拆为分项保存，旧快照只读保留；桌面与模型公共协议 v9 对齐。最近 20 项是展示分页默认值，可读取旧页，活跃轮次不因分页隐藏；不是任务条数限制。内存仍缓存关联元数据，未声称实现无限规模性能。
