# 上下文系统最终方案：基于 M3 v2 的接续与回读改进

> 日期：2026-09-21。状态：方案已实施到 dev 工作区；定向、桌面与双模型隔离接续验证完成，未提交 / 推送。
>
> 当前运行基线是已实现的 [压缩第二版](context-compaction-v2.md)。本方案确定新增差异和完整行为，不推翻既有压缩、记忆、协作。已按用户明确实施指令完成，实际进度与验证见 [M3 进度](../progress/m3.md)。

## 1. 结论

保留 **按需工具减量 → 完整切点 → 一份接续摘要 → 近期交互 → 按需回读**。宿主负责事实、计量、切点、配对与来源，模型负责提炼语义及决定何时回读。原始历史不改写，摘要不是新的事实数据库。

本次确定新增五项：

1. 给摘要输入的每条材料附真实来源序号，摘要采用简洁的接续结构。
2. 历史搜索直接返回关键词命中的正文片段及原文位置。
3. 历史工具调用与结果能够相互定位，用户与模型共用同一事实。
4. 相同旧前缀的无收益摘要不因近期尾部增长而自动重复生成。
5. 摘要输入容量与实际使用的输出额度采用同一有效配置，消除不必要的保守分批。

不把默认恢复全部原文、永久 pin、语义重要性评分、全量主题图、向量库、审核模型、固定格式检查或二次收紧摘要加入此次范围。上下文仍有损，本方案改善的是任务接续和找回信息的路径，不承诺所有细节自动留在窗口中。

## 2. 三个 Agent 的讨论与最终裁决

按用户明确授权启动三个只读 Agent，由主任务核对当前实现并整合。三方先独立提出意见，再交换关键问题；以下保留分歧如何收敛，不将资料阅读称为产品效果测试。

| 角度 | 主要关注 | 提出的关键点 | 最终处理 |
| --- | --- | --- | --- |
| 上游证据 | DSH、Pi、Hermes、Claude 的具体版本与默认分支 | 上游也先裁工具结果再摘要；结构化接续和来源追踪有实际参考 | 保留默认减量；采用软结构摘要与少量来源；完整取材仅候选 |
| 接续质量与交互 | 纠正、错误中段、近期证据、任务 / 记忆边界 | 提示要求序号但输入缺逐条 seq；查询命中中段却展示头部 | 逐条来源与命中正文列为必改；不靠扩大窗口掩盖回读缺陷 |
| 工程简单性与成本 | 状态所有权、迁移、校验、重复请求 | 复用当前存储和工具；无收益去重应看实际旧前缀 | 少量派生字段和局部去重，不建新索引服务或策略框架 |

交叉讨论形成的决定：

- **摘要取材不默认恢复全文。** DSH 可选 pruner 和 Pi 当前样本明确把裁剪内容交给摘要模型，Hermes 也有先减量路径。它们并未彻底解决中段信息丢失，不能把相同取舍叫作本项目独有的架构错误。
- **回查线索要先有真实来源。** 当前摘要输入只有组末 `history_through_seq`，模型无法可靠引用组内调用 / 结果。先补逐条序号，再要求有用的简短引用。
- **近期保护不增加 pin。** 保留未消费结果、完整工具单元和可调近期区；已消费内容不等于不再重要，但尚无依据增加新的“活跃证据”状态机。
- **原文缺失仍是未知。** 搜索与回读改善能恢复已保存内容，却不能保证模型总能自发发现被省略的错误。需要精确判断时应回读，而不是据预览推断不存在问题。
- **不把分析中的假设直接列成缺陷。** 摘要输出实际被主运行额度限制，容量不一致造成的是保守预留，不是先前猜测的输出超额溢出。

## 3. 上下文由什么组成，谁负责更新

以下是逻辑职责，不要求新增独立数据库、通用 context engine 或重排当前 provider 消息角色。

| 材料 | 所有者 / 来源 | 进入请求的方式 | 不能承担的职责 |
| --- | --- | --- | --- |
| 产品指令、当前工具定义 | 装配根、运行时、工具实现 | 使用当前已装配的真实能力 | 不靠旧记忆声明工具是否存在 |
| 任务目标、已确认决定、会话角色与范围 | 任务与协作服务 | 请求边界刷新当前材料 | 摘要不能覆盖用户维护的目标 |
| 当前运行 / Goal 控制 | 会话与 Goal 服务 | 使用实际状态与最新用户输入 | 历史摘要不能复活已结束 Goal |
| 长期记忆 | 记忆服务 | 沿现有范围、召回、纠错与停用机制注入 | 会话摘要不自动变成永久记忆 |
| 会话接续摘要 | ContextService / checkpoint | 一份有效摘要替换所选旧前缀 | 不是全历史真相或无损副本 |
| 近期交互、当前要求 | 原始会话事件与有效投影 | 原顺序保留，遵守工具配对 | 近期预算不是强制字符切割器 |
| 协作 / worker 结果 | 既有邮箱与 worker 服务 | 短结果、角色 / 范围及轨迹入口 | 不自动导入其他会话全历史，不自动新建会话 |
| 原始历史 / 工具归档 | SessionStore 与原产物 | 有需要时通过现有工具展开 | 不等于磁盘文件的当前状态 |
| 请求材料清单与用量 | 同次请求装配与 provider usage | 向 UI / 状态工具解释实际发送内容 | 展示预览不是实际发送内容的替代计量 |

同一当前任务状态不因历史中曾存在而被反复当作新的决定。新用户纠正优先于摘要中的旧结论；长期记忆仍按其独立接口纠正，不借压缩重写记忆库。协作访问继续遵守用户已安排的角色和范围。

本次不扩展项目 AGENTS.md / Skill / MCP 加载，不调整记忆检索算法或启动新的知识整理流程。这些研究建议保留在各自模块。

## 4. 完整处理流程

### 4.1 正常请求

1. 保存用户输入及已经发生的工具事实。
2. 从当前任务、记忆、协作状态和有效会话窗口组装本次材料，保留最新要求。
3. 估计包括系统、工具定义、原生续接和历史在内的整体输入；未达到自动起点则直接发送。
4. 达到起点时先缩短可处理的旧工具输出。低于起点就采用减量，不调用摘要模型。
5. 仍达到起点时，按完整交互边界选取旧前缀和近期尾部；生成一份接续摘要，以较小的候选替换旧前缀。
6. 发送最终窗口，记录同次材料清单；模型返回后保留真实 input usage，不能用整理前 usage 冒充整理后的占用。

### 4.2 手动或模型主动压缩

沿现有入口在完整步骤边界执行。保留最新用户原文一次和末尾必要完整交互，其余可替换前缀尽量进入摘要；不套自动 15K 近期区。没有可替换历史则不发摘要请求，并说明原因。

普通对话不因每条新消息到来就裁旧结果。未消费结果和未完成配对保持；长用户回合中已完成的工具步骤可以进入旧前缀。已采用的短预览保持生效，不在下一次组装时自动恢复全文。

### 4.3 失败、无收益和接续

- 摘要正常返回但不比同快照的旧前缀更小：不采用，保留旧窗口与有效工具减量；不停止仍可正常发送的业务。
- 模型 / 保存等实际故障：沿既有 Run / Goal 归属与停止规则，不新增重试。
- 独立维护失败不自动使后来正常对话失败。
- 新消息在摘要快照之后到来：保留为后续尾部，不覆盖新输入，也不以新消息造成的总量增长判定原摘要无收益。
- 原始记录、旧 checkpoint 和既有修改结果不删除；重启不自动重放副作用或重发模型请求。

## 5. 摘要输入与输出

### 5.1 输入给出可复制的真实来源

继续使用已有有效摘要与本次旧前缀的公开消息，不恢复全历史。每条材料在摘要专用序列化中增加真实 `source_seq`，保留现有 `role / content / tool_calls / tool_call_id`；组级覆盖边界仍由宿主计算。

这些定位字段只用于摘要取材，不写入主模型 provider 原生消息结构。一个事件可能对应多个派生片段，`source_seq` 是原始来源，不是全局唯一的消息身份。超大单元原有 `original_sequences` 与不完整标记继续有效。

模型可以直接复制来源，不负责生成 checkpoint 身份、控制切点、填充所有引用或证明来源有效。引用写错通过正常回读反馈处理，不以语义引用审核拒绝整份摘要。

### 5.2 输出是工作接续简报

提示围绕以下顺序组织内容，允许短段落或要点、合并和省略空项：

1. 当前目标、最新纠正与有效约束。
2. 已完成事项及实际观察到的结果。
3. 正在处理的问题、失败、未知和未完成事项。
4. 下一步及必要的文件路径、标识符、数值或错误信息。
5. 需要精确展开的少量内容及其来源。

更新既有摘要时保留仍有效的信息，移除已经被否定的结论和失效方案；需要解释变化时简短说明最终取舍。不机械保留所有旧摘要信息，不重新叙述完整执行过程。

示例只说明表达方式，不作为必须满足的格式：

```text
当前目标：完成本地预览；用户已将端口从 8123 改为 8127。
已完成：页面已写入，运行检查曾超时；尚未据此判断页面正常。
待处理：确认当前服务状态，再按用户要求继续。
回查：原超时结果见 seq 214，对应调用可从历史详情展开。
```

省略中段不能概括成“没有错误”；摘要写的是切点当时的状态，后续完整尾部可能已完成其中的待办。主模型应结合尾部继续，而非重做摘要所述下一步。

不要求固定章节、JSON、最少字数、每项都有来源，不新增格式修复请求、第二个评审模型或语义评分。2K 是正文目标，不是精确硬上限。

## 6. 历史搜索与展开的最小契约

### 6.1 搜索必须给出命中正文

当前普通事件搜索先按全文过滤，却从正文开头返回，可能让中段命中在返回片段中不可见。改为：

- 无关键词浏览、精确条目读取继续使用现有字符分页。
- 有关键词时，每条事件先返回首个命中位置开始的原文片段；不新增前后窗口配置或多命中合并算法。
- `offset` 是本次片段在原文中的真实字符位置，`next_offset` 是这段结束位置；不能使用大小写转换后发生长度变化的字符串坐标。
- 模型要连续展开普通事件时，保留 `entry_seq`，将返回的 `next_offset` 传作 `offset`，并清空 `query`；归档则保留原 `artifact_id`，同样传 `offset` 并清空 `query`。归档展示条目的 `seq=0` 不能当事件身份，避免续页读错来源或再次跳到下一个命中。
- 界面保留查询条件用于结果列表；单条原文的“继续读取”使用无关键词精确读取，不能把两种请求混在一起。“从头查看”保留事件或归档身份并使用 `offset=0`，即可访问命中位置之前的正文。
- 保留来源过滤与现有搜索结果排除策略，不建立新搜索服务；错误定位仍是可修正反馈。

`offset > 0` 或 `next_offset != null` 都表示当前展示不是整条原文。即使片段已到末尾，也不能把前半段未展示说成全文完整。归档关键词路径同样采用真实位置；`matches` 明确区分普通搜索的“命中记录数”和单归档的“出现次数”，在现有响应中增加有默认值的计数单位说明即可，不冒充同一统计含义。

### 6.2 一次调用与结果相互可查

`HistoryItem` 增加可选的 `tool_name / tool_call_id / call_seq / result_seq`，从原事件的运行身份和调用身份推导。调用项能定位结果，结果项能定位调用；缺失或未完成时相关字段为空，正文仍可读。

不把运行卡片的调用参数覆盖到结果正文中。UI 用简短工具名称和“调用 / 结果”入口，模型拿到对应序号；详情按需展开，不在搜索结果中默认复制全部参数和结果。

保留原事件 `kind`；展示类别与事件类型分别解释，不为命名统一改写旧日志。关联仅从同一运行的真实调用关系恢复，不按工具名或相邻序号猜测。直接读取来源不会重新执行历史工具。

字段只存在于读取投影和生成 DTO，不另存一份关联数据库。旧数据不迁移、不补写；找不到关系时不阻断压缩或当前任务。

## 7. 近期材料与工具减量

保持现有规则：新结果先完整消费；整理时处理已消费的长结果；保留真实状态、已有事实字段、头尾片段及精确回读入口。原工具本身未返回的内容不宣称能从历史恢复。

自动近期目标继续是约 15K 完整交互，实际值可因协议边界超出。它不是“所有近期结果全文免裁”。手动更积极，已结束 Goal 仍只是历史。

本轮不增加语义重要性分类，不根据工具名字永久保留命令 / 搜索结果，不要求用户 pin，也不在每步判断材料是否“已经没有价值”。需要精确代码就读取当前文件；需要当时的错误、输出或讨论就回读历史。

若后续真实任务反复在“压缩—读取同一大结果—再压缩”之间循环，再以该样本比较更完整的摘要取材或范围明确的近期保护。是否采用按接续正确性、总 token、延迟和重复回读衡量，不以单次摘要覆盖率决定。

## 8. 计量、预算与重复无效请求

### 8.1 自动起点按当前 1M 模型调整，其余默认保持

用户进一步指出当前两个模型均为 1M 窗口。已核对本项目 `defaults.json` 的模型目录：GLM 与 DeepSeek 都登记为 1,000,000 token。因此方案将自动起点从此前 128K 调高为 **800K**，约为当前窗口的 80%；这是本项目新的可调初值，不是最佳效果结论，也不表示所有 Coding Agent 都使用相同阈值。留出的约 200K 用于后续消息增长、输出预留和估计误差，不保证任意大小的新输入都能容纳。

自动起点控制何时开始整理，与压缩后保留多少内容分开；本次不随窗口大小把近期区按比例放大。用户仍可在达到起点之前主动压缩。运行默认已改为 800K，用于没有保存策略的新会话；已保存值不通过“恰好等于128K”猜测是否为用户选择并自动改写，可在「上下文 → 压缩参数与计量详情 → 自动整理起点」调整并保存。

| 项目 | 本轮决定 |
| --- | --- |
| 自动起点 | 800K，可调；实际起点不高于所选模型可用输入容量 |
| 自动近期目标 | 15K，可调；完整边界可超出 |
| 旧工具预览目标 | 1K，可调，含引用成本 |
| 摘要正文目标 | 2K，可调，提示目标 |
| 摘要生成额度 | 默认继承主运行；显式设置沿既有主运行预算约束 |
| 模型与服务 | 当前 GLM / DeepSeek，经现有 OpenCode Go；无静默切换 |

K 为 1000 token。当前模型目录只提供统一窗口值时沿现有窗口减输出预留计算，不凭空新增未核实的 provider input limit。将来目录具有独立输入限制时才按适配契约使用。未知容量仍使用显式维护起点，不为计量联网。

摘要有效输出额度在接纳时固定；摘要输入容量估计和实际 `model.complete` 都使用它。本轮发现的差异是父额度较大时过度预留，修正用于避免不必要分批，不宣称修复了未发生的超额请求。

### 8.2 同一无收益前缀不要自动再总结

需要修正的具体场景：上次摘要未变小，新加入的短消息仍全在近期区，实际选中的旧前缀没变；当前比较整个会话 `through_seq` 会认为需要再试。

最终采用最小的会话内自动去重：在计算完实际选区、完成新的确定性减量后，对上次“确实生成过摘要但候选未缩小、未采用”的相同 checkpoint、旧前缀终点、有效策略、模型与摘要输出额度跳过重复摘要生成。必须基于实际选区，不能仅凭整个历史末序号判断。不能只判断 `outcome=not_smaller`：同轮减量有效、摘要未采用时，现有界面结果可能为 `trimmed`，同样应记录这次无收益生成。

该记录可以只保存在当前进程的 ContextService 会话状态中：重启后允许重新尝试一次；不为它增加持久 schema、hash、通用缓存或版本系统。新的切点、有效策略 / 模型变化、成功替换后重新评估；显式手动请求允许再试。实际代码应复用一个选区函数，避免预判与执行各写一套算法。

去重只减少无收益模型调用，不跳过新工具减量，不阻断正常请求，不把“省不到某个比例”定义成失败。若必须材料超过模型实际可用容量，沿现有错误说明主要占用来源，不重复压相同摘要。

## 9. 用户与模型怎样使用

- 用户继续从输入区打开上下文、历史与记忆面板；不新增常驻顶部区域。
- 上下文面板区分上次实际输入、下次估计、历史与固定材料、同快照前后减量、摘要维护费用。未知用量保持未知；不把一组接近的数字宣传成估算准确率。
- 摘要、来源、历史查询、匹配列表和单条调用 / 结果均可关闭或折叠；后台变化不重开详情。
- 模型仍用 `get_context_status / compact_context / read_history`，无需先看状态才准执行任务。搜索 → 命中片段 → 精确展开是建议使用路径，不是强制流程。
- 正常工作不需要用户逐项确认摘要、引用、记忆或近期材料。记忆设置与用户显式保存 / 纠正行为保持既有规则。

稳定指令与动态参考材料的职责要清楚，但本轮不为缓存重排全部 system 消息、冻结任务修订或改变原生 reasoning 续接。当前请求材料的真实性优先于未经测量的缓存收益。

## 10. 实施落点与最小验收

| 顺序 | 改动 | 主要位置 | 直接验证 |
| --- | --- | --- | --- |
| A | 摘要每条输入带来源、精简软结构提示 | `context/service.py` | 实际摘要输入含真实来源；不增加工具执行或第二次摘要 |
| B | 查询命中正文、准确偏移、计数单位、调用 / 结果关联 | `context/store.py`、`types.py`、`tools.py` | 中段命中可见；中文 / Unicode 偏移准确；配对来源无串 Run |
| C | 历史片段与详情交互 | `ContextMemory.tsx`、生成协议 | 从命中继续读取不跳页；从头看 / 折叠可用；末尾片段不伪装全文 |
| D | 同前缀无收益去重、统一摘要有效额度 | `context/service.py`，必要的小型选区函数 | 新尾部不触发相同摘要；前缀变化可重新生成；新减量照常；输出预留一致 |

实施时同步将集中配置的新会话自动起点改为 800000，并更新生成协议中的默认值和相关说明；已有会话设置保持，不把此前 128K 样本验收当作 800K 长输入质量验收。无需为了更改初值立即构造 800K 真实请求，后续正常使用有具体问题再定向核查。

新增 DTO 字段给出默认值，沿 Pydantic → schema → TypeScript 生成，保留旧会话和 checkpoint；不手改生成物。若文案只需解释事件类型，不另造新的持久分类。

复用 `tests/python/test_context_memory.py` 和既有桌面 / 模型入口，仅新增或扩展直接覆盖变化的场景：

1. 长输出中段有关键错误；关键词返回真实命中片段，模型可从来源连续展开。
2. 调用、结果不同序号，能互相定位；没有结果的旧调用仍能读取。
3. 用户纠正、已结束 Goal 和当前任务在连续压缩后不会被旧摘要重新覆盖；原日志保持。
4. 上次无收益、新增仅在近期区时不重复生成；同时覆盖减量成功但摘要未采用的组合；实际前缀增长时允许生成，手动请求不被屏蔽。
5. 显式较小摘要输出额度与输入预留一致，UI 区分实际 / 估计与片段 / 全文。

真实模型接续复用隔离样本，使用已有授权与显式请求 / 时间预算，不发送私人历史。重点看事实正确性、是否重复工作、来源回读次数、总请求 token 与延迟；不新增模型评委、常驻评测系统或全量回归门槛。本次双模型各 3 次请求的验收已通过，详细结果与语义限制见进度；未构造 800K 真实请求。
