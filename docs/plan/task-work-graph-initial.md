# 任务工作图与流程接续：初次实现

日期：2026-10-19。用户已授权按讨论结果初步实施；本批属于 M5 增量。

## 归属与范围

工作流保存阶段 / 依赖 / 反馈骨架，团队配置保存角色，任务持有具体工作图与模板快照，项目聚合任务。节点是完整 Agent 工作单元，复用已有会话、工作报告、协作和持续执行服务。Loop Engineering 表达选工作、执行、接收反馈、记录并接续；不等同于 Goal 按钮，也不另造循环运行时。

本批交付：从任务流程生成可编辑工作骨架；任务级保存标题、范围、阶段、依赖、反馈和负责人；团队 / 工作两个视角；节点单次执行和选定工作范围的持续推进；节点关联真实运行、结果及历次尝试；模型领取 / 反馈时关联阶段 Skill；原任务与模板保持可读。

用户维护的工作定义与模型进度分开保存。模型可通过已有报告提出新增工作；不覆盖用户维护的目标和工作定义。图未填完、依赖缺失、反馈成环不成为普通聊天的前置门槛。模板修改不自动改已有任务，生成骨架不自动执行或创建会话。

持续执行由用户选择节点范围及补充目标后启动，既有成员负责协调与委派，宿主复用原执行及失败语义。测试未通过先报告，只有授权包含修复才反馈接续；真实故障停止受影响 Run / Goal。节点完成是工作报告事实，Run 完成不自动等于工作完成。历史来自既有任务版本和空间消息 / 轮次，不另存一套 Trace。

## 实施与验收

1. 扩展任务工作定义、反馈边和执行关联，提供工作图读取、骨架预览、保存和启动接口。
2. 在同一任务空间提供工作图、节点编辑与执行入口，保留团队视角；执行状态和历史引用原记录。
3. 定向验证模板快照、保存 / 重启、节点阶段材料、单次与持续执行、反馈结果、真实故障 / 停止、旧任务兼容。使用 FakeModel 和隔离 Electron 数据根；不调用真实模型或扩大全仓回归。

本批不引入通用 DSL、图形脚本编辑器、项目级总调度、自动创建正式会话、默认并行工具或新依赖。项目默认团队 / 流程继承继续留待后续。已有未提交修改保留，不提交或推送。

## 初版落地说明

本批已在 M5 工作区实现，具体证据见 [阶段进度](../progress/m5.md)。桌面入口为任务概览中的合作空间「工作视角」；没有空间时可显式复用首会话。模板使用已有阶段 / 依赖 / 反馈定义生成骨架，任务单独保存具体节点；暂不提供任意任务图另存为独立图模板。

工作定义与报告进度分别保存。后台进度不使未冲突的图草稿失效；成员分配与结果的时间分开，避免更换负责人回滚新结果。启动选定节点及后续领取节点会绑定该会话的阶段，让下一请求使用对应 Skill。单次工作使用既有 Run，持续工作使用现有 Goal；停止 / 失败后仍可明确接续原轮次，图和模板不形成第二个执行循环。

图的分行排布、依赖 / 反馈连线只表达关系，阶段与结果不形成强制审批。一次选多个节点时，历史关联整次执行范围，不能据此推断每个工具属于哪个节点。初版通过隔离服务链路与真实 Electron 检查，未调用真实模型评估自主规划 / 委派质量。
