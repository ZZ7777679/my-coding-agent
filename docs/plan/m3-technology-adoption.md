# M3 技术吸收：把前期调研变成可用能力

> 日期：2026-09-18。状态：方案修订，未实施。用户希望结合前期 coding agent 调研尝试新技术；本文说明哪些进入 M3、以什么粒度进入，以及与论文完整方法的差别。
>
> 入口：[M3 总体方案](m3-implementation-plan.md)。相关专题：[记忆](../research/01-memory.md)、[自演化](../research/03-self-evolution.md)、[工作流](../research/04-workflows.md)、[Harness](../research/06-harness.md)、[上下文工程](../research/08-context-engineering.md)。

## 1. 为什么需要调整上一版

上一版已经覆盖保存、恢复、摘要和协作生命周期，但算法层偏保守：记忆主要是文本条目与词法查找；压缩主要是历史减量；子任务没有明确继承上下文的选择。这样可以搭起基础，却没有充分体现用户希望探索记忆、上下文和 Agent 工作组织的目标。

本次保留三个核心模块和现有运行时，补充 **分层读取、记忆语义整理、时间与关联、增量经验手册、按角色组装子上下文**。在 M3 内交付可关闭的关联记忆和知识页实验；不是只写未来接口或换一批框架名称。

本文“采用”均指设计决定，实际效果仍未验证。借鉴某个机制不等于复现完整论文，尤其不能把公开实验的准确率、延迟或 token 改善直接写成本项目收益。

最显著的范围调整是：**“暂不引入图数据库”不再被误读成“不做记忆关联”；“不自动演化 skill”也不等于“不能积累改进做事方式的经验”。**

## 3. 上下文：从一段摘要升级为可展开的材料

### 3.1 分层读取

OpenViking 将内容与索引分开，使用 L0 / L1 / L2 渐进装载，并对历史和记忆做派生处理。这里借鉴信息层级，不接入其服务、URI 协议或向量基础设施。[官方架构](https://github.com/volcengine/OpenViking/blob/main/docs/en/concepts/01-architecture.md)

本项目的对应关系：

| 层级 | 材料形状 | 谁产生 |
| --- | --- | --- |
| L0 短索引 | 标题、类型、范围、来源、大小、是否有概览 | 宿主已有元数据，通常无新增模型调用 |
| L1 概览 | 一段历史、主题或任务结果的必要摘要 | 复用 checkpoint / 工作报告；需要时由现有整理作业生成 |
| L2 正文 | 原始事件、记忆条目、文件或归档输出的选定片段 | 原始存储与现有读取工具 |

不是每个小文件都生成三份文本，不在每次打开项目时遍历仓库并让模型总结。L1 缺失时直接读 L2；过期概览只影响该材料的使用，不阻止会话执行。

组装入口按当前问题选材料、再选择粒度。用户最新要求和完整工具交互仍优先，不能为了平均分配 L0 / L1 / L2 配额挤掉关键输入。

### 3.2 大材料在外部处理

RLM 的完整方法把大输入放进外部环境，允许程序访问及递归模型子调用；本项目仅先吸收外部输入访问部分。[论文 v3](https://arxiv.org/abs/2512.24601v3)

归档工具增加搜索、范围读取、可解析记录的字段筛选 / 计数。对日志先找 run ID 或关键词，再读命中附近内容；统计由本地代码完成，不要求模型数几万行文本。普通命令执行仍走现有程序工具，不为此向模型开放应用内部任意 Python 执行或复制一套 REPL。

这可直接复用 A 批回读工作，不宣称已经实现完整 RLM 或百万 token 推理。更深的递归分析只在现有子 agent 能力与预算下明确委派。

## 4. 记忆：可理解、可更新、可关联

### 4.1 写入时消除对旧聊天的依赖

SimpleMem v3 的关键机制包括独立事实单元、写入时语义合成与意图感知多路检索；它实际包含稠密、词法、结构索引。本项目借鉴表示和增量合成，不把自己的无向量实现称为完整 SimpleMem。[论文 v3](https://arxiv.org/html/2601.02553v3)

例如“以后仍然用刚才那个路径”，整理后应成为“当前项目的开发数据根使用已确认的配置项；具体值见本机配置”，而不是丢失项目范围的一句“默认放某盘”。指代或日期不能确定时保留原范围与不确定性，不让模型编一个精确事实。

一次提取可同时发现新增、重复、替代与暂时信息。重复内容不反复新增；临时安排留在任务层；明确长期变化建立替代关系。沿现有工作边界批处理，不照搬论文的在线写入时序使每个前台请求多等一次模型。

### 4.2 时间与弱关联

时间设计参考前期 [Graphiti 分析](../research/01-memory.md)：写入时间由宿主记录，事实适用时间只在材料确实给出时保存。当前查询优先有效条目，历史查询可找到旧决定及其替代原因；不是按最后写入时间抹掉所有旧事实。

A-MEM 将新笔记与已有笔记关联，并允许更新派生解释。M3 的实验版本只做轻量连接，保留原条目及来源，不默认部署它的向量近邻和完整演化流程。[论文 v11](https://arxiv.org/html/2502.12110v11)

关联采用 `related_ids` 加可选说明；表示“可能相关”，不自动表示因果或依赖。候选从同主题、路径、任务和检索命中中选择，不两两扫描整个库。现有整理请求可以一并提出连接，不额外为每对条目发请求。

查询先命中直接证据，再按剩余预算展开少量邻接条目；没有连接不影响正常检索。关联功能关闭时不使用 / 生成模型关联，原条目和明确替代关系仍保留。实验页可以查看和移除连接。

### 4.3 词法、结构与关系共同召回

Hindsight 的官方实现组合语义、关键词、图和时间召回，再合并与重排；这说明不同检索路径解决不同遗漏。[官方实现说明](https://github.com/vectorize-io/hindsight)

本项目先做三条本地路径：关键词 / 标识符命中；项目、主体、路径、时间等已知条件；明确关系及启用实验后的弱关联。合并按 ID 去重，当前问题决定先后与展开深度。不固定所有查询都必须 top-k 或另调一个模型规划检索。

问题较复杂时，主 Agent 可在现有循环中明确改写查询或分解查找；不在用户每次发送后插入隐藏的分类模型。词法 + 结构 + 关系不等于 embedding 语义检索，跨表述召回仍有局限。

## 5. 经验手册与项目知识页

### 5.1 增量经验手册直接进入 M3

ACE 将上下文作为增量维护的 playbook，避免反复整体改写丢失细节。这里采用条目级更新，不复制其训练、完整多角色循环或实验得分。[论文 v3](https://arxiv.org/abs/2510.04618v3)、[实现](https://github.com/ace-agent/ace)

经验条目表达“什么场景、怎么处理、何时不适用、来自什么结果”，正文仍可自由编辑，缺少可选字段不拦保存。通过既有 Agent 或空闲整理新增 / 修订某几条，而不是每次重写整个项目手册。

例如“本仓库修改协议时先改 Python DTO，再走生成入口”是可检索的操作经验；它不能扩大为“永远不允许编辑 TypeScript”。用户可标记有用 / 误用、修订或停用；计数只辅助查找问题，不成为工具准入评分。

M3 不自动修改 AGENTS.md、执行器或正式 skill。知识对当前任务有帮助时作为上下文使用；将经验正式导出为 skill 的动作保留为后续明确需求，不依赖一个持续运行的优化器。

### 5.2 知识页作为可选实验

Hindsight 的 knowledge pages / mental models 和前期 LLM Wiki 调研都强调把重复综合结果保存成可读材料。读取已生成页面可避免每次重新总结；更新成本仍存在。[Hindsight](https://github.com/vectorize-io/hindsight)、[前期 Wiki 分析](../research/01-memory.md)

M3 允许按主题维护少量派生页，例如“项目启动与目录约定”“某接口的重要决定”。页面保存在应用数据根，引用记忆 / 事件 / 产物；不开启全仓自动 Wiki，不要求 Git 和 PR。

用户可手动“整理为知识页”；自动维护是默认关闭的项目实验。开启后只刷新受新增内容影响的主题，复用维护作业的调度和预算。页面缺失 / 过期时可直接回查来源；正文和资料仍能使用，前台不等后台生成。

忘记某条记忆时，立即移除依赖它的页面缓存并停止自动注入旧页，稍后从剩余来源重建；不是必须等模型“证明已忘记”才能继续。用户独立手写的页面保留用户所有权，不由后台整页覆盖。

## 6. 协作：上下文按工作性质选择

Deep Agents 当前文档区分默认 isolated 与继承父历史的 fork；fork 仍有版本与 beta 限制。本项目自行实现这两种输入语义，复用自己的日志，不增加 Deep Agents 依赖。[官方文档](https://docs.langchain.com/oss/python/deepagents/subagents)

- **独立输入**：检索、独立 Review、独立模块任务。只带共同事实、分工和所需材料，避免继承主会话的全部猜测。
- **继承输入**：接续已经完成的诊断或整理调查结果。固定父会话已完成前缀 / 有效 checkpoint 和尾部，再附具体子目标。

继承的是上下文，不是文件副本、父 Goal 控制权或旧工具的执行权限。不能重放父工具，不能让孩子同时继续父会话未完成的顶层请求；在途的委派工具调用不作为半截交互复制进去。

用户已有会话不能被一次 fork 覆盖历史：handoff 给它的是可引用的来源快照。内部 worker 才从选择的上下文方式启动。两个方式都沿原角色、预算、停止规则运行。

SWE-grep 的专用训练和推理基础设施不是本项目凭一个提示就能复制的速度。可迁移的是检索角色、独立探索及文件位置结果。[Cognition 工程说明](https://cognition.com/blog/swe-grep)

子 agent 开启时，检索 worker 可探索互不依赖的位置，返回文件、行 / 符号、相关原因和未找到部分；主会话只读取需要的原文。不开启时主 Agent 使用同样的检索 / 材料工具，不为了此角色绕过总开关。

## 7. 本轮不直接引入什么

| 技术 | 当前判断 | 何时再考虑 |
| --- | --- | --- |
| GraphRAG 全库实体 / 社区图、完整 Graphiti 服务 | 先做轻量关系和时间，不部署图基础设施 | 多跳 / 跨项目关系成为明确需求 |
| SAGE / MemGate 完整算法 | 可以吸收避免重复与按相关性使用的目的；不把简单阈值伪称密度模型或训练门控 | 有合适嵌入、训练数据与实际检索瓶颈 |
| GEPA / gskill、DSPy Flex、Agent Lightning、RSI | M3 的经验更新不是优化器或训练；本轮不安排批量任务搜索 / 参数学习 | 用户明确进入 skill / harness 优化阶段 |
| 完整递归 RLM | 先做材料读取与受现有预算管理的 worker | 确实需要多层语义拆解且基础调度已验证 |
| 默认语义向量索引 | 不为本轮增加模型下载、embedding provider 或 API key | 少量实际查询显示词法 / 结构 / 关系召回不足后，再单独选型 |
| LangGraph / ADK / Temporal 全栈替换 | 现有 Goal、队列和任务记录能承接本轮功能 | 明确缺少某个运行能力时按缺口评估 |

这些是当前选择，不是永久禁止。技术的引入单位是具体能力与代价；没有现成向量库，也可以实现有意义的关联记忆与分层上下文。

## 8. M3 内怎样试用并判断效果

基础功能进入既有 A–D 批；关联记忆、知识页自动维护在 C 批交付可用开关和界面。实验默认关闭是为了允许比较，不能以“实验”名义只交空接口。

| 小场景 | 验证什么 | 记录什么 |
| --- | --- | --- |
| 日志仅一处相关 | L0 找材料，局部过滤 / 回读，不把全部日志发给模型 | 实际输入量、回读次数、是否找到原文 |
| 偏好从旧方案改为新方案 | 记忆独立可理解；当前 / 历史问题找到不同状态 | 是否误用旧决定、使用条目 ID |
| 两次不同描述指向同一问题 | 开 / 关关联后是否更容易找到相关经验 | 命中来源、额外模型请求与等待 |
| 已诊断问题交给 worker | 独立输入与继承输入是否减少重复探索 | 已读文件重复数、输入量、实际结果 |
| 两个相关经验形成知识页 | 页面能复用，删去来源后不再注入旧页 | 维护请求数、后续读取量、删除传播 |

这些检查复用简单任务和隔离材料，可用快照与可控响应验证结构；只有确需比较模型效果时才执行小量真实请求。不新增独立评测平台，不把每个日常任务变成回归。

比较保持模型与问题相同，区分“这次找到材料”与“已证明普遍更快”。无收益时关闭相应实验，基础压缩、记忆、协作继续可用；关闭不删除原始历史或普通条目。
