## 1. 阶段目标与取舍

| 优先级 | 模块 | 用户能直接感受到的结果 |
| --- | --- | --- |
| P0 | 执行正确性与故障接续 | 区分模型仍在生成、客户端处理、程序已结束但记录未保存等情况；保存与切换问题有具体处理结果 |

| P2，接在材料优化之后 | 可选后台压缩 | 长会话在容量允许时边工作边整理，摘要在下一请求采用 |

## 3. 模块 A：执行正确性与故障接续

### A1. 先定位已知保存问题

沿现有操作身份和事件核对“界面发起 → RPC 接纳 → 业务写入 → 响应 / 事件 → 界面展示”，避免新增另一套操作日志。优先读取已有失败 trace 和程序错误记录；只有现有记录缺少关键环节时才补最小关联字段。

- 工作图保存：确认用户修改是否接纳、版本是否变化、保存回调是否被切页 / 迟到响应覆盖；失败保留草稿，区分未接纳和保存结果未知。
- 程序收尾：区分程序实际退出结果与终态落盘结果；保存失败不能将真实退出描述成“程序没有执行”。保留已有输出、原因及相关程序身份。
- 如需要“重新保存已知结果”入口，只补写已经取得的结果，不重新运行程序 / 工具；明确结果未知时先读取现状。
- 没有根因证据的项目继续标为待观察。保存路径真实失败继续沿产品故障语义处理，不吞错或伪造成功。

### A2. 长响应与跨模型接续

利用既有 ModelProgress / 请求身份补齐可解释计时：本地装配、发起到响应头、第一段思考、第一段正文、工具参数完成及客户端回调 / 持久化处理。没有观测的数据标为未知，不能把“尚无正文”一律叫网络失败，也不能把收包叫任务进展。

用同一隔离小任务核对 GLM 与 DeepSeek，不把自然波动当作本地性能改进。仅修证据指向的阻塞、重复注入或协议问题；不自动换模型、重试、改变 VPN 或把超时无限放大。

跨模型切换在请求投影处核对原生字段：保留历史供展示，同模型工具续接所需数据不随意删除；只有确认与目标模型不兼容的字段才适配。已发送请求保持原模型，下一请求采用已保存选择。不能为切换清空用户历史或把旧思考改写成新的用户指令。

### A3. 补清能力与结果入口

在现有上下文 / Trace / 资源面板中明确区分：本次模型工具、可发现但未加载工具、桌面管理入口、项目未配置以及尚未实现能力。不再增加一张固定工具数量清单，不把这些说明放成输入框上方的常驻大卡片。

针对本阶段协作场景，在现有 Trace 中增加“打开目标 Run / 返回发起记录”的关联入口；运行时间、父级等待和并发用量分别表达，按请求身份去重汇总。历史缺来源时显示未知，不反查最新消息冒充原结果，不建设全局观测平台。

## 4. 模块 B：请求装配与协作材料

### B1. 一条装配路径、一份实际材料记录

复用 [runtime/loop.py](../../src/my_agent/runtime/loop.py)、[ContextService](../../src/my_agent/context/service.py)、[成员简报](../../src/my_agent/spaces/context.py) 与现有材料清单。统一核对系统规则、项目规范、Skill、工具定义、任务事实、成员简报、记忆、摘要与近期消息的来源，避免增加第二条上下文注入路径。

先以同一输入记录优化前材料，再做以下减量：

1. 同一事实从任务状态、成员简报和历史投影进入多次时，明确其当前权威来源，避免重复全文。
2. 当前成员保留目标、用户确认的约束、职责与相关协作关系。自身工作、直接依赖 / 反馈结果带入短简报；其他节点提供目录与读取入口，不默认携带全部结果正文。
3. 已完成工作的长输出继续使用现有摘要 / 归档；新工具结果、未完成工具配对和最新用户纠正不能为省 token 被切掉。
4. 有效项目规范和当前 Skill 正文仍按原规则进入请求；稳定规则与动态进度在协议允许的位置分开组织，不能靠降低规则优先级换缓存。
5. 长期记忆仍由现有召回 / 纠错服务负责。临时 Review 结论和任务待办不因此变成永久偏好；不新增成员记忆库或记忆算法。

“来源去重”不是禁止模型在摘要中自然提及目标，不为文字相似度引入打分或阻断条件。角色相关性优先使用已有成员 / 工作身份与关系，不额外用一次模型请求筛选每轮上下文。

### B2. 展示真实收益与代价

上下文面板保留可关闭和各节折叠，按材料类别说明来源、带入原因、全文 / 摘要 / 引用及读取方式。服务返回的总输入 token 是实际计量；各部分为估算时明确标注，不能把估算占比包装成服务端精确拆分。

对比同一任务的输入估算、真实 usage、缓存命中（仅服务明确报告时）、首字、回读次数和任务结果。减少 token 却增加多轮工具发现 / 回读，不直接判定优化成功；没有证据就保留原策略，不设机械的压缩百分比验收门槛。

低频内置工具渐进加载只作本批后段的定向试验。MCP 已具备发现机制；此前缩工具菜单未得到稳定收益，因此不默认隐藏全部工具，也不把安装数量当成本次实际输入数量。

## 5. 模块 C：保存与复用个人工作方式

### C1. 数据关系

继续保持三层分工：**工作方式模板提供蓝图，项目保存默认选择，任务保存具体实例和运行历史**。实际执行图归任务，不把整个项目所有任务塞进一个共享可执行图。

| 层次 | 保存内容 | 更新规则 |
| --- | --- | --- |
| 工作方式模板 | 阶段、团队角色 / 关系、可选工作图骨架、角色 / 阶段 Skill 引用、说明与来源 | 修改只影响以后创建的实例；沿用现有模板目录和版本记录 |
| 项目默认 | 默认模板身份及本机资源映射 | 保存在应用数据根；只影响新任务，打开项目不向项目写文件 |
| 任务实例 | 创建时快照、任务范围、实际成员 / 会话绑定、工作定义 | 用户可单独调整；模板更新不覆盖该任务 |
| 执行事实 | Run / Goal / 协作身份、结果、等待、修改与 Trace | 继续由现有服务保存，不进入可分享模板 |

选择顺序建议为：创建任务时显式选择 → 项目默认 → 现有个人默认流程。允许只选简单流程、不要团队或工作图，不增加“先配置合作空间”门槛。

### C2. 首版内容与桌面入口

- 左侧保留「工作流管理」，加入“工作方式”组合编辑与预览，不另建插件市场。
- 在任务合作空间提供“保存为工作方式”：选择阶段、角色 / 关系、工作骨架与 Skill，剥离当前会话 / Run 身份、运行状态、产物、绝对机器路径和凭据。
- 模板角色使用逻辑身份，应用到新任务时映射为该任务成员；不把某个旧成员的 UUID 或旧会话复制进新任务。
- 新建任务可预览组合并修改；创建任务按现有约定建立首会话。其他正式成员会话由用户使用已有组建 / 绑定入口创建；套模板本身不自动开跑，也不扩大子 agent 开关。
- 项目设置可选默认工作方式；已有任务有显式套用 / 更新入口，预览配置差异，保留原历史和已完成结果。
- 模板中的 Skill 保存稳定引用与来源信息，实际解析版本在任务 / 请求材料中可查；项目、用户、内置覆盖规则保持一致，不再复制一套 Skill 正文数据库。
- 首版 JSON 导入 / 导出用于配置蓝图和资源声明。缺少 Skill 时显示对应来源并复用已有导入入口；纯 JSON 不宣称含完整资源。可跳过缺失资源，普通任务仍能使用。携带所有资源的离线包另行安排。

技术上优先扩展 [WorkflowTemplate](../../src/my_agent/workflow/templates.py)，复用现有团队配置类型和 [模板存储](../../src/my_agent/spaces/team_store.py)；旧流程、独立团队模板都继续可读。跨文件创建失败保留已经成功的任务与明确补齐入口，沿用 operation_id，不包装成并不存在的跨文件事务。

### C3. Loop / Graph 如何落地

Graph 表达工作单元、依赖、反馈和角色关系；节点仍由完整会话 / worker 承担。Loop 表达根据结果选择下一步、委派、等待、汇总、在已授权范围内返修。现有 Run / Goal 负责实际推进，不新建通用 DAG 运行时。

首个可复用例子是“实现 → 用户启动独立 Review → 汇总 → 按明确授权返修”。需要全程连续推进时，用户可在启动目标中明确包含相关工作；只选模板不等于授权执行所有阶段。依赖和反馈用于建议、导航和接续，未填写报告或图有反馈环不阻断普通任务。

普通对话回答后返回用户；持续模式才连续工作。测试正常执行但未通过时按现有授权决定是否修复，真实故障停止受影响 Run / Goal。一个工作节点或局部 Goal 完成不自动结束整个任务。

## 6. 模块 D：可选后台压缩

放在材料优化之后，作为本阶段有条件增强：若用户仍需要减少长会话整理停顿，且小样本能验证尾部保留与取消边界，再交付可选模式。首版不默认替换当前同步自动压缩。

建议行为：

1. 继续使用默认 800K 自动点及已有绝对 token 配置，不新增写死的 128K 起点或近期保留百分比。
2. 达到触发点先做已有工具结果减量；仍需摘要时固定完整交互切点 N，使用旧前缀快照启动摘要。
3. 当前材料加输出预留仍在窗口内时，前台可继续；新事实追加在 N 后，不进入正在生成的旧快照。
4. 摘要完成后在下一请求边界采用“摘要＋N 后完整尾部”。不得修改在途请求；通过现有作业身份、切点与来源处理重叠整理，不增加 hash 或模型证明表。
5. 接近实际容量且尚无可用摘要时，显示正在等待整理；不能为“无阻塞”发送已知超窗请求。服务端未报告精确输入时继续区分估算与真实用量。
6. 背景整理的停止、失败、已准备和已采用可在现有面板查看。作为独立维护作业，失败保留历史，容量允许时前台可继续；主模型 / 执行 / 保存故障仍沿既有规则停止。此条是拟议的维护语义，实施时同步相关守则与方案，不悄悄改现有规则。
7. 摘要请求有真实费用和并发成本，沿现有归属与预算计入，按请求去重；没有第二份隐形预算。用户停止 / 退出后不自动重发，重启只恢复已有结果和状态。

800K 的真实效果需要专门样本，先验证小切点只证明算法和生命周期正确，不宣称百万 token 验收通过。没有测得等待收益时，不把后台模式推广为默认。

## 7. 交付顺序与最小验证

| 批次 | 内容 | 交付 / 验证 |
| --- | --- | --- |
| A | 保存问题定位、长响应与模型切换核实、必要的状态修正 | 两个偶发观察分别给出根因修复或证据缺口；一项短工具任务核对时序和切换；不循环追逐无法复现问题 |
| B | 上下文来源整理、相关成员简报、材料可视化 | 同一任务前后材料对照；新约束、纠正、工具配对和结果回读保留；不凭估算保证提速 |
| C | 工作方式模板、任务快照、项目默认、跨运行导航 | 从已有任务另存模板，套到新任务；编辑旧模板不改新旧任务快照；跨会话来源能往返查看 |
| D | 可选后台压缩 | 新尾部、停止、失败、模型切换、重复整理归属及真实计量；不重做压缩算法 |
| E | 小场景联合体验与增量收尾 | 使用下方例子，审阅本阶段差异、过度约束、协议 / 注释 / 提示词一致性，记录剩余限制 |

A、B、C 是建议核心交付；D 可独立暂停，不作为 A–C 使用前提。B 与 C 设计可以分别推进，实现仍按实际工作量拆批。每批带桌面入口，不等后端全部完成再接前端。

联合场景沿用**空白项目单页计数器**：保存一个实现 / Review 工作方式 → 新任务套用 → 实现计数器并按需用浏览器点击 → 用户启动 Review → 明确授权修改一个问题 → 查看来源 / Trace → 重启后从已有结果接续 → 第二个任务复用同模板。无需把沙箱、发布、数据库等所有未做模块塞进例子。

上下文验证另用短隔离历史触发小切点，检查用户最后纠正、已完成操作和新增尾部是否保留。阈值只改隔离样本，不改用户 800K 默认。真实大窗口测试单列可选实验。

复用现有 `tests/`，只补明确行为变化和关键风险；产物归 `.artifacts/tests/`。真实模型用隔离样本、小批执行并记录请求 / 时间 / 成果；具体预算在实施相应批次前明确，不写入产品上限。本轮规划不消耗额度，也不自动取得个人 OAuth 授权。
