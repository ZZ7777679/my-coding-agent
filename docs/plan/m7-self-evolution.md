## 1. 阶段目标与已确定方向

### 2026-10-20 审查后的流程修订

默认路径调整为「选择证据与问题 → 只读调查 → 展示发现、未知项及相关资源 → 生成多个候选 → 分别编辑、采用、比较或恢复」。无需预先指定工具或 Skill；用户仍可通过指定资源入口直接提出修改。借鉴 Hermes 的资源目录与按需阅读，以及 GEPA 的事实反馈／候选版本比较，复用现有运行循环、资源服务和 Trace，不引入新的通用优化框架。

调查从用户选定范围的事件索引开始，支持搜索、失败筛选和分页回读；记录实际已读正文与覆盖量。整体选择不表示模型已经读完全部正文。工具补充说明与工具实际描述／schema 分开展示，使用问题与实现缺陷分开记录；缺陷可以关联所选 Harness 源码项目。来源项目和写入项目可不同，原始证据身份保留。

调查作业可独立结束并留存发现；生成阶段接受调查身份及所选问题，允许针对多个相关资源形成独立候选，也允许结论为无需修改。旧指定资源候选继续可读。自动反馈复盘返回同一作业身份，活动中相同输入复用，显式的新一轮请求不受永久去重限制。

候选比较绑定正文版本；正文变动后旧结果仍留存但不代表当前效果。自动采用记忆保留实际已读 Trace 来源。取消等待已经开始的写入和终态保存结束，不再出现停止返回后继续写入。桌面保留按项目和候选的编辑草稿，刷新元数据时不覆盖未保存文本。以上均不增加采用审批、强制测试或 hash 门槛。

真实验收后，调查通过 `submit_review` 结构化工具提交发现和提案，缺项以可修正反馈回到同一运行循环；仍兼容原最终 JSON。保存公开最终返回供按需排查，不将原生 provider 状态暴露给桌面。调查工具复用普通运行循环，预算按下述 2026-10-21 修订独立保存；首包材料预算与后续累计读取分别展示，不把首包字符数当作整个调查的硬上限。源码候选保留模型同一次文件阅读的基线，外部编辑不会在生成结束时被重新取成“原版”。

### 2026-10-21：改进预算独立设置

「经验与改进 → 新建改进 → 改进预算」按当前项目保存请求次数、工具次数、总运行秒数、单请求秒数和每次输出 token 上限，同时管理初始材料字符量。高级容量设置独立保存累计调查上下文／模型响应的字节预算，避免普通对话的辅助请求容量间接限制改进；文件读取规则仍复用应用设置，代码比较继续使用项目执行环境的命令限额。

调查、从发现生成多个候选、指定资源快捷生成，以及自动反馈复盘均采用项目改进预算。每次作业独立计数，多候选共用同次生成预算；预算在接纳时写入作业，修改仅影响下一次启动。旧作业未保存预算时显示未知，不根据当前设置补造历史。普通对话预算不再控制上述改进请求；旧项目缺少此配置时使用集中默认值，不修改普通对话设置。

默认请求 25 次、工具 60 次、总时限 600 秒、单请求 180 秒、每次输出 8,192 token、初始材料 48,000 字符；高级容量沿用既有默认量级，由 `defaults.json` 的 `evolution` 段统一定义。单请求时限包含完整生成，不随流式输出重置；总时限耗尽保存作业失败与调整入口。所有设置可在模块内显式保存，不增加先设置才能开始的门槛；设置本身不会触发模型请求。

每项（含高级容量与初始材料字符量）均可单独勾选“不限”。配置／作业快照使用 `null`，不是大整数：循环跳过对应次数／累计容量判断；总时限与 HTTP 请求超时停用；输出 token 不限时省略 Chat Completions 的 `max_tokens`；响应不限时不执行应用的 SSE 帧、事件与累计内容预算。初始材料不限时按已选范围完整装配，不再裁剪正文；调查仍按索引按需阅读，并不自动扩大选材范围。模型服务的真实能力、正常结束协议与用户停止仍适用。不取消其他模块的读取规则或代码实验命令限额，不修改普通对话的数值配置；已有设置不自动改为不限。

未保存的桌面草稿覆盖当前窗口内的项目／候选切换和导航；已保存记录持久化。关闭应用后的未保存草稿恢复不在本次交付承诺内。比较和真实短样例通过也不等于长期效果已被证明。

让 Harness 能根据真实使用形成可复用经验，找到适合修改的对象，提出并执行改进，展示实际效果，必要时恢复旧版本。成功任务、失败、用户纠正和手动优化目标都能成为输入，不能只从异常学习。

两条主线共同纳入本阶段：

- **工作方式改进**：个人偏好、项目规范、事实与经验记忆、Skill、工具使用策略、工作流和协作分工。
- **实现改进**：工具实现、上下文与记忆策略、运行控制、错误处理及桌面交互等 Harness 代码。

这要求贯通“运行事实 → 反馈与归因 → 修改候选 → 实际比较 → 采用／恢复 → 后续观察”。仅自动写记忆或生成建议，不能算第二条主线交付；代码修改也应最终能生效并恢复。初版不需要参数训练、新模型或完整进化搜索框架。

沿用正常开发优先、最小相关验证、免持续提权、不增加逐工具审批的要求。复盘与实验不能成为每次聊天、编辑或任务结束的前置条件。

| Harness 核心与界面 | 上下文、记忆召回、运行状态、持久化、UI 行为 | 应用代码及必要配置 | 网络连接阶段被错误显示为思考，修复事件与状态投影 |

这些对象共用一次改进记录，但继续使用各自已有服务读写，不创建包办所有业务的“万能资源引擎”。

需要保留的区别：

- **偏好不由性能评分决定**。用户明确要求可以直接按该要求保存；推测偏好不能因一次临时选择变成全局规定。
- **规范、方法与事实分别维护**。项目约束来自项目规则，步骤来自 Skill，环境事实来自记忆；避免相同正文多处复制后互相矛盾。
- **规范可改进其表达与可执行性**。模型不能为了提高分数自行删除用户已经明确的限制；用户的新要求可以更新旧要求。
- **工具描述必须符合实现**。只改文案不能新增实际参数；schema 和执行契约变化进入代码修改路径。远端 MCP 原始 schema 来自服务器，本地注释不能伪造远端能力。
- **适用范围参与召回**。一次项目兼容修复不直接推导为所有项目的工具禁令；取消或未知结果不记录为“该工具不能用”。
- **当前任务状态继续归 Task／WorkItem／会话**。不是所有短期信息都升为长期记忆。发生了修改、被加载、任务成功、有证据帮助成功，分别记录。

## 4. 支撑模块及建议实现内容

### A. 运行证据、日志与反馈

业务事件继续以现有会话／任务记录为事实来源；Trace 是查看入口。新增结构化诊断只补宿主、传输、进程、持久化等尚未保留的信息，正文与产物引用原记录。

按实际可得信息关联项目、任务、会话、Run、请求、工具调用、后台作业；宿主启动前没有会话时使用进程启动身份，旧记录未知字段保持未知。保留发生时间、阶段、耗时、组件、错误与原因引用，关联实际采用的代码／模型／Skill／工作方式版本。

内部诊断保留经过筛选的异常链和源码位置；不保存完整环境、凭据、任意局部变量或默认重复记录完整请求。日志轮转与清理集中配置，记录失败只报告诊断能力降级，不把正常任务改成失败；业务数据保存失败仍沿原规则处理。

用户可在消息、工具或 Trace 上标记“这里不对／这种方式很好／以后这样做”，直接关联对象；普通自然语言纠正仍有效。反馈不要求逐项填表，也不要求所有任务必须评分。

### B. 统一异常与结果语义

复用 `AgentError` 和现有事件，逐入口补充结构化阶段、底层原因与影响范围。统一的是事实表达和边界转换，不把所有情况变成同一种异常或一套通用恢复算法。

| 情况 | 对运行的既有含义 | 对学习的含义 |
| --- | --- | --- |
| 参数缺项、原文不唯一、未写入的局部冲突 | 反馈模型选择下一步 | 参数／描述／使用策略问题候选 |
| 测试正常执行但未通过 | 报告；修复取决于当前任务范围 | 业务结果，不能默认归为工具故障 |
| DNS／连接／认证／流读取故障 | 停止受影响 Run／Goal，保留真实阶段 | 外部条件与实现问题分别调查 |
| 实际执行、保存故障 | 按现有规则停止并清理 | 记录最后完成动作及未知副作用 |
| 用户取消／预算到达 | 明确中止原因 | 不能据此证明能力缺失 |
| 独立记忆、压缩或自进化作业失败 | 只结束对应维护作业，按现有容量条件继续前台 | 保留维护失败，不重新标记前台成功为失败 |

原因尚未确定时明确“观察”与“假设”。底层重试能力不等于产品自动重试授权；统一错误不引入故障后自动重放有副作用的操作。

### C. 记忆成为经验的承载与接续层

优先扩展现有条目、修订、来源、替代与失效逻辑：

- 事实、明确偏好、解决过程与尚待验证的假设可区分；保留触发条件、相关工具／环境／资源版本。
- 纠正可落到具体条目，新旧关系可查看，冲突和过期内容不继续当作确定结论召回；有效对话分支与来源失效继续沿 M6 处理。
- 召回显示匹配原因、适用范围、当前版本和实际使用位置；避免每次加入整份复盘日志。
- 建立“经验 → Skill／项目规范／工具改进”的关联，用户能看清这条经验后来改变了什么。
- 对同义表述、跨语言检索和长期扫描成本做小样本比较；按结果决定是否补本地索引或混合检索。暂不预先绑定向量数据库、额外云服务或大型本地模型。

记忆更新成功不等于能力改善；明确偏好的保存无需性能实验，自动提炼的通用方法则需要后续使用证据。

### D. 轻量复盘与改进候选

在任务结束、用户反馈或用户手动发起时读取相关事件；也可以分析一次成功任务的可复用方法。何时自动运行及读取范围仍待确定，不默认扫描全部私人历史。

一次候选至少表达：改进目标、目标资源、依据、原版本、实际差异、预期作用及比较结果。使用已有 Task／Run／Goal 或维护作业生命周期，不让每条反馈自动产生正式会话或多 Agent。

归因后选择合适路径：记忆纠正、项目规范更新、Skill 更新、工具说明更新、流程模板调整或代码修复。多个目标可组成用户授权的改进任务，但比较时保留各项关联，避免同时改变模型、预算和代码后只宣称“自进化有效”。

候选之间有冲突时处理具体目标，正常开发继续。模型的“我觉得改善了”是分析材料，不能充当实际验证。

### E. 比较、采用与恢复

不同对象使用不同证据，避免机械的一刀切：

- 明确偏好／规范修改：检查表达、范围与实际装配；无需为了记录用户习惯跑代码测试。
- Skill／工具描述：用触发问题和一两个相关正常场景，观察错误调用、重复工作、输入量、耗时及用户体验。
- Tool／Harness 代码：复用直接覆盖改动的检查；UI 问题需要实际界面验证，不能仅靠 Python 测试。
- 同一比较记录真实模型、配置、环境与成本；无法固定外部服务时标出差异，单次样本不宣称稳定统计提升。
- 明确区分“已修复这个案例”“对相似任务更好”“尚无证据”。样本不足不阻断普通开发。

资源采用后显示何时生效；已发出的请求保留原材料，新请求按现有资源刷新机制采用新内容，Trace 保留实际版本。工作流模板仍不静默改写已有任务快照。

代码改进必须覆盖运行版本切换与恢复：候选在独立实验目录／数据根启动，应用仍可用于正常开发；验证通过后按选定策略采用并在合适边界重启。恢复代码不等于恢复持久化数据，涉及数据结构时须记录兼容性和必要备份；启动失败应由未被本次候选替换的启动入口恢复已知可用版本。

上述实验目录只用于自改比较，不改变普通项目默认使用原目录的选择；不要求项目连接 Git 远端。自动采用到什么程度仍待用户决定，不在讨论稿中增加逐步审批。

### F. 桌面上的自进化入口

建议左侧集中入口，复用已有详情与 Trace：

- **经验与记忆**：查询偏好、项目事实、经验、来源、纠正与使用记录。
- **问题与反馈**：查看归并问题、具体实例、原始 Trace 和当前处理状态。
- **改进记录**：查看修改对象、差异、比较结果、当前采用版本、生效状态与恢复入口。

现有 Skill、工作方式管理继续保留，允许从改进记录跳转，不新造另一份相同资源编辑器。主对话只放简短状态及入口；记录和列表可折叠／关闭。

当前入口统一为左侧「经验与改进」：首屏先提供问题输入与醒目的「开始改进」，无需先保存反馈、选择 Trace 或指定资源。会话／Trace／诊断选材仍可追加；补充说明和反馈存档折叠。启动后原位置显示状态与「查看本次改进进度」，查看同一作业不重复发起；改写输入或显式重新发起可开始新作业。默认调查后由用户选择发现生成关联候选，已指定资源时直接生成定向候选。未选择项目时提供进入项目选择的按钮。

证据查看统一使用视窗内的可关闭浮层：材料预览、作业实际材料、候选来源、实验详情和原始 Trace 不再追加到长页面。浮层内按需读取，加载、失败与重读就地显示；关闭按钮保持可见，Esc 关闭并返回原入口和页面位置。材料内部可进入原始 Trace，再返回原有材料展开与阅读位置。选材不因打开、关闭或定位而改变；窄窗口同样采用视窗内布局。候选编辑与采用仍在原页面，查看证据不丢失草稿。

## 8. 首次实施取舍（2026-10-20）

- 以“记录反馈 → 生成候选 → 对比与采用／恢复”为桌面主入口，明确目标资源与作用域。用户直接编辑可立即保存；后台发现默认保存候选，项目设置可选择资源种类的自动采用，不增加逐工具审批。代码候选默认显式采用、重启生效，后台不打断运行中的服务。
- 复盘默认使用本次选择的反馈、对应运行事实及目标资源；历史批量读取须由用户选择范围。维护任务独立计量，可停止，失败不更改原任务结论。
- 项目规范／偏好／记忆／Skill／工具使用说明／工作方式使用现有资源服务；工具说明的本地补充单独带来源，实际工具 schema 和实现改变走代码路径。
- 首版每个代码候选对应一个明确文件，保存完整建议与原内容，在独立项目／数据目录比较。多文件改进分成关联候选或继续使用现有任务，不另造多文件事务引擎。采用与恢复保存实际结果，不把恢复代码等同于数据迁移回滚。无远端 Git 依赖，不改普通任务的工作副本默认值。
- 优先标准库与现有服务，不加入 GEPA、向量库或新模型依赖。协议随公开字段实际变化升级；正常错误行为保持现有规则。
- 两条验收使用隔离样本：项目规范／Skill 经验改善及新请求实际采用；一个小型工具代码缺陷的生成、验证、应用与恢复。真实模型验收在本地链路通过后使用隔离材料，预算与实际结果单独记录。

## 9. 首版使用与实现边界

### 2026-10-21 更新：统一筛选与工作现场入口

本次用户已要求实施。以下取代早期按顺序装配正文和必须先选资源的入口描述，其他采用／恢复规则保持。

- 会话、任务、项目提供就地“复盘与改进”：继承当前范围，可补关注点后启动同一个独立作业；原位置显示状态并可进入详情或转到独立页定制。独立页保留跨项目选材、指定资源、模型和预算。日常模型提供同等入口，不创建新的正式会话。
- 后端统一解析范围、冻结来源和筛选；默认调查与定向提案共用索引及按需读取，不再在定向入口顺序填满全文。仅对明确选择的项目／任务／会话展开，界面显示范围；不存在固定时间截断或必须分析完所有材料的门槛。
- 先在本地对公开 Trace 正文检索、提取真实失败与用户反馈线索、按工具／错误／运行归组并排序，给出代表事件和前后关联。关键词及纠正提示只是检索线索，不冒充已确认原因；成功过程保留可检索入口。模型优先检查候选经历，证据不足可扩展到其他所选事件，不永久删除低排名内容。
- 推荐以可分页的问题片段展示，明确数量、排序理由和代表来源；推荐索引不计作正文已读。初始窗口只是分页默认，模型可搜索和读取完整已选范围。复盘提示明确不以提高覆盖率为目标。
- UI 分开“选中范围”“推荐经历”“实际读取”；建议支持返回独立页调整后重新发起。沿用既有草稿、作业、候选和采用服务，不新增审批、向量库、优化器或工作流 DSL。自定义预设编辑器留待实际习惯稳定后再做。
- 最小验证：重复失败归组／正文相关性／成功对照／跨会话来源不越界，定向路径不再全量读取，三类快捷入口与独立页指向同一作业，生成类型与相关桌面交互。用隔离样本，不读取个人会话。

重启 `StartAgent.cmd` 让前后端同时采用协议 v12。选定项目后，从左侧 **经验与改进** 进入：

1. 在“参考哪些记录”中先选会话，再用“选材范围”选择整个会话、指定运行（可多选）或指定事件（可多选）。运行按轮独立分页并支持全会话提问搜索，加载更早记录保留列表与选择；也可选异常诊断、已有反馈。每项明确显示范围与截止位置，来源可选，不要求先保存反馈。
2. 选择改进对象，阅读其用途并按名称筛选资源。项目规范默认 `AGENTS.md`；偏好／记忆的新身份留空；内置 Skill 会转为用户副本。填写当前要求后可“预览本次参考材料”再生成，预览不调用模型，也不是生成的强制前置条件。当前未保存的要求同样进入生成请求。
3. 打开候选查看修改前／建议内容，按需要编辑、评价并采用。设置中可打开“反馈后自动复盘”，以及按资源种类自动采用；代码始终通过明确的采用入口。Plan 模式的模型提案仅保存草稿。
4. 改进记忆时可选择事实、明确偏好、解决经验或待验证假设，在正文写明适用条件。记忆目标的反馈可作为另一种资源的生成依据，例如由经验生成 Skill；引用保存在反馈／候选，原记忆仍由现有服务管理。
5. 代码候选可展开“独立代码实验”，输入一个明确检查命令，在原版／候选副本中各执行一次；输出按需查看、可停止。比较不自动取得修复授权，也不要求先通过测试才能采用。
6. 资源采用后由下次请求／新任务按原加载规则使用；已有工作流快照不改写。代码采用后重启对应应用。恢复按钮只恢复此候选的资源，保留之后已发生的其他修改；不确定写入显示原始状态，不自动重放。
7. 如果代码导致 Harness 不能启动，关闭应用后运行候选详情所列数据目录中的 `Restore.cmd`。恢复入口只依赖标准库和现有 Python 解释器，不依赖被修改的 `my_agent`；恢复后再启动应用。

代码实验复用项目的解释器和执行模式，默认排除 `.git`、虚拟环境、依赖目录、`.env`、测试产物及链接；排除清单可通过 `EvolutionExperimentParams.exclude` 调整。没有自动安装依赖。Python `src/` 布局或 editable 安装需要检查命令明确从副本加载代码，例如设置当前副本的 `PYTHONPATH`；绝对脚本路径不会自动改写。副本不是额外的 OS 沙箱，执行边界仍由项目选择的 direct／sandbox 决定。

本次不是安装包升级器：没有自动热替换、自动重启、数据结构迁移回滚或整库自主进化循环。独立恢复保存的是本次修改前版本，不把它称为已经全面验证的发行版本。实验比较只证明同一检查的差异；真实数据迁移、长期效果、跨语言语义检索与全库自修改另需具体样本验证。

技术入口：`evolution/` 只组织反馈、候选、诊断和独立作业；实际资源仍由 memory／skills／workflow／文件服务写入。工具按需发现 `record_feedback`、`propose_improvement`；工具使用说明单独带来源、仅随已加载工具装配，不篡改原 schema。运行故障保留 `cause_code`／`failure_phase`／`diagnostic_id`；桌面进程日志保留启动身份、PID、退出码／信号，不保存原始 stderr。诊断保留量与队列、Electron 日志大小集中在 `defaults.json`，不成为任务预算。

### 选材与日志关联补充（2026-10-20 历史设计）

以下关于顺序装配 Trace 正文的描述已被 2026-10-21 的统一筛选方案替代：当前初始输入包含线索索引，正文由调查工具按需读取，指定资源路径也一样；“不限”不再表示自动装配所选 Trace 全文。来源、归档与实际材料记录原则继续保留。

- Trace 来源是已有会话事实的公开投影，包括用户请求、模型响应、工具参数及结果。整次运行按合并后的 Trace 行展开，不重复把调用结果的隐藏序号当成新记录；同一行从反馈或直接选择进入时去重。
- 异常来源是数据根 `logs/diagnostics/` 的结构化错误／告警，显示组件、阶段、代码和异常位置。选择异常记录只带入该诊断；关联 Trace 另可选取。Electron `logs/electron.log` 尚不在自动选材范围内；没有自动扫描所有日志。
- 材料正文受项目 `input_chars` 预算约束，可在“改进预算”修改或选不限。选定的具体事件／异常优先于整次运行，有限预算超出部分显示截断与省略数量。Trace 单行沿现有详情分段接口读取，直到读完或达到材料预算；目标资源和补充说明单独计入模型请求，不宣称字符数是完整请求 token 数。
- 预览与生成共用 `evolution.preview` 的装配实现；生成时重新读取，作业持久化实际参考正文与来源。候选通过 `review_job_id` 关联作业，按需读取，列表不重复传全文。折叠与关闭不改变材料内容。
- 手动候选和此前旧作业没有输入快照时明确显示未记录，不倒推当时使用的材料。该快照是复盘参考材料，不是包含 system 指令、传输字段和凭据的原始网络请求。

### 范围选择修正（同日）

这里的整个会话指该会话事件日志中的运行事实；独立压缩／记忆维护作业不自动混入，宿主诊断通过单独的诊断选择入口添加。大正文沿 Trace 分段接口继续读取，实际纳入量由可调整的材料预算决定，不再隐式停在第一段。

- 旧版“先读 40 条 Trace，再推导可选运行”的目录实现被替代。`evolution.runs` 从完整会话投影按运行归组后分页，返回总轮数／事件数、提问、时间、状态和事件数量。单轮工具多不再挤掉其他轮。
- 来源增加显式 `scope`（session／run／event）与 `through_seq`。旧的 run_id／seq 来源保持原含义，旧纯会话引用不自动扩大读取；新的整个会话选择必须显式保存 session 范围。
- 整个会话和运行范围以选择时的截止序号冻结，配对工具结果也受截止约束。切换范围清除当前会话的旧直接选择，保留其他会话及已选反馈；避免界面同时表示“整个会话”和“只选一条”。反馈关联来源在预览中同样列出。
- 预览／作业快照分别显示“所选范围及匹配事件数”和“去重后完整引用、部分引用、省略的事件数”。选择整个会话不代表正文绕过材料预算全部发送；不再只显示模糊的“几个来源”。
- 定位原始 Trace 仅用于浏览，不改变复盘范围。目录的分页大小是展示粒度，不是复盘仅限最近 N 轮的产品约束。
