## 1. 阶段目标与范围

### 2026-10-19 收尾补充

本批只增强搜索和既有 Git 的模型入口。搜索默认字面匹配，可选 rg 正则、带行号前后文及查询级包含 / 排除模式；模型与桌面共享后端。Git 暴露 status / diff / log / stage / unstage / commit / init，复用本地服务，无远端，Plan 仅读取。

项目 Git 开关控制桌面与模型 Git 入口。旧项目默认开启，不自动初始化。按用户选择，关闭将项目根自己的 `.git` 移至所选应用数据根 `git-backups/<project_id>/metadata`，开启恢复；代码文件不动，上层仓库不动。工作树的 `.git` 指针文件只移动文件自身，不移动共享仓库。存在新 `.git` 与备份并存时保留两者并报告，不覆盖。开关不限制通用 shell，不描述为执行隔离。仅在隔离项目验证移动、恢复、重启与冲突，不对开发仓库切换。

M5 同时推进多智能体协作和单 Agent 编码能力完善。用户能够描述项目目标、生成并调整协作团队，也能够在应用内看代码、编辑、运行、继续输入、管理修改，并向模型提供文件和图片。

### 1.1 工程基线与取舍

- 继续使用 Windows、Python 3.13 / uv、Electron、React、TypeScript 和现有 JSON-RPC / Pydantic 协议；Python 核心继续可独立使用。
- 模型仍为 OpenCode Go 的 `glm-5.3-flash` 和 `deepseek-v4.1-flash`。本阶段不增加视觉辅助模型或 provider，分别实现并核实两者的图片输入链路。

- 不引入新的 Agent 框架、图数据库、消息中间件或通用插件运行时；压缩、记忆、Skill、MCP、工作流与 Trace 继续复用。

## 2. 智能体合作空间

### 2.1 创建与组织

- 一个任务对应一个合作空间，保留“项目 → 任务 → 会话”结构。
- 用户选择项目并描述目标后，Agent 结合项目材料生成团队草稿：成员职责、工作范围、建议模型与 Skill、协作关系、初始工作项。
- 草稿阶段允许读取和讨论；用户调整后点击“启动”，创建或绑定草稿中的成员会话，开始授权范围内的工作。用户启动这份草稿是对其中成员会话的批量创建 / 绑定操作，不延伸为运行中任意扩编的授权。
- 成员具有独立于会话的稳定身份。更换会话后继续保留职责、工作归属和成果引用；旧会话仍可访问。
- 支持保存、复制和导入导出团队模板。创建任务采用模板快照，模板后续修改不改写运行中的团队；模板不自动带入真实会话绑定和宿主机器路径。说明建议使用项目相对引用；自由说明原样保留，不用路径关键词拦截保存，也不将其中的文字作为可执行命令。
- 成员使用已启用的项目能力及所选 Skill / 模型，继续沿用现有资源服务与模型切换语义；不因角色名字永久增加工具禁令。

### 2.2 三种组织方式与可视化图

| 方式 | 默认组织 |
| --- | --- |
| 中心协调 | 协调者分配工作并整合结果 |
| 分层协作 | 总协调者、分组负责人和执行成员分层推进 |
| 对等协作 | 成员直接协调；指定一个可更换的接收 / 整合成员处理未指定对象的输入 |

三种方式共用运行核心，作为可编辑的组织预设。节点代表完整 Agent；连线描述委派、结果交付、讨论或反馈关系，允许反馈环。关系图不是逐工具执行 DAG，也不是通信权限白名单。

图支持增删成员、调整职责、拖动布局和修改关系。运行状态来自真实会话、工作项和协作事件；点击节点或连线可查看对应工作与结果。计划关系与实际发生的协作分别展示，实时更新保留用户的布局和阅读位置。

### 2.3 群聊与执行

- 群聊作为主要交流入口，支持 `@成员` 或多个成员。未指定对象的消息交给协调者或本轮接收成员，不默认唤醒全体。
- 公开发言、进度和结果直接显示；思考、工具和内部通信按需展开或进入 Trace，公开回答保持流式输出。
- 普通对话完成后返回用户；启动合作目标后才持续推进。中途插入普通问题时先回答，再继续原目标。
- 合作轮次关联现有成员 Goal、Run、协作请求和结果，只补空间级控制与投影，不建立第二套模型 / 工具执行循环。
- 在既定成员、职责和目标内，团队可调整分工与协作关系，并显示变化；新增正式成员或会话由用户操作。内部子 Agent 继续受现有开关控制。
- WorkItem 增加负责人、承接状态、关联执行和结果。复用单写者处理分配与领取，同一成员沿既有会话串行执行；独立成员可以并行，不建立额外租约或心跳系统。
- 普通通知在接收方下一次请求边界进入上下文；明确的工作请求按已有机制启动空闲成员或排队，结果通过事件等待，不靠模型轮询。
- Review 及其修复若已包含在启动时确认的目标中，可以连续执行；不在范围内的问题先报告。报告仍以 summary / outcome 为最小输入，工作图、产物和逐项验收不成为执行门槛。

### 2.4 停止、交接与接续

单个成员失败时停止其受影响的 Run / Goal，依赖该结果的工作等待处理，无关工作继续。可分别停止成员或整轮合作，不自动重试、转交同一失败操作或绕过停止状态。可修正的参数 / 文件定位反馈仍按既有规则交回模型，不被重新升级为运行故障。

成员之间传递任务目标、职责、相关结论、工作进度和成果引用；历史详情按需读取。新会话不默认复制群聊或其他成员全部历史。用户维护的目标和约束不被成员报告覆盖，具体报告保留来源与历史。

重启恢复团队、图、消息和工作状态，不自动重新执行模型请求或副作用。局部 Goal 完成不自动结束整个任务，停止 Goal 不顺带关闭已保留的预览服务。

## 3. 编码工作台与 Agent 能力

### 3.1 文件、编辑与修改管理

- 增加文件树、快速打开、搜索、多标签编辑、行号定位、代码块复制和外部编辑器打开入口。
- Monaco 支持人工编辑、保存及未保存草稿恢复。草稿归应用数据根；人工保存和 Agent 文件操作共用后端文件服务与修改记录。
- 补齐文件 / 目录创建、移动、重命名、删除和多文件补丁工具，继续保留现有创建与精确编辑方式。
- 成果页区分历史修改与当前磁盘差异，支持按成员、Run、文件查看，提供并排 diff 和明确选择后的恢复操作。
- 批量操作按实际成功文件记录结果，不将部分失败显示为全部成功；终端或外部程序产生的修改不冒称已经拥有可撤销记录。
- 人工缓冲尚未保存、磁盘又被修改时，在对应文件提供比较与合并入口。保留双方内容，不冻结整个项目或团队。
- 恢复只处理选定修改；存在后续重叠修改时交给用户比较，不覆盖其他工作。文件写入保留原编码 / 换行，沿用已有原文匹配与真实内容变化反馈，不要求模型传回 hash。

### 3.2 交互式程序与终端

- 保留现有非交互命令和服务卡片，另增加真正的交互终端，支持输入、尺寸调整、中断和关闭。
- Agent 可启动交互程序、读取输出并继续输入；用户可在同一终端接管，再显式交还。输入归属只作用于该终端，避免双方输入混在一起。
- 人工新开的终端默认由用户控制，关联给成员后才参与其工作。
- Python 后端管理进程与生命周期，沿用项目环境、输出归档和进程清理；renderer 只显示和发送输入。非交互命令继续保留独立 stdout / stderr，不强制全部转成 PTY。
- 切换会话不结束保留的终端或预览服务；退出应用时清理，重启只恢复记录，不自动重启程序。
- 终端仍运行不等于其中某条命令已成功；退出状态、等待输入和运行中分别表达。不能仅凭看起来像命令提示符就记录成功。

### 3.3 本地 Git 工作台

以工作区和暂存区为主要入口；用户所说的本地“缓存区”在界面中使用 Git 的“暂存区”名称。提供文件状态、工作区 / 暂存区差异、按文件暂存与取消暂存，以及用于本地版本记录的提交和历史查看。上述操作全部在本地仓库完成，不需要 remote、GitHub 账号或登录。

本阶段不提供远端登记、认证、fetch / pull / push 或远端连通性检查；已有仓库配置的 remote 不作为使用条件，也不因打开项目而访问。专门的分支 / worktree 管理界面后置，普通工作不依赖它们。

默认仍在原项目工作，不自动初始化 Git、创建分支或工作副本。没有仓库时可由用户明确选择初始化本地 Git；未初始化仍可编辑、运行、查看已有修改记录和使用合作空间。本地 Git 操作依据用户操作或已有任务指令执行，冲突进入文件与差异界面，不自动丢弃修改或重写历史。

### 3.4 LSP 与代码理解

- Python 后端按项目和语言按需启动语言服务，桌面编辑器和 Agent 共用服务。
- 首批接入 Python 的 Pyright，以及 TypeScript / JavaScript 的 TypeScript 原生 LSP；仓库现有 TypeScript 7.0.2 已核实提供 LSP 启动入口。项目使用的 Python / TypeScript 配置仍按实际项目环境处理，不把本应用版本强加给目标项目。
- 提供定义、引用、符号、悬浮说明、诊断、补全和符号重命名。重命名产生的修改通过统一文件服务执行并记录。
- 设置中管理语言服务命令、项目启停和解释器关联；支持登记其他标准 LSP 服务。不在应用启动时自动安装服务或重建用户环境。
- 结果注明所依据的文件或未保存缓冲及版本，并能回读对应内容，避免将编辑器草稿当成磁盘事实。
- 服务缺失或失败只影响对应语言能力，普通文件工具和文本搜索继续可用；诊断不自动成为执行门槛，不能代替实际测试结果。

### 3.5 文件引用、图片与成果展示

- 对话支持 Markdown、表格、代码块；保留流式回答和可折叠思考。
- 输入区支持选择文件、`@文件`、引用编辑器选区，以及粘贴、拖入图片；发送前显示可移除的材料条目。
- 文件和选区在发送时保存实际材料及来源；未保存选区明确标为草稿，不悄悄保存到项目。
- 图片接入现有两个模型的多模态内容块；浏览器截图也可以由 Agent 按需读取并送入模型，不把截图保存成功称为模型已看图。
- 官方资料确认两个模型具有原生视觉能力，但 Go 渠道仍须分别真实验收。公开 Go 模型目录此次只返回身份信息，没有模态声明，不能据此断言其图片能力已验证。[GLM 说明](https://docs.z.ai/guides/vlm/glm-5.3-flash)、[DeepSeek 说明](https://api-docs.deepseek.com/news/news260910/)、[Go 接口说明](https://opencode.ai/docs/go/)
- 图片字节存为附件，发送时组装请求；不将 Base64 当正文估算 token。服务端 usage 为实际用量依据，发送前未知的图片用量明确标注。
- 压缩保留图片用途、已得到的观察结论和附件引用，原图按需回读；不把全部历史图片持续塞回请求。
- 图片、文件和代码成果可打开并定位来源成员、Run 与 Trace。内容缺失或无法解析时显示真实状态，不用模型描述代替未完成的读取。

## 4. 界面、接口与存储

### 4.1 桌面布局

左侧继续保留项目、任务和会话导航，并提供文件视图切换。主区域可切换合作空间、会话与代码；图、Trace、成果和终端均可关闭或折叠，避免全部常驻挤占对话。输入区保持可见，布局和编辑草稿可恢复；窄窗口采用切换 / 覆盖式面板，不靠整页上下滚动寻找主要输入。

Skill / MCP 继续从左侧资源管理进入，按项目使用；本阶段不将这些管理面板重新堆到输入框上方。

2026-10-19 体验优化沿现有机制补充：任务页折叠容器保持自然高度，只有群聊历史有独立滚动区，输入和协同工作不再共用固定高度；共享信息默认收起。图形按三种组织方式提供手动触发的自动排布，连接点依节点相对位置选择，反向反馈不穿过节点；节点显示实际运行状态，双击进入原会话。图中的短关系类型可点击查看完整说明。

群聊按原消息 / 合作轮次关联成员回答，增加“仅看进行中”、等待对象和跳转入口。关联和等待来自已有投递 / Run 事实，仅作为公开投影，不另建日志、调度器或完成判定；一次回答结束不代表任务完成。旧记录缺少关联时单独显示，不猜测归属。

### 4.2 服务与公开接口

新增能力沿现有服务边界组织：

| 接口组 | 职责 |

| `terminals.*` | 交互输入、终端尺寸、中断和控制归属；原 `programs.*` 非交互命令 / 服务继续保留 |
| 代码理解接口 | 语言服务配置、实际状态、查询、诊断与编辑建议 |
| 附件接口 | 导入、预览、引用、读取及请求材料关联 |
| 本地 Git 接口 | 工作区 / 暂存区状态、差异、暂存 / 取消暂存、本地提交与历史 |

协议由 Pydantic 定义，同步 schema 和生成 TypeScript；2026-09-30 实施已从 v6 升至 v7，具体证据见阶段进度。Python 继续负责业务写入；Electron 保留原生选择、剪贴板和后端生命周期职责。

### 4.3 事实来源、上下文与兼容

- 团队配置与运行报告分开保存。会话、Run、Goal、工具、成果和请求用量继续引用现有记录；跨成员 Trace 做关联投影，不复制另一套完整日志或重复计费。
- Skill、成员职责、协作消息、文件和图片统一进入现有请求组装与实际材料清单，不增加第二条隐式上下文注入路径。
- 团队模板、成员配置、布局、编辑草稿和附件使用所选应用数据根；只有明确的用户代码操作写入项目。
- 旧任务可继续使用原界面，并由用户显式升级为合作空间；不批量改写历史。新旧修改记录均可阅读，缺失字段显示真实的未知状态。
- 正常操作沿用已有授权和失败语义，不新增信任开关、模型回传 hash、强制报告或逐工具审批。只在实际冲突及对应协议 / 存储边界处理必要问题，不层层重复校验。

## 5. 交付顺序与验收

### 5.1 实施顺序

实施前先保存本方案、[M5 进度](../progress/m5.md)，同步总规划与进度总览。方案落地时仅完成文档；2026-09-30 用户随后授权开始实施，实际结果以进度文件为准。

每批包含可体验的桌面入口，按交付结果推进，不设固定工期。开始每批实施时，在阶段进度写明本次具体范围与下一步，再将该批标为进行中；不把保存方案或安装依赖算作模块完成。

### 5.2 简单联合场景

继续使用空白项目中的单页计数器，不扩展成复杂业务样例：

1. 用户选择项目并描述目标，生成团队，调整成员职责和关系后启动。
2. 成员按分工完成页面与逻辑；Review 返回一项问题，按已确认目标修复。
3. 用户在编辑器修改一处文案，在终端运行程序；另外用极小的输入程序确认持续输入和接管。
4. Agent 定位代码、查询引用，浏览页面并读取截图，确认按钮点击前后的变化。
5. 查看成员成果、历史 / 当前差异和 Trace，在未配置 remote 的隔离仓库完成暂存与本地提交，并查看提交历史。
6. 重启恢复团队、记录和编辑草稿，再为同一成员显式绑定新会话接续；不自动重启模型、终端或浏览器。

三种组织方式分别验证路由与状态，不要求为每种组织方式重新制作一套复杂应用。

### 5.3 最小定向验收

- 合作：三种组织方式、消息路由、并行分配、局部失败、停止及成员更换会话；报告和实际运行来源一致。
- 文件：人工未保存修改与 Agent 写入并存、修改恢复、批量操作部分失败；后续修改不被覆盖。
- 程序：真实终端输入、中文输出、中断和子进程清理；普通命令 / 服务生命周期不被破坏。
- 代码理解：Python / TypeScript 的实际语言服务，以及服务缺失时普通编码可用；模拟协议通过不能替代实际服务验证。
- 多模态：双模型真实图片理解、截图来源、压缩回读和用量展示；请求拒绝或未读取图片时不得记录为理解通过。
- Git 与兼容：未配置 remote 的隔离仓库可以完成工作区 / 暂存区查看、暂存 / 取消暂存、本地提交与历史查看，无登录或远端访问前置条件；重启恢复以及旧任务 / 会话 / 修改记录可读。
- 桌面：图、编辑器、终端、Trace 的折叠与切换不破坏输入区和阅读位置。

测试集中在 `tests/`，产物进入 `.artifacts/tests/`。每批只验证实际变化，低影响文档 / 样式修改以必要差异检查为主；不无理由扩成全仓回归。联合真实模型验收使用隔离样本，在实际执行前记录可调整的请求 / 时间预算；该预算不是产品限制，不发送用户历史会话作为默认测试材料。

阶段开始、相关固定条件变化及收尾时，按 AGENTS.md 对本批范围检查硬编码、过度约束和实现 / 注释 / 提示词一致性；结果写进 M5 进度。只有实际验收通过并记录剩余限制，才能将阶段标为完成。

## 6. 2026-10-19 增量：三个可选开发方法

根据用户授权，将 [工作流研究第 12 节](../research/04-workflows.md#12-2026-10-19把常见开源开发方法作为可选流程) 中的 OpenSpec、Superpowers、Spec Kit 制作为内置适配模板。个人流程保持默认，新建任务或已有任务套用时可选择；本批不实现项目默认继承、BMAD 或 GSD。

- OpenSpec：探索 → 变更提案 → 规范与设计 → 任务 → 实施 → 核对 → 归档；以一份变更目录里的产物接续。
- Superpowers：讨论 → 计划 → 实施 → 调试 / 验证 → Review → 交接；复用已内置的 Superpowers 方法适配资源，并补流程级指引。
- Spec Kit：项目原则 → 需求 → 澄清 → 技术计划 → 任务 → 实施 → 收敛；保持规范、设计和实现任务的对应。
- 每个流程有来源、参考版本及与上游的差异。按阶段装配对应方法，不把整套上游提示词、CLI / Hooks 或并发引擎引入请求。方法自身的 Skill 可在现有资源库查看和复制。
- 桌面提供左侧工作流入口，模板说明可读，支持新建任务选择、当前任务套用 / 切换阶段及复制编辑。内置目录不可直接修改，副本和任务快照可编辑；旧任务不自动迁移。
- 产物由 Agent 在本次任务授权范围内写入；选择模板本身不写项目、不建分支、不自动推送或要求 TDD / 子 Agent / 额外审批。需使用严格 TDD 时遵循用户当前要求。流程说明明确适配差异，不宣称安装了上游原版。
- 最小验收：三个模板可列出和选择、关联资源可装配、阶段切换正确、复制 / 重启后任务快照保留；旧模板 / 无模板任务正常，桌面入口可用。零模型验证不宣称已经证明真实模型遵循质量。
