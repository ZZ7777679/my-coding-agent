# 上下文系统：用户操作与 Harness 使用接口

> 日期：2026-09-20。状态：首版使用接口已实施。本文保留后续方向，已交付边界见下一节；验证记录见 [M3 progress](../progress/m3.md)。接续 [M3 上下文计划](m3-context-compaction-plan.md) 与 [记忆计划](m3-memory-plan.md)。

## 本次实际交付

- 输入区提供“上下文 / 查找历史 / 记忆”三个紧凑入口，打开可关闭浮层；不占用主对话固定高度。标题、底部收起与 Escape 支持关闭查看，后台刷新不重开。
- 历史查询区、结果列表、单条原文分别折叠；续读累加原文，续页保留前页与原匹配数。查询输入与已提交条件分开，修改输入框不会改变当前续页来源。查看、查询、草稿与所选材料在本次应用运行内按会话缓存；重启不保留这些临时状态，已保存记忆与原历史持久化。
- “上次实际发送的材料”来自 `request.started.context`，包含请求 / 模型身份、任务版本、摘要身份、历史事件、记忆 ID / 修订、协作预览、消息数和工具名。预览最多 600 字符，仅限制展示；实际材料完整 / 片段标记独立保存。旧请求没有清单时不倒推；之后修改记忆不改写旧清单。
- “下次如何组装上下文”解释当前设置下的规则，不冒充实际发送清单。模型侧 `get_context_status` 分页返回同一材料记录；`compact_context` 复用原作业、同模型、预算和失败归属。短使用说明只列已装配工具，没有强制预检或轮询。
- 记忆有独立入口、搜索框和操作说明。“上次带入 N 条”来自实际请求；列表数量不冒充总库存。自动带入与空闲提取为常用开关，主动保存、实验和维护参数在高级设置。开启空闲提取会一起开启贡献，界面明确说明；手动保存不调用模型。
- 历史与记忆可“加入这次提问”：选择公开文本快照和来源，输入区显示可移除标签，发送时作为标记明确的参考输入，由 Python 沿既有 Run / Goal 接纳路径持久化。查看不等于发送；接纳失败或关闭面板不清除选择。材料在清单中归入用户输入，不另建引用服务或长期记忆。
- 动作明确为“压缩当前会话”“提取可复用记忆”“整理知识页”；参数与累计用量折叠。没有新增模型、审批、执行前置条件或真实模型请求。

尚未交付的草案方向：跨来源统一搜索、自动发现全部归档并免填引用、按旧修订展开记忆完整正文、从任意消息直接保存、独立结构化附件协议、浏览任意过去请求的完整清单及 token 驱动自动压缩。当前清单是来源与固定预览，不是完整 provider 请求转储；原文回读取对应来源的可用数据。自动压缩仍按既有可调字节策略。

## 1. 要解决的使用问题

日常执行自动带入合适材料；用户能看清采用了什么、纠正不合适的材料；模型知道缺少信息时去哪里找、找到后怎样展开，什么时候应该留下可复用信息。人、模型和宿主使用同一套来源与状态，不能各自推测另一侧做了什么。

已有摘要、存储、工具和 RPC 继续复用；按用户授权接通首版，不创建通用上下文平台、常驻协调 agent 或新的确认流程。下文原始目标中尚未交付的部分以上述清单为准。

## 2. 当前代码中的具体缺口

| 已核对的位置 | 已有能力 | 使用上的缺口 |
| --- | --- | --- |
| `ContextMemory.tsx` | token 显示、摘要、历史查询、记忆与参数表单 | 日常操作与维护参数混放；查归档需要输入 ID；事件序号、scope/source 等内部名直接成为界面主信息 |
| `ContextService.prepare`、`MemoryService.recall` | 自动组装摘要、尾部、任务材料、记忆和协作消息 | 没有记录完整的逐请求材料清单；记忆 `used_ids` 只是最近召回状态，不能代表所有来源或某次历史请求 |
| `ContextTools` | 当前会话历史搜索、指定条目和归档读取 | 没有模型侧上下文状态与整理入口；工具说明中的 next_offset 没讲清要传回输入参数 offset |
| `MemoryTools` 与运行提示 | 搜索 / 读取 / 保存 / 遗忘记忆，发布任务决定 | 规则分散在工具描述和注入文字；没有简洁的使用顺序与同类操作选择示例 |
| 记忆开关 | 自动注入、贡献提示、空闲提取、实验 | 用户难理解“使用”“贡献”“自动整理”之间的关系；需把自动行为和用户明确要求的操作区分清楚 |
| 历史与记忆列表 | 可查询、可分页、可管理 | 缺少从结果直接“加入这次提问”的路径；查看一条记录不等于模型收到它 |
| 模型窗口与整理预算 | token 用量可见，整理按字节处理预算触发 | 显示 1M 窗口但可能在较低 token 用量时整理，需要明确触发依据；token 驱动策略仍是另一项待实施能力 |

这些是代码核对结果，不是模型实测证明。M3 首版的基础功能验收仍有效；它不能替代使用路径完整性验收。

## 3. 对用户：三个动作与一个紧凑入口

输入区保留一行，例如：`上下文 · 上次输入 123.5K / 1M · 自动管理 [查看]`。展开为按需面板，使用三个明确入口，不把全部维护表单同时堆在输入框上方。

### 查看内容随时可收起或关闭（用户已确定）

- 摘要、历史原文、归档结果、记忆、来源和工具详情默认折叠；点击标题可展开，再次点击可收起，并显示明确的展开 / 收起状态。长内容的末尾也提供“收起”，不要求滚回开头。
- “继续展开 / 读取更多”只增加当前详情内容，整个详情仍可一键收起。收起后保留标题与简短状态，释放会话主体空间。
- 整个上下文侧面板或浮层提供始终可见的关闭按钮；键盘 Escape 关闭最上层查看面板，焦点回到打开它的入口。关闭后不留下占位宽度或高度。
- 后台刷新、流式更新、读取完成或整理完成都不能把用户已收起 / 关闭的内容自动打开。切换会话时不把上一会话的展开内容带到新会话；返回时可以恢复该会话自己的展开状态。
- 查看状态与业务状态分开：收起 / 关闭不取消运行、不停止压缩、不删除材料，也不改变“加入这次提问”的选择。已选材料仍用输入区标签显示，可独立移除；关闭查看面板不丢未保存草稿。

### 查看本次上下文

区分“上次实际发送”和“下次准备采用”：前者来自请求组装时保存的事实，后者是当前设置与已保存材料的预览，仍可能在发送前变化。

材料按用户能理解的来源展示：任务目标 / 已确认结论、会话摘要、近期对话 / 工具结果、带入的记忆、已收到的协作结果、用户为本次提问选择的材料。每项显示标题、来源、完整 / 摘要 / 片段、是否实际加入请求及展开入口；未加载的可回读材料单独标明。

任务事实和用户明确约束由原任务入口编辑；这不是可任意取消系统指令的提示编辑器。自动带入的记忆可查看原文、纠正或停止自动带入；所有改动说明从下一请求生效，已经发出的请求保持原样。

### 找回旧信息

用户明确指出当前“查找历史”展开后不便收起，此项是本次交互修正的具体目标：整个历史查询区、查询结果列表、单条历史原文分别支持自由展开 / 收起。再次点击对应标题即可切换，长结果底部提供收起入口；收起保留关键词、筛选范围、已取得结果和分页位置，再展开不要求重新查询。查询完成或后台刷新不得重新打开用户已收起的区域。不能只让单条原文可折叠，却把整个查询区或结果列表一直留在界面上。

输入关键词，范围明确为本会话历史、归档结果、项目记忆；需要其他会话时使用已有角色安排内的协作入口。首版可先统一显示本会话与记忆的查询结果，复用现有查询，不要求新建全局索引或向量数据库。

搜索结果显示自然标题、时间或所属会话、命中片段与“展开原文 / 加入这次提问”。归档 ID、事件序号和分页位置由结果携带，用户不需要复制填写。长内容用“继续展开”，每次读取的来源与范围保持明确。

“查看”仅在界面展示；“加入这次提问”是显式的输入材料选择，发送后它可能随会话历史保留，但不会自动成为项目长期记忆。界面用可移除的材料标签表明本次选中了什么。

### 保存以后要用的信息

用户可在消息、搜索结果或记忆条目附近发起，也可直接说“记住这个项目用 uv”。默认给出已有内容和明确作用域，不要求先填分类、关联 ID 或来源序号。

| 用户意图 | 默认承载位置 | 生效范围 |
| --- | --- | --- |
| “这次参考一下这段日志” | 本次提问材料 | 本次请求，随后作为历史保留 |
| “这个任务决定只用标准库” | 任务已确认结论 | 本任务内后续请求、已有协作会话 |
| “这个项目以后都用 uv” | 项目记忆 | 本项目相关任务 / 会话按需召回 |
| “以后我的项目都这样” | 用户偏好 | 用户明确表达的跨项目范围 |

任务报告中的临时进展继续归任务工作记录，不为了让模型记得进度把它写进长期记忆。知识页、关系、有效期和批量整理属于高级管理。

## 4. 整理与记忆的按钮语义

- 摘要操作称为“压缩当前会话”，记忆提取称为“提取可复用记忆”，知识页操作称为“整理知识页”，避免三个不同动作都叫“整理”。
- 压缩结果显示“摘要已生成，下次请求采用”或“已用于最近请求”；压缩前后 token 对比只在都有可比实测值时显示，不能用字节差冒充 token 节省。
- 自动行为用“自动压缩会话”“自动带入相关记忆”“空闲时提取项目记忆”表述。原 `contribute` 同时影响提示与后台提取，其语义必须随迁移一起处理，不仅换标题；建议默认只露出上述常用选项，模型主动保存许可放到高级设置并明确说明。
- 自动行为关闭后，用户明确要求的一次读取、保存或压缩仍能执行。保留开关状态，不偷偷重新打开自动模式。普通记忆保存不增加逐项确认。
- 参数、累计维护费用、目录来源、字节预算、原始错误码进入高级详情；失败卡片直接说明本次动作、失败原因、原历史是否保留及可执行的下一步。
- 当前运行所需摘要故障仍按既定 Run / Goal 规则停止；独立维护的失败留在自身卡片。具体失败归属不因界面改版改变。

## 5. 对模型：短使用说明与最小工具调用

宿主处理容量、切点、自动摘要、记忆自动召回和下一请求采用。模型负责理解当前问题、判断还缺什么、主动补读、保存值得复用的知识或发布任务决定。日常回答无需先调用检查工具。

新增一段随能力装配的“上下文使用说明”，与具体工具 schema 同步维护：

1. 先用当前已提供的材料；发现摘要遗漏细节、旧决定来源不明或工具结果有归档引用时才补读。
2. 当前任务的目标 / 已确认结论用 `read_task`；本会话旧对话 / 归档用 `read_history`；项目和用户知识用 `search_memory`，再用 `read_memory` 展开。项目当前代码仍通过文件工具读取。
3. 使用工具返回的引用和分页参数，不猜 ID / 序号，不把旧日志当作刚执行的结果。续读示例明确：返回 `next_offset=8000` 时，下一请求传 `offset=8000`。
4. 用户确认的任务决定用 `publish_task_decision`；可复用知识用 `save_memory`；纠正已知记忆时更新已有 ID；用户要求忘记时定位相应条目后调用 `forget_memory`。作用域遵循上一节。
5. 搜索无结果就报告范围、调整关键词或继续看实际代码；查完无需提交证明表，不能为了流程齐全先读一遍所有历史和记忆。

最小调用保持现有接口：

```json
{"tool":"read_history","arguments":{"query":"启动命令"}}
{"tool":"read_history","arguments":{"entry_seq":42,"offset":8000}}
{"tool":"search_memory","arguments":{"query":"环境"}}
{"tool":"save_memory","arguments":{"fields":{"title":"项目环境","content":"使用项目已有的 uv 环境。","scope":"project"}}}
```

以上是文档示例，条目序号和 ID 必须取自真实返回值。工具发现由当前能力决定，不能在工具未装配时向模型宣称可调用。

已新增两个薄入口，复用 `ContextService`：

| 入口 | 模型何时调用 | 返回事实 |
| --- | --- | --- |
| `get_context_status` | 用户问带入了什么 / 为何压缩，或模型确需了解上下文状态 | 当前请求材料清单、最近实际 token、整理状态、可回读引用；不返回全量历史 |
| `compact_context` | 用户明确要求压缩，或模型识别到明确整理需求且在既定自动行为范围内 | 复用或接纳已有整理作业，返回状态 / 来源；不新建会话，不悄悄换模型 |

`compact_context` 的接纳、请求计费、取消和失败归属使用既有路径，在下一完整请求边界采用结果；模型不反复轮询作业，也不直接改宿主摘要文件。具体等待方式在实施前按现有调度接通，不再增加一个摘要调度器。

## 6. 对宿主：提供能让两侧一致的事实

现有组装入口返回最终消息时，同时产出一份轻量材料清单：请求 / 模型身份、来源类型、已有来源标识、实际采用范围与呈现形式、采用摘要的身份、所用记忆修订和选择依据。依据来自宿主实际分支，如“任务固定事实”“命中当前问题”“用户选择”，不另找模型生成理由。

清单随该请求的事实保存，桌面和 `get_context_status` 读取同一份数据。内存中的 `used_ids` 不能回推某次旧请求；事后修改记忆也不能让旧请求详情看起来使用了新版条目。只需保存已采用引用、版本与必要片段，不复制另一套完整聊天，不新加内容 hash 门槛。

材料引用沿用已有会话 / 事件 / 归档 / 记忆身份，适配层将其变为回读参数。首版直接补充现有 RPC / 工具，不建立引用服务或万能 DSL。用户选中已通过 RPC 展示的公开快照，发送时作为参考输入交给 Python 持久化；renderer 不直接访问文件。结构化附件协议按实际需要再引入。

## 7. 一个简单的完整使用过程

1. 在同一项目新建任务和会话，用户说“做一个离线计数器，项目继续用 uv”。任务目标自动带入；与项目环境有关的已有记忆按需带入，可从“查看本次上下文”核实。
2. 用户说“记住这个项目不用 CDN”，Agent 保存项目记忆并返回简短结果；用户可在相应条目直接纠正，不需要寻找记忆 ID。
3. 对话较长后自动压缩，显示生成 / 等待采用 / 已采用。用户继续说“按照之前讨论的按钮样式，加一个清零按钮”。摘要缺细节时 Agent 搜索历史、展开相关片段，接着执行。
4. 用户也可以搜索“按钮样式”，将结果加入提问。界面明确显示本次选中的材料，Agent 从同一来源读取。
5. 用户在同任务新建会话时，带入任务事实和相关记忆；旧对话不会全部灌入，也不自动创建会话。需要旧会话细节时沿已安排协作路径访问。

这里的摘要和操作示例是设计目标，不是已通过的真实模型验收。

## 8. 建议实施顺序

1. **先贯通可见性**：逐请求材料清单、状态含义、紧凑查看入口；同时补短使用说明及 `get_context_status`。人和 Agent 先能准确回答“这次用了什么”。
2. **再贯通操作**：从现有结果展开原文 / 续读 / 加入提问、自然语言保存与纠正的明确反馈、`compact_context`；常用操作移到结果旁，高级参数收进详情。
3. **最后校准自动策略**：在同一接口上细化 token 驱动压缩、召回选择与可选知识页。该策略变化单独确认范围，不靠界面上的 1M 数字推断已经实现。

每步都形成能用的小闭环，不设置固定工期。必要检查聚焦实际问题：清单与真正发出的材料一致；分页和来源能直接续读；展开 / 读取更多后仍能收起，关闭面板释放空间且后台更新不重新打开；新会话 / 压缩后还能完成上述简单任务；普通使用不增加确认或强制自检。不为文案 / 布局另跑全量回归。
