# Skill 在线发现与导入（M4 增量）

日期：2026-09-22。用户选择在应用内搜索、安装，再导入项目；随后明确优先 Skill 网站，MCP 在线市场与登录后置。本方案先落地，实施记录见 [M4 进度](../progress/m4.md)。

## 体验与范围

**用户后续纠正：主要需求是直接在 Harness 内访问聚合网站，使用网站原有搜索、分页和分类；不是仅把一个网站的 API 拉成自建列表。** 首批按用户要求选一家国内与一家国外站点，先验证实际网页兼容性。

左侧「Skill 管理」提供「已安装」「逛网站」「链接导入 / 快捷搜索」。网站页使用 Electron WebContentsView 显示真实站点，提供站点切换、自填地址、前进 / 后退 / 刷新及页面加载状态；网站搜索、分页、筛选继续由网站本身处理，无需给每站复刻 UI 或寻找付费 API。

首次进入显示未选择状态，不自动访问列表中的第一个网站；只有选择站点或提交地址才开始加载。应用内再次进入时显示用户已打开的网页，不重新导航；站点选择框反映当前网站。

在网站详情点击「导入本页 Skill」读取当前地址和页面可见的公开来源链接，用户选择具体来源后进入已有快照预览 / 安装。未识别到来源时允许手动粘贴，不把未知网站变成空结果或假成功。网站内的安装命令只作为网页内容，不自动执行。支持在 skills.sh 快捷搜索，以及粘贴 skills.sh 条目、GitHub 仓库 / 子目录链接或 `owner/repo`；已有后端能力继续作为辅助导入路径。

「安装到资源库」写入所选数据根的 `skills/`，之后沿现有入口导入项目；也提供明确的「导入当前项目」操作。默认不覆盖同名资源，不自动修改项目或执行 Skill 脚本。重复安装显示已有资源和编辑入口，不将其变成普通对话的阻断条件。已安装资源断网可用，启停、选择及上下文加载复用已有逻辑。

## 数据来源与实际证据

- 国内首选 [腾讯 SkillHub](https://skillhub.cn/skills?sortBy=score)，其原 `skillhub.tencent.com` 地址实际跳转到 `skillhub.cn`；默认直达全部技能目录，使用默认排序，避免将“近期飙升”子集误当全部搜索结果。国外使用 [skills.sh](https://skills.sh/)。预设只是快捷入口，可自行输入其他网站，不建立站点白名单。
- 两站的站内搜索 / 分类 / 继续加载均由原站处理。腾讯用户上传且没有 GitHub 来源的条目，使用 SkillHub 官方公开详情与下载 API 进入同一快照预览 / 安装链路；网站页面仍由原站负责展示。
- skills.sh 搜索采用其 [官方 CLI 的公开调用方式](https://github.com/vercel-labs/skills/blob/main/src/find.ts)：`GET https://skills.sh/api/search?q=...&limit=...`。2026-09-22 匿名查询 react 返回 200 和真实结果。这是 CLI 当前使用的接口，不宣称它是有稳定承诺的 v1 API；接口变化会显示真实错误，不伪装为空结果。
- [skills.sh 文档 API](https://skills.sh/docs/api) 的 `/api/v1/` 要求 Vercel OIDC，本桌面首版不接这一认证链路。
- 下载使用 GitHub `codeload.github.com/{owner}/{repo}/zip/{ref}`；公开仓库 HEAD 实测 200，约 1 MiB，ZIP 注释给出提交标识。GitHub REST 匿名元数据调用实测 403 限流，因此不把 REST 查询作为安装前置条件。ZIP 提交信息只记录来源，不做 hash 执行门槛。
- 公开 GitHub 与腾讯 SkillHub 原生包是两种明确支持的下载来源；私有仓库、其他托管站点和 Git 登录不在本轮范围。GitHub 子目录链接可用；带斜线的分支名可通过显式 ref / 目录输入纠正，不猜测分支。

### SkillHub 原生下载增量（2026-09-23）

用户选择先完成“站内详情 → 原生下载 → 真实预览 → 导入当前项目”。[SkillHub 官方 API](https://github.com/Tencent/skillhub/blob/main/docs/api/skills.md) 提供 `GET /api/v1/skills/{slug}` 与 `GET /api/v1/download?slug={slug}&version={version}`；后者重定向到 ZIP 文件。无需登录，不使用 DSH 插件协议或安装命令。仅当前 SkillHub 详情页产生原生来源，列表页不会因为含有多个详情链接就自动下载。

详情页识别 `/skills/{slug}` 和 `/skills/{owner}/{slug}`，用 slug 查询详情；高级 ref 对该来源表示版本，省略时采用详情给出的 latestVersion。下载与预览保留同一 ZIP 快照，来源记录为 SkillHub slug、实际版本和下载时间。压缩包若在根目录放置 `SKILL.md`，正常识别；若站内上传的是普通 Markdown 或仅有 SkillHub 元信息，导入适配器用 slug 作标准名称，从正文 Description 或详情提取用途说明，生成标准 YAML 头，保留原文与附件。预览可按现有长度上限明确截断，安装始终使用同一快照的完整内容；转换只服务 Skill 格式兼容，不执行其中脚本或虚构内容。

该增量沿用已有网络超时、下载 / 解压预算、取消、同名不覆盖、项目目录与路径边界。需要验证一个标准包和一个无 YAML 头的实际用户上传包，包含项目导入及重启；隔离测试项目和数据根，不调用模型或写个人资源库。API 或压缩包格式变化显示明确错误，不伪装为空结果。

## 实现路线

0. 真实网站使用无应用 preload 的独立 WebContentsView，复用锁定 Electron，不使用可能被网站拒绝的 iframe，也不引入浏览器插件运行时。网站不能调用应用 RPC / 文件 API；原生浏览区跟随布局和页面切换显示 / 隐藏，退出时销毁。用户浏览器的站点会话存储位于应用数据根，与 Agent 使用的临时 MCP 浏览器分开。页面来源读取只在用户点击导入时发生，不向模型自动发送页面全文。
   网站普通下载由 Chromium 保存界面处理，缺省目录为数据根 `site-downloads/`；用户可以自行指定保存位置，不执行下载文件。源码来源中的 `skills.sh/site/...` 是外站条目，不将其错误解析为 GitHub 的 `site/仓库`。
1. Python Skill 在线服务负责搜索、下载、仓库目录解析、预览和安装；复用现有 httpx、zipfile、SkillService，不引入新依赖或通用插件框架。
2. 搜索 / 下载作为可查询、可取消的后台操作；renderer 用短 RPC 轮询真实状态，离开页面再回来仍可查看。网络超时与下载大小上限有明确覆盖入口；不改变 VPN、代理和系统环境，不读取 OpenCode 或 GitHub 凭据。
3. 预览绑定已下载快照，安装使用同一份材料，不在确认后悄悄刷新版本。记录仓库、ref、实际目录和下载时间，能取到提交标识则记录；正文预览截断时明确标注，安装保留完整原文及该目录的 references / scripts / assets 等文件。
4. 临时文件归数据根的下载缓存，完成关闭 / 取消时清理自有临时目录。文件提交沿业务单写者；完整目录准备好后再发布，失败不留下冒充已安装的半成品。存储边界只处理真实路径越界、同名覆盖与不可读取等问题，不增加内容评分、审批或 hash 校验。
5. DTO、schema、TypeScript 与 preload / IPC 同步。来源不提供模型执行授权；既有按需加载规则继续适用。

## 验证与完成标准

只验证本次新增链路：公开搜索响应解析、带附属文件的快照预览和安装、项目导入 / 重启识别、同名保护、下载取消以及晚到结果；必要的 ZIP 路径边界在解包处验证一次。补一条桌面在线发现交互，定向 Ruff / mypy / TypeScript / 构建检查。真实网络在隔离目录安装一个公开 Skill，不调用模型、不写个人资源库。测试统一放 `tests/`，产物在 `.artifacts/tests/`。

补充验收：一家国内 / 一家国外网站的真实加载、站内搜索与翻页（或该站提供的继续加载），前进后退、切换页面隐藏原生浏览区，以及从详情页进入来源导入。网站拒绝嵌入环境或当前网络不可达时记录真实限制，不以本地样本替代网站成功。
