# 为什么研究这些项目：候选池、比较方法与取舍

> 截止 2026-09-23。本文是重新开展的第二轮研究，替代上一轮的推荐清单。研究对象是非 DeepSeek 官方维护的 DSH 插件、适配器和衍生产品；官方 Harness 只用于核对扩展边界。

## 1. 本轮要回答的实际问题

本项目已经有 Windows 桌面、独立 Python 执行核心、会话与 Goal、协作邮箱、可选 worker、上下文压缩、记忆、Skill 导入、MCP 和 Trace。继续研究生态的目的，是寻找能改善真实使用的设计：用户怎样发现并正确使用能力，多个会话怎样接力，长任务怎样保持上下文，扩展更新怎样不破坏运行中的工作，以及怎样把对话变成可继续编辑的成果。

因此，选题不能只由“源码容易读”“正好知道这个仓库”决定，也不能用 Star 总榜直接替代工程判断。本轮先构建候选池，再在同类中比较，最后沿用户进入产品、能力装配、请求执行、状态保存与恢复的顺序分析实现。

## 2. 候选池怎样取得，覆盖边界是什么

本轮使用三条发现路径：

1. **热度入口**：2026-09-23 06:19:44 UTC，即北京时间 14:19:44，读取 GitHub `topic:dsh-plugin` 按 Star 降序的前 100 个仓库，保存精确 Star、Fork、最近 push、是否归档、默认分支和许可元数据。[查询入口](https://github.com/search?q=topic%3Adsh-plugin&type=repositories&s=stars&o=desc)
2. **时效入口**：读取话题的最近更新页，补入 MCP 管理、Claude 兼容、长上下文和其他新插件；结合固定提交的社区目录做问题导向检索。[近期更新入口](https://github.com/topics/dsh-plugin?o=desc&s=updated)
3. **实现入口**：沿入选仓库的实际适配链接追到独立包。例如 EverOS 的 DSH 实现位于 `EverMind-AI/plugins/dsh`，不是 EverOS 主仓库里的某个臆测目录；MemOS 则需要区分 Python 服务端和本地 TypeScript MemoryCore。

GitHub 搜索当次返回 `total_count=15879`，但话题标签由仓库维护者填写，里面混有完整产品、目录、教程、内容集和外围工具。**这个数字不是 15,879 个经过确认的可安装 DSH 插件，更不是本轮审计数量。** 最近更新第二页遇到限流；核心 API 在补充读取时额度耗尽，后续改用公开页面、固定提交源码和 Git 元数据。没有用失败请求补零，也没有声称穷举生态。

前 100 项的逐项处置见 [候选清单](10-candidates.md)。它是筛选记录；只有进入正文的项目才有相应深度的源码分析。新一轮允许复用同日取得的原始 Star 响应和固定源码，重新判断选题与结论；这与沿用上一轮推荐不同。

## 3. Star 怎样真正影响本轮排序

Star 反映用户愿意关注、保存或传播某种产品承诺。它不能证明安装、留存、付费或生产稳定性，但也不能因为这些限制就被忽略。此次它产生了实际结果：补入 Archify、Distilly、EverOS、MemOS、BrowserSkill、iPolloWork 和 LoopX，并提高 OpenDesign 的产品研究优先级，而非继续围绕低关注的几个机制插件展开。

| 比较维度 | 看什么 | 如何影响取舍 |
| --- | --- | --- |
| 用户关注 | 精确 Star / Fork、产品形态、任务是否容易理解 | 同类机制相近时优先研究关注更多、产品表达更清楚的项目 |
| 时效 | 当前默认分支、实际 DSH 目录变化、发布版与源码版区别 | 不能用主仓库一次文档更新掩盖适配器长期未更新 |
| 接入深度 | 原生插件、Skill、MCP、子进程、独立产品 | 区分研究宿主扩展与研究完整产品，避免把热度全归给 DSH |
| 工程实质 | 状态所有者、取消、重启、安装更新、错误处理 | 有具体实现才能进入机制建议；只有 README 的留在候选层 |
| 使用证据 | 明确版本的用户报告、维护者回应、可检查的评测材料 | 比作者自称“企业级”更有分量；问题报告也能证明真实使用场景 |
| 本项目价值 | 已有能力的真实缺口、迁移范围、用户收益 | 不重复建议我们已经实现的按需 MCP schema、Skill 目录与会话管理 |

不计算一个带小数的“工业价值总分”。这些信号并不具有统一量纲，也没有足够的安装量和留存数据支持精确权重。下文提供可审查的同类取舍，而不是包装成科学排名。

## 4. 入选主线与同类比较

以下 Star / Fork 采用上述同一时点的 API 快照；两个低热度机制样本另注明来源。Star 属于整个仓库，**不是 DSH 接入部分单独的 Star**。

| 研究线 | 主要项目与 Star / Fork | 选择理由及没有选择谁作为主线 |
| --- | --- | --- |
| 桌面与成果工作台 | Anywhere 28,591 / 1,358；OpenDesign 97,699 / 11,336；iPolloWork 6,591 / 1,267 | 分别代表 DSH 原生桌面、多 CLI 成果产品、多引擎统一工作台。DataElement 8,521 Star 保留为同类候选，不再对多个相似启动壳平均分配篇幅 |
| 长任务与多会话 | LoopX 5,933 / 568；Nanmi Agent Teams 1,775 / 154；wowyuarm Agent Team 为 9 月 22 日目录快照 36 Star | LoopX 研究持久控制层；Nanmi 研究原生团队调度；低 Star 的 wowyuarm 只因“成员身份与会话寿命分离”进入机制对照，不称成熟标杆。2 Star 的 task-coordinator 不再作为主要推荐 |
| 记忆与经验复用 | OpenViking 38,498 / 2,998；EverOS 13,149 / 921；MemOS 11,542 / 1,056 | 三者分别代表上下文服务、Markdown 事实层、本地记忆加工核心。Mem9 1,216、Honcho 7,306、ReMe 3,502 仍是候选，不能据此宣布劣于前三；本轮不重复扩大到所有记忆后端 |
| 企业知识入口 | WeKnora 29,092 / 3,921 | 纳入 DSH 接入源码，明确它是组织知识检索服务，不把它混同为对话记忆；不宣称审计了整个 Go 后端 |
| 能力与成果 | Archify 70,122 / 4,713；Distilly 24,978 / 2,171；Vibe-Skills 3,412 / 299；SkillCorpus 665 / 111 | 覆盖确定性成果生产、经验 / persona 蒸馏、技能选择和目录治理；比只列 Skill 管理器更能解释用户为何愿意安装 |
| 浏览器执行 | Tencent BrowserSkill 6,728 / 492 | CLI、扩展、原生 DSH 工具与可见浏览会话构成完整链；dsh-browser 718 / 52 作为另一种连接与页面归属方案比较，避免只因先发现它就优先 |
| 上下文与扩展生命周期 | dsh-context 1,488 / 46；dsh-market 4,412 / 223；billion-context 当日页面 251 / 29；两项 zhang-guo-wen 插件的当日精确 Star 未取得 | 可视化、实际请求压缩、安装恢复、MCP 会话资源和规则兼容各解决不同问题。低热度样本只承载可验证机制，不据此升格为主产品推荐 |

按热度，Ruflo 73,096 和 Reasonix 35,688 本应进入候选；但“被标上 dsh-plugin”不足以说明它是本轮要找的原生二次开发。Ruflo 的已检查同名入口属于另一生态子包，不能把整个 swarm 能力归给 DSH 插件；Reasonix 是独立 coding agent，对缓存与循环的价值更适合独立 Agent 对比专题。它们留在候选清单，**未读完整实现的部分不作负面质量判断**。

OpenPencil 6,009、dsh-web 7,944 也有明确产品吸引力：前者的设计画布与并发团队、后者的任务面板值得继续研究。本轮工作台主线优先选择三种不同的运行时组织；dsh-web 保留为原生 Host 任务账本方向的后续候选，不把前轮局部阅读算成本轮完整主线。

## 5. 如何理解“工业落地价值”

本轮采用四类证据标签，避免将设计能力与采用事实混在一起：

- **代码机制**：源码中可定位的调度、序列化、恢复、状态与数据路径。可以判断工程取舍，但没有等同于实测通过。
- **作者验证**：仓库提供的测试、benchmark 或演示及其具体条件。没有由本轮运行的，明确称作者材料。
- **用户使用**：带版本、环境和过程的公开报告，能揭示真实组合方式及维护成本。用户报告仍不是本轮复现。
- **生产采用**：可明确辨认的组织、部署场景、运行规模或业务指标。本轮没有取得足以对这些 DSH 适配统一宣称“大规模企业生产验证”的证据。

例如 Anywhere 的 Windows 插件升级失败报告同时列出了市场、OpenViking、BrowserSkill、上下文和 UI 插件，是“真实组合使用”的强信号；其价值在于暴露运行时文件句柄、包管理与恢复入口之间的边界，而不是证明整个产品不可靠。BrowserSkill 的 Windows 更新报告同样说明“已下载”“已暂存”“已替换”和“正在运行新版”必须分开。[Anywhere #1115](https://github.com/anywhere-labs/dsh-desktop/issues/1115)、[BrowserSkill #305](https://github.com/Tencent/BrowserSkill/issues/305)

因此，本研究的推荐分为**优先学习的产品组织**、**适合局部吸收的工程机制**和**需要效果验证的探索方案**。不会把安装一个复杂框架当作完成本项目优化；也不会因为尚无企业案例，就抹掉有吸引力的新产品路线。
