# 2026-09-16 复查：缺口、补充与证据边界

本次复查确认，上一版虽然已有十篇专题，仍存在影响理解与选型的缺口：记忆偏产品结构，优化器与训练接入不足，主要 harness 和 SDK 覆盖不全，企业案例正文获取不充分，推理模式与观测平台仍有遗漏，跨系统协议则缺少独立分析。用户对深度、完整性和时效性的质疑有依据。

本轮对原十篇逐篇检查问题结构，再针对上述缺口查阅官方文档、论文方法、源码和企业原文；十篇均已补充，并新增 [11 Agent 互操作协议](11-agent-protocols.md)。这是一轮有针对性的复查，未将全部历史来源重新通读一遍，也没有把新增链接数作为质量指标。

## 2. 哪些时效核查会实质改变结论

这些变化包括原文缺口的补足，也包括补查时发现的旧资料陷阱；不是声称上一版已经写错过所有下列版本。

| 容易采用的旧判断 | 核查后的处理 | 为什么影响开发 |
| --- | --- | --- |
| SimpleMem 的各版本都是同一异步合并流程 | 按 v3 解释在线合成，当前仓库扩展另列 | 写入延迟、成本和恢复位置不同 |
| Agent Lightning 始终沿用早期存储 / tracer 架构 | 按 v1 报告区分 Trainer、Gateway、Rollout Controller | 真实调用记录与训练样本的切分改变 |
| ADK 只需了解层级 Agent 和顺序 / 并行模板 | 核查 2.0 图引擎与三语言 GA 日期 | 状态存储、Event 和节点契约涉及迁移 |
| 子 Agent 总应使用空白上下文 | 按 9 月 fork / isolated 功能讨论职责 | 连续工作、独立审查和缓存的目标不同 |
| DeerFlow 跨 Worker 取消必然返回 409 | 当前文档已支持持久转交取消请求 | 恢复与取消延迟依赖所有权 / 租约 |
| Agents API 就是 Agents SDK 的另一写法 | 当前官方文档区分托管 harness 与应用内循环 | 谁管理环境、状态和资源清理不同 |
| A2A 最新仍是 0.3；ACP 只有一种含义 | 当前规范是 1.0；Communication ACP 已并入，Client ACP 另有职责 | 避免选错协议、接口和迁移路径 |
| 记忆相似度高就适合注入 | 补 SAGE / MemGate，并区分写入、召回、适用性和权限 | 减少冗余、过时偏好与跨任务误用 |
| 更新、更难的基准自然更可信 | 加入 9 月 Pro Verified 的任务与环境分析 | 分数变化可能来自测试质量或运行条件 |

本轮使用的近期材料包括 9 月 3 日 MCP SDK 更新、8 日子上下文设计与 Pro Verified、9 日 Connections、10 日 Credit Genie 案例。具体原始链接和读取深度在 [证据台账第 9 节](00-evidence-register.md)，不把抓取时间当成发布日期。

## 3. 企业落地证据怎样加深了分析

**Stripe Minions**：补读正文后，可以解释 Blueprint 中确定性节点与完整 Agent 节点如何配合、为什么组织既有 devbox / 工具库很重要、CI 修复与人工审查怎样连接。不能把其内部改造简单归功于公开 Goose 核心，也不能把企业吞吐量等同人均提效。

**Manus**：补读原文后，将稳定提示前缀、文件外置与失败证据放在同一个循环中解释。它提供历史设计经验；对动态工具和缓存的建议仍需放回当前接口条件，不能永久照搬。

**Credit Genie / OpenWiki**：加入随代码变更维护知识的案例，区分源代码、派生 Wiki 与检索入口的版本。原文谈到的跨仓库增强仍是后续方向，未写成已经交付的能力。

这些补充提供了架构和使用方式的证据，没有企业私有系统访问，也没有独立复现它们的生产收益。

## 4. 实现核查达到哪里

Deep Agents 读取到固定提交中的实际装配与权限边界；DeerFlow、OpenViking、Agent Lightning 记录了 HEAD，但本轮主要读取当前文档与对应论文，未将其冒充为完整固定源码审计。具体 hash 和范围见 [证据台账第 10 节](00-evidence-register.md)。

论文同样区分深度：A-MEM、SimpleMem、SAGE、MemGate、Step-Back、Self-Discover、ProgramBench 等读到相关方法；TextGrad 结合摘要与官方使用示例；Least-to-Most / Self-Consistency 本轮主要核查原论文摘要与机制定位。对所有材料均未执行实验，文中的工程例子不能作为性能证据。

本轮已纠正首次因访问失败保留的 Stripe、Manus、ProgramBench 限制。读取失败有时来自提取方式，不能据此判断项目不存在或内容没有公开。

## 5. 仍保留的明确边界

尚未独立展开模型路由与网关经济性、浏览器 / GUI Agent、多模态工程任务、A2UI / MCP Apps 等界面标准，也未审计全部通用 SDK 与专门 debate 系统。它们列作后续范围，不作为已完成的深入结论。

已有研究也不能代替本项目实测：没有比较既定模型在这些模式上的效果，没有验证 Windows 第三方框架兼容性，没有跑记忆或自进化基准。若要采用具体方案，应先确定要解决的实际问题，再固定版本并做相应最小验证。

本次只改写 `docs/research/` 与独立调研进度。没有修改其他任务维护的总览、阶段进度和设计稿，没有新建实施阶段、安装依赖、调用付费模型、提交或推送。文档检查记录保存在 [调研进度](../progress/research.md)。
