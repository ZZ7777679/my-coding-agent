## 更新与接续规则

1. 开始工作先读本总览和涉及阶段已存在的进度文件，再核对代码、Git 状态与已存在的验证入口。
2. 新阶段按最新需求逐个细化；范围、设计与验收明确后创建该阶段进度文件。文件记录本次范围、工作项、产物、验证、阻塞和具体下一步；开始实际实施时更新状态。
3. 有实际进展、检查结果、范围调整或阻塞变化时及时落盘，结束或交接前完成更新；同步本总览中受到影响的摘要。
4. 验证记录写日期、实际命令或检查方式、结果、必要文件位置；未执行、模拟通过、真实调用通过和安装验证通过分别表达。
5. 日期只表示事实记录时间，不作为工期承诺。已有失败保留解决经过，过期结论注明被哪些新证据替代。
6. 规划保存设计与验收定义，进度保存执行事实；跨阶段需求调整要同步相关方案与进度，不能仅留在会话中。
7. 先写本地文件，再按任务授权决定是否提交和推送；记录中不保存真实密钥、完整会话或无关日志。

仅要求规划时先完成规划；路线图不等于已经授权实现所有阶段。保留已开展阶段的记录，后续文件随实际推进逐个增加。
