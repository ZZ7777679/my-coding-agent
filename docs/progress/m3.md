## 暂停时的方案方向（现已形成正式计划）

以下为工作草案，恢复后需要落实到各模块文档，不是新增的用户决定或已实现功能。

### 共同架构

- 原始事件 / 工具产物负责“发生过什么”；任务当前状态负责“现在以什么为准”；压缩 checkpoint 负责当前会话接续；任务工作记忆负责跨会话短期接续；长期记忆负责跨任务可复用信息；协作简报 / 消息负责传递工作。
- 三模块共用来源引用和上下文组装入口，但不合并成一个不断膨胀的摘要。已取消 Goal 的历史目标不能重新成为活动任务。
- 模型辅助调用使用既有 Go / 当前选择模型 / 连接池；区分压缩、记忆提取与前台回答的活动和成本。无需新增 key、静默换便宜模型或每回合串行整理。
- 严格控制新增阻断：来源与状态由宿主带入，摘要不强制固定标题 / JSON 评分，不以 hash、证据齐全或语义审查作为正常运行前置条件。

### 上下文压缩

- 承接既有方案：旧长输出外部化、近期工具调用配对保留、同模型增量摘要、手动与自动触发、后台准备 / 请求边界采用、原始历史回读。
- 区分 token 容量、可配置整理阈值、传输字节上限；未知容量不能直接拒绝普通对话。
- 摘要覆盖固定历史前缀，新消息留在尾部；不因追加消息反复废弃后台结果。当前任务事实与记忆独立注入，不随摘要递归改写。
- 当前运行必要的压缩失败沿既有失败规则处理；单独后台维护失败不能混作无关前台工具故障。

### 长短期记忆

- 短期：任务目标、已确认结论、进度、未决项及交接；复用 M2 任务记录，不能再建一套矛盾状态。
- 长期：项目 / 用户作用域的偏好、稳定知识与经验；来源、更新时间、适用范围由宿主维护，区分用户明确事实与模型推断。
- 先采用本地可解释存储和简单检索；中文检索需实际考虑分词 / 子串或 FTS 支持，不默认需要 embedding 服务或图数据库。
- 支持显式记住、自动提取开关、查看 / 改正 / 忘记；自动提取安排在空闲或工作边界并合并批次，不逐条弹确认。忘记后避免旧历史立即重新生成同一条；原始历史是否保留要如实说明。
- 普通后台记忆整理失败保留待处理状态，不阻塞已成功的代码任务。

### 多会话协作

- 复用已有角色、范围、持久队列与 handoff；新增清楚的任务协调视图、结果投递、历史按需回读和有条件接续。优先形成可实际完成简单任务的流程。
- 图的节点是完整会话 / Agent 工作单元，边是委派、依赖、结果与 handoff；不引入细粒度工具 DAG 或强制工作流引擎。
- 区分用户已有的长寿命会话和可选临时子 agent。不要自动新建用户会话；子 agent 开启后根据独立性、可并行收益、上下文隔离需求与协调成本判断，不用机械评分和硬编码数量判断业务是否可执行。
- 同目录分工仍是默认；可选工作副本不成为协作前提。失败只停止受影响运行及其所属 Goal，其他独立工作保留；不无条件触发新轮或相互 ping-pong。
- 源会话忙时在合适边界收到消息；空闲 / Goal 等待 / 终态时的接续策略需要在计划中写清，特别是用户停止后不能被迟到结果自动复活。
