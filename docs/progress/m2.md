### B 实现与结果（2026-09-17）

- `runtime/tools.py` 与 `runtime/modes.py` 定义能力装配和本次模式，`bootstrap` 注入实际文件工具；会话服务不再直接创建只读工具。新会话默认常规，旧日志缺失字段按 Plan 读取，用户可显式切换；运行事实保存模式及当次计划文档授权。CLI 新增 `--mode` / `--plan-document`，仍用同一服务，不运行另外一套 Agent。
- `create_file` 支持空项目和缺失父目录，目标已存在时拒绝覆盖；`edit_file` 必须使用本轮 `read_file` 的 hash 和唯一原文。提交前再次核对路径与磁盘版本，保留 UTF-8 / BOM、原换行；混合换行按精确文本处理，不猜测其他编码。读写继续共用忽略 / 凭据保护，新建补充 Windows 保留名称、真实祖先与目录规则检查。
- 应用内按真实目标短时协调写入。成果保存在 `<data-dir>/changes/<session-id>/<change-id>.json`，单个记录含前后原始字节、hash、工具 / 会话 / Run 来源及准备 / 成功 / 失败状态；目标项目没有额外 Agent 数据或 Git 初始化。基线保存失败不写项目，写入后结果保存失败保留 `prepared` 并明确结果未知；不自动重放或回滚。短写入开始后取消仍等待它及结果保存结束。
- Plan 默认只读；用户填写唯一相对文档路径后只开放该目标，并拒绝通过链接别名把该授权导向另一文件。工具执行仍校验实际权限，不能通过直接构造未公布的工具调用绕过。模式选择在桌面输入框上方显示，当前活动的读写与模型请求分开呈现。
- 每次副作用工具调用前，重新读取任务目标 / 约束 / 已确认决策 / 状态和会话分工；与本次模型请求采用的范围不同则停止。普通进度文本更新不因此锁死写入。实际工具失败停止当前 Run，同一回合尚未开始的工具保存独立 `tool.skipped`，既不伪造执行次数，也不破坏后续显式接续的模型配对。
- 桌面右上角“查看修改成果”打开可收起的右侧列表 / diff；按保存的两端内容展示历史修改，明确未确认 / 失败状态，长差异分页，原内容不进入通用 RPC 或配置日志。preload 只新增按会话 / 成果身份查询的 `listChanges` / `getChange`，不暴露任意文件路径读取。重启可再次查看成果。
- 已同步 README、实施方案及测试清单。协议仍为开发中的 v3，生成物从 Python DTO 更新；不手工修改生成文件。任务树 / 模型 / 连接池原能力保留，未增加依赖、provider、模型、全局环境配置或推送。
