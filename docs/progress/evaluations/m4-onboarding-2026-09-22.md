# M4 首次使用与资源接入体验评价

日期：2026-09-22。状态：已完成本轮两条体验场景与证据审阅。

本轮由 Agent 模拟第一次打开 Harness 的开发者及需要接入 Skill / MCP 的用户，不是外部真人用户研究。只测试和评价，不修复产品。保留当前 dev 分支的 M4 未提交改动，不接触个人项目、日常数据根、真实模型或外部账号。

已阅读 AGENTS.md、进度总览、M4 当前进度及相关桌面装配。通过 [独立体验脚本](../../../tests/desktop/persona-onboarding.spec.ts) 执行真实 Electron 场景，复用 `runtime.ts`、`helpers.ts`、`desktop_peer.cjs`。模型使用替身；IPC / RPC / Python 后端 / 文件持久化是真实链路。原生选择器仅替换返回目录，MCP 使用本地 HTTP 服务。使用现有最终构建，没有重建或安装依赖。未提交 / 推送。

## 结论

这两条场景没有复现阻塞性功能缺陷。项目选择、任务建立、默认模型切换、Skill 本地导入与会话选择、MCP 认证失败恢复及重启持久化都可完成。值得调整的是首次进入任务后的继续入口、Skill 两种选择的可见说明，以及默认环境的信息可见性；下文均标为使用困惑，不升级为运行失败。

严重度采用 P0 紧急、P1 严重阻塞、P2 明显功能影响、P3 使用清晰度 / 效率。当前观察没有 P0–P2 项；这不构成全产品无缺陷的结论。

## 亲自复现的使用困惑

### ONB-1 · P3 · 创建首会话后，主区域的下一步不够醒目

- 用户目标：填写一个目标后开始第一轮对话。
- 步骤：打开项目 → 新建任务 → 填写阶段目标 → 点击「创建任务与首会话」。
- 预期：创建成功后有醒目的开始对话入口，用户能立即识别下一步。
- 实际：主区域切到任务概览，首屏是工作流、阶段和共享信息。会话确实已创建，并在侧栏显示「新会话」；主区域「打开 / 补齐首会话」位于长表单下方。本轮需再点击该入口才能见到输入区。功能没有丢失或重复创建，但初次用户容易停留在配置页。
- 证据：[创建后主区域](../../../.artifacts/tests/persona-onboarding-first-DP6I9u/06-after-create-task.png)、[进入首会话](../../../.artifacts/tests/persona-onboarding-first-DP6I9u/07-first-session.png)；对应入口见 `apps/desktop/src/renderer/src/TaskPanel.tsx` 的创建按钮及「打开 / 补齐首会话」。
- 最小建议：创建成功后在页首给出「进入首会话」主按钮，或将明确的创建动作直接导航到已创建会话。仍保持创建本身不调用模型，不增加审批。

### ONB-2 · P3 · Skill 的持续选择和启用使用相邻勾选，视觉含义不对称

- 用户目标：让一个项目方法持续用于当前会话，同时理解其他已启用方法何时会使用。
- 步骤：进入会话 → Skill 管理 → 本地目录导入到项目 → 观察并勾选 `first-steps · project` 左侧复选框。
- 预期：每个选择项在所在行能直接表达是「允许按需使用」还是「本会话持续使用」。
- 实际：每行 Skill 名称左侧有一个无可见文字的复选框，右侧另有带「启用」文字的复选框。页首说明解释了两者大意，但滚到列表底部后说明不在视野；两个都勾选时尤其需要记忆含义。左侧有 `aria-label`，所以这里不称为无可访问名称。保存与重启恢复正常。
- 证据：[同一行的两种勾选](../../../.artifacts/tests/persona-onboarding-first-DP6I9u/09-skill-selection-controls.png)、[重启后仍选中](../../../.artifacts/tests/persona-onboarding-first-DP6I9u/12-skill-selection-restored.png)；对应 `apps/desktop/src/renderer/src/Skills.tsx` 的 `选择 ${item.name}` 与 `启用 ${item.name}`。
- 最小建议：给左侧增加可见的「本会话持续使用」说明或明确列标题，将右侧说明为「允许按需使用」。保留现有两种语义，不把“启用”自动解释为强制带入。

### ONB-3 · P3 · 默认本机环境可运行，但首页提示与实际环境细节仍有信息差

- 用户目标：知道第一次任务是否还要配置环境，以及任务将使用哪套本机 Python。
- 步骤：打开项目 → 阅读工作台页脚 → 设置与诊断 → 项目执行环境。
- 预期：不需要配置时明确可直接开始；需要调查兼容性时能查到当前命令解析结果。
- 实际：设置页明确写「本机工具（默认，无需导入）」「默认使用本机工具。需要特定解释器时再导入并选择」，也明确显示未隔离。但工作台页脚仍写「选择项目默认环境后执行与预览」，容易让新人以为还欠一次设置。默认选项附近没有显示 `python` 的实际路径或版本。本轮只确认这项界面事实，没有执行命令或证实某个解析结果。
- 证据：[默认环境](../../../.artifacts/tests/persona-onboarding-first-DP6I9u/04a-default-execution-environment.png)、[首页页脚](../../../.artifacts/tests/persona-onboarding-first-DP6I9u/01-first-launch.png)、同目录 `04-model-settings.txt`；源码位置 `EnvironmentSettings.tsx` 默认项与 `main.tsx` 页脚。
- 最小建议：将页脚改为默认可直接运行的准确描述；可提供按需查看本机命令解析路径 / 版本的入口，或在执行环境工具结果中提供事实。不将检测变为运行前置条件，不强制用户项目采用 Agent 自身的 Python 3.13。主评估可与其他视角的实际解释器兼容性证据合并，避免重复计数。

## 顺畅部分

- 首次启动空状态清楚；取消选择留在空状态，无效目录选择保留原项目并显示错误。没有要求初始化 Git、创建独立副本、导入环境或保存信任开关。
- 设置区区分凭据已检测与真实调用已验证；保存默认模型后，新会话立即采用 DeepSeek，不需要为该设置重启。两个模型范围符合既定选择。
- 只填写目标即可建立任务及首会话；约束与接续信息保持可选。第一条替身对话完成真实文件读取，没有要求先保存环境。
- Skill 本地目录导入写入独立项目的 `.agents/skills/first-steps/SKILL.md`，正文读取正确，持续选择重启后恢复。资源来源信息可见。
- MCP 常用预设可以用普通表单配置，不需要先写原始 JSON。401 错误明确提示编辑认证配置；修正后状态由「连接失败」变「已连接」，发现的工具显示用途。失败展开图：[401 及修复入口](../../../.artifacts/tests/persona-onboarding-mcp-GCtsNc/04-auth-failure-detail.png)。
- 项目停用仍保留资源登记；重新启用与重启后重连成功。图：[连接成功](../../../.artifacts/tests/persona-onboarding-mcp-GCtsNc/05-recovered-connected.png)、[重启重连](../../../.artifacts/tests/persona-onboarding-mcp-GCtsNc/07-restored-and-reconnected.png)。这说明本地场景可恢复，不证明真实服务永不失效。
