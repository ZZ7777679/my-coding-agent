> 整理日期：2026-10-19。依据本地阶段进度、规划、源码入口、Git 状态和既有验收报告。本轮只整理文档，没有重新运行产品、模型或回归。

## 1. 产品方向与工作方式

这是一个 Windows 优先、按个人习惯工作的 Coding Harness，同时服务日常编程和大模型应用开发。它以项目 → 任务 → 会话组织工作，支持可复用 Skill、任务工作流、长任务、上下文与记忆，以及完整 Agent 之间的合作。

- **任务**承载长期目标和阶段；**会话**承载具体工作；常规、Plan、Goal 决定本次怎样推进。一个局部 Goal 完成不等于整个任务完成。
- **合作空间**组织长期成员、职责、实际会话和合作关系；图里的节点是完整 Agent，不是细粒度工具步骤。工作流阶段也不是强制执行 DAG。
- 默认直接在选择的原项目工作；Git、本机沙箱和工作副本不成为普通编码前提。正常授权范围直接推进，可修正的工具输入错误交回模型；真实调用失败停止受影响工作。
- 图、工作报告和记忆帮助接续，不增加评分、强制填写、信任开关、hash 或逐工具确认门槛。

依据：[初版产品设计](../plan/harness-initial-design.md)、[M5 方案](../plan/m5-implementation-plan.md)、[项目约定](../../AGENTS.md)。早期文件的“待实现”需结合下方现状读取。

### M3：当前采用的上下文与记忆方案

上下文使用“长工具结果减量 → 按完整交互切点汇总旧前缀 → 保留必要近期单元 → 原文按需回读”。采用绝对 token 配置，新会话默认 **800K 自动压缩起点**，旧会话设置不被覆盖。界面区分服务端实际输入用量和发送前估算，不把历史字节数冒充模型 token；没有安装重型本地 tokenizer。

长期记忆与当前会话摘要分开。记忆可以查看、纠正、召回与遗忘；摘要不会自动变成长期事实。来源和本次实际带入材料可查。算法已有实现，后续应看真实任务的接续效果，不再从零建设同类系统。[最终上下文方案](../plan/context-system-final-design.md)、[记忆方案](../plan/m3-memory-plan.md)

### M4：方法、外部能力与可观察性

- 左侧集中管理 Skill 和 MCP，项目可以启用 / 导入资源。Skill 按项目 → 用户 → 内置取有效版本，短目录与正文按需加载。
- 预装九项资源；在线入口已有腾讯 SkillHub 和 skills.sh。支持公开 GitHub 来源及 SkillHub 原生包的下载、预览、项目导入和重启读取；任意网址并不自动兼容导入。
- MCP 已有 stdio / Streamable HTTP、工具发现与按需装载，以及 Playwright、Context7、GitHub 预设。认证可引用环境变量或使用既有凭据保存流程，OAuth 首版也已实现。
- 临时浏览器按会话隔离、同会话复用、退出清理；它与 Skill 网站浏览入口是不同用途。
- 工作流模板与任务实例分开，可跳过 / 返回阶段；Trace 从真实事件投影，主对话不用铺满参数和结果 JSON。

来源：[M4 方案](../plan/m4-implementation-plan.md)、[网站与导入](../plan/skill-online-catalog.md)、[MCP 预设](../plan/mcp-service-presets.md)、[OAuth](../plan/mcp-oauth.md)。

## 6. 建议的接续顺序

以下是本次整理建议，不是本轮实施范围，也不替代后续阶段确认。

1. **收好 M5 的明确缺口**：修正 `report_work` 反馈；在 Go 上用一个很小的真实协作任务恢复日常使用观察；需要保存版本时再做 M5 差异审查和 Git 提交。已有终端、编辑器、LSP 验收不无理由重跑。
2. **确定下一阶段主线**：优先将“合作空间实际任务体验”与“上下文 / 记忆如何向成员提供有效材料”一起细化。依据真实开发任务确定缺什么，避免把整个研究清单塞进新阶段。
3. **独立安排桌面交付**：安装 / 升级是最初目标中仍未交付的部分，可单独成批；近期更关注 Harness 行为时，继续保留开发入口也可以，不强制同时实施。

不设固定工期，不在此创建 M6 全量任务表。本轮不新增 provider、依赖、自动化或执行门槛。
