## 规划时的发现

- `models/types.py` 与 `runtime/events.py` 仅提供草案；不存在模型客户端、工具循环或会话事件存储，不能把 M0 的握手成功视为模型调用成功。
- `rpc/server.py` 顺序读请求、执行、写响应；`apps/desktop/src/main/backend.ts` 只接受带已知 ID 的响应。接入长任务必须增加独立运行任务与通知分发，否则停止请求被阻塞，事件会被当成协议错误。
- 现有普通 RPC 等待 8 秒，诊断 60 秒；模型请求应另有可配置预算，不能只扩大所有 RPC 超时。
- 现有项目与配置会持久化，对话尚未实现。M1 应同时规划历史保存和重启查看，延续用户对 E 盘数据与桌面可用性的要求。
